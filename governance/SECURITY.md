# SECURITY.md — M6 治理与安全模块安全说明

## 威胁模型（STRIDE）

### 1. Spoofing（身份伪造）

| 威胁 | 缓解措施 |
|------|----------|
| 冒充其他主体访问记忆 | RBAC 五级角色 + 临时令牌验证 |
| 伪造 owner 身份修改配置 | HMAC 签名校验 + owner 令牌常量时间比较 |

**信任边界**：外部调用方必须通过 `checkPermission()` 入口访问，不允许绕过访问控制直接操作记忆存储。

---

### 2. Tampering（篡改）

| 威胁 | 缓解措施 |
|------|----------|
| 篡改记忆条目内容 | Merkle Tree 根哈希校验 + 周期性巡检 |
| 篡改审计日志 | 哈希链结构，任何修改都会破坏后续哈希 |
| 篡改运行时配置 | 配置 HMAC 签名，启动时校验 |

**信任边界**：记忆存储层是不可信的，本模块通过哈希校验检测篡改，不依赖存储层的安全性。

---

### 3. Repudiation（抵赖）

| 威胁 | 缓解措施 |
|------|----------|
| 用户否认自己执行过操作 | 全量审计日志记录谁在什么时间做了什么 |
| 审计日志事后被删改 | 哈希链结构，追加-only，不可篡改 |

**审计合规**：
- 所有敏感操作（写/删/导出）必须记录审计日志
- 日志包含：主体、动作、资源、时间戳、结果
- 哈希链保证日志不可抵赖

---

### 4. Information Disclosure（信息泄露）

| 威胁 | 缓解措施 |
|------|----------|
| 越权读取他人记忆 | ABAC 属性条件 + 默认 deny-all |
| 审计日志泄露敏感信息 | 日志查询需 audit 权限 |
| 配置中泄露密钥 | 签名密钥不写入日志，从环境变量注入 |

---

### 5. Denial of Service（拒绝服务）

| 威胁 | 缓解措施 |
|------|----------|
| 大量请求打爆权限检查 | LRU 缓存 + 纯内存决策，P99 < 1ms |
| 审计日志占满内存 | 环形缓冲 + 自动淘汰旧条目 |
| 巡检太频繁影响业务 | 快速巡检 < 100ms，后台异步执行 |

---

### 6. Elevation of Privilege（权限提升）

| 威胁 | 缓解措施 |
|------|----------|
| 低权限角色执行高权限操作 | deny 优先策略，默认拒绝 |
| 临时令牌被滥用 | TTL 限制 + 可随时撤销 |
| 运行时恶意修改策略 | 策略变更需要审计日志记录 |

## 信任边界

```
┌─────────────────────────────────────────┐
│           外部调用方（不可信）            │
│  Agent / 第三方插件 / 脚本               │
└─────────────────┬───────────────────────┘
                  │
                  ▼  (必须经过)
┌─────────────────────────────────────────┐
│         M6 治理与安全（信任根）           │
│  ┌─────────┐ ┌──────────┐ ┌───────────┐ │
│  │ 访问控制 │ │ 策略引擎 │ │ 安全配置  │ │
│  └─────────┘ └──────────┘ └───────────┘ │
│  ┌─────────┐ ┌──────────┐               │
│  │ 审计日志 │ │完整性巡检│               │
│  └─────────┘ └──────────┘               │
└─────────────────┬───────────────────────┘
                  │
                  ▼
┌─────────────────────────────────────────┐
│        记忆存储层（半可信）               │
│  MemSym 条目 / 命名空间 / 向量索引       │
└─────────────────────────────────────────┘
```

**关键边界**：
1. 外部调用方 → 治理层：必须经过访问控制检查
2. 治理层 → 存储层：存储层被视为可能被篡改，需巡检验证

## 密码学设计

### 哈希算法

| 用途 | 算法 | 说明 |
|------|------|------|
| 审计日志链 | SHA-256 | 每条记录哈希链接前一条 |
| 配置签名 | HMAC-SHA256 | 防止运行时配置篡改 |
| Merkle Tree | SHA-256 | 记忆条目完整性校验 |
| 缓存 key | SHA-1（截断16位） | 性能优先，仅做缓存索引 |

### 审计日志哈希链公式

```
hash_i = SHA256(prevHash_i-1 + timestamp + subject + action + resource + result + nonce)
```

- **prevHash**：前一条记录的哈希，形成链式依赖
- **nonce**：随机数，防止重放攻击
- 篡改任何一条记录，后续所有哈希都会不匹配

### 配置签名公式

```
signature = HMAC-SHA256(signingKey, canonical_config)
```

- canonical_config：配置按 key 排序后序列化，确定性
- signingKey：从环境变量注入，不硬编码
- 常量时间比较（timingSafeEqual），防时序攻击

## 密钥管理

### 签名密钥（signingKey）

**生成方式**：
1. 生产环境：通过环境变量 `GOVERNANCE_SIGNING_KEY` 注入
2. 开发环境：启动时随机生成（32 字节随机数）

**存储要求**：
- ❌ 禁止硬编码在源码中
- ❌ 禁止写入日志
- ✅ 通过环境变量或密钥管理服务注入
- ✅ 最小权限访问

### Owner 授权令牌

**派生方式**：
```
ownerToken = HMAC-SHA256(signingKey, "owner-token")
```

**使用场景**：
- 修改安全配置
- 轮换签名密钥
- 覆盖自检失败（紧急模式）

**安全要求**：
- 令牌仅在启动时生成一次，不落盘
- 令牌比较用常量时间函数，防时序攻击

### 令牌轮换

```
新 signingKey = HMAC-SHA256(旧 signingKey, "rotate")
```

需要用旧 ownerToken 才能触发轮换，形成链式授权。

## 审计合规说明

### 日志保留

- 内存环形缓冲：默认 4096 条
- 超过阈值自动异步刷盘（阈值默认 64 条）
- 刷盘间隔：兜底 5 秒

### 不可否认性

审计日志采用哈希链结构：
1. **追加-only**：只能新增，不能修改
2. **链式校验**：`verifyChain()` 可检测任何篡改
3. **完整证明**：任何一条日志都可以通过哈希链追溯到创世块

### 合规场景

| 场景 | 记录内容 |
|------|----------|
| 记忆读取 | 谁、读了哪条、时间、结果 |
| 记忆写入 | 谁、写了哪条、内容哈希、时间 |
| 记忆删除 | 谁、删了哪条、是否审批 |
| 导出操作 | 谁、导出了哪些、导出格式 |
| 策略变更 | 谁、改了哪条策略、变更前后 |
| 配置变更 | 谁、改了哪个配置项、新旧值 |

## 安全默认值（Secure by Default）

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| 默认策略 | deny-all | 无匹配规则一律拒绝 |
| 令牌 TTL | 5 分钟 | 最小必要权限 |
| 最大令牌 TTL | 1 小时 | 防止超长令牌 |
| 权限缓存 TTL | 30 秒 | 限制权限生效延迟 |
| 自检开关 | 开启 | 启动时校验配置签名 |
| 快速巡检间隔 | 1 分钟 | 及时发现篡改 |
