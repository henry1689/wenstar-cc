### 2.3 建议新立：《户籍三元组法》条款草案（**文本待业主审定**）

> 定位：作为《UUID 户籍管理法》的**修订版**（升 V2.0），而非另立平行法律 —— 避免又多一个法源。
> 核心是把散落的铁律收敛成**一条判定链**。

**第一条（三元组定义）**
> 每一条数据记录携带**户籍三元组**，三维各司其职，不可互相替代：
> - **UUID（`belong_entity_uuid`）—— 管「隔离」**：硬边界，决定这条能否被当前人格看见
> - **DNA（`dna_root_id`）—— 管「溯源」**：同一段经历的所有衍生件共享同一 DNA 主链，防止跨源碎片拼接
> - **40D（`perception_40d` / `emotion_vector`）—— 管「相关」**：软排序，决定在可见集合内的注入优先级

**第二条（存入义务）**
> 凡写入六类存储，必须确定三元组的归属维度；DNA 与 40D 维度按第四条的法定要求填写。
> 禁止任何不经户籍校验的写入路径（现存的 4 个 `scripts/` 旁路必须收口或显式标注为"迁移专用"）。

**第三条（无归属语义 · 按域分治）**
> 无归属（`belong_entity_uuid IS NULL`）在**共享域**（知识库文档类）语义为"共享"，
> 对全部人格可见；在**私有域**（memories / conversations / black_diamond / vault_log）
> 语义为"未登记"，仅户主钥匙可见。**两域语义不得互相援引。**

**第四条（检索唯一判定源）**
> 任何检索路径的归属判定**只允许调用** `UUIDPoliceFilter.buildSqlClause` / `passes`；
> 禁止任何形式的二次实现（含"等价改写"）。`allowUnowned` 的取值**只能有一个决定点**，
> 由被检索的表所属域推导，不得由调用方随意传入。

**第五条（拼接闸门 · 三维同源）**
> 组装给 LLM 的上下文，其筛选依据必须与检索阶段**同源**；拼接阶段不得引入检索阶段未用的判据，
> 也不得放宽。名字解析失败时**fail-closed**（剔除），不得保守保留。
> DNA 与 40D 在拼接阶段参与"同源聚合"与"优先级排序"，不参与"可见性"判定。

**第六条（法定异常态）**
> 归属指向不存在实体 = **孤儿归属**，为法定异常。私有域孤儿 → 标记待人工归属；
> 共享域孤儿 → 视为无归属（共享）。

**第七条（生效与巡检）**
> 全部 AGENT 无条件遵守。新增巡检项：三元组落库率 / 孤儿归属数 / 形态不一致行数 /
> `allowUnowned` 取值一致性，纳入现有 `UUIDSupervisor` 周期巡检与 `/api/household/dashboard`。

**第八条（存量过渡）**
> 存量数据的补齐遵循"**先实证后补**"：任何回填前必须先实测可关联率，
> 关联不上的**不得强行赋归属**（本项目已有两次教训：按类别扫的谓词造成数据损失）。

### 3.1 检索侧：`allowUnowned` 单一决定点

现状 5 处取值不一（1.5 表）。收敛方案：

```
在 UUIDPoliceFilter 内新增一个纯函数（不新增文件）：

  export function policyFor(domain: 'private' | 'shared', visibleUuids: Set<string>): PolicePolicy

  · domain='shared'  → allowUnowned: true    // 知识库文档类
  · domain='private' → allowUnowned: false   // memories/conversations/black_diamond/vault_log

调用方不再手写 allowUnowned，只声明"我在查哪个域"。
```

**理由**：语义由**域**决定，不由调用方决定 —— 这正是 D5 的根因（5 个调用方各自判断）。
