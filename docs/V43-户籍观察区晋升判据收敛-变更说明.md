## 一、问题与实测证据

乙1（`f0c1dbb`）给转正通道补挂了准入同源闸门，但部署后实测暴露**覆盖面不足**：

```
candidate 498 个 → 闸门判拒 43 / 放行 455        ← 乙1 只保护 8.6%
```

卡在证据分 2/3（再被提及 1 次即到晋升线）的 **31 个**中：

| 乙1 会拦下（7 个） | 闸门放行、仍会晋升（24 个） |
|---|---|
| `麻批这` `毛毛多` `连在一` `后到我` `后你麻` `于是我` `管他们` | `关于` `经历` `强烈` `高潮` `相通` `高尚` `游泳` `国国家` `全不一` `终于进` `通过麻` `越舒服` … |

**`关于`/`经历`/`强烈`/`高潮` 是整词普通名词**，字面判据分不出来 ——
系统自身注释早已承认（`FamilyGraph:2745`）：「中文人名与滑窗片段在字面特征上不可分」。
**乙1 的方向（补闸门）在这个层面已到极限。**

### 1.1 结构诊断：真正的根因是晋升判据

```
证据分 = strongHits×3 + titleHits×1 + count×1   ≥ 3 即晋升
                                    ↑
                        纯「被提及次数」也能独立凑够 3 分
```

**任何词**在日常对话里都会被提到 3 次 ⇒ 观察区退化为**高频词计数器**。

### 1.2 实测数据（观测位：`status='candidate'` 的 498 个）

| 指标 | 数值 |
|---|---|
| 观察区里的**业主确认真人** | **0 个**（`陈都灵` 的 candidate 节点 `TXS-961` 语境是「陈都灵的叫声」，非真人介绍；其 `TXS-032` 已 void） |
| **纯裸提及**（`strongHits=0` 且 `titleHits=0`） | **497 / 498** |
| 有上下文（`strongHits≥1` 或 `titleHits≥1`） | **1 个**（`沈墨白`，titleHits=1，语境「沈墨白说他下周开班」） |
| `active` 97 个的构成 | 业主白名单真人 **25** + **疑似垃圾 72**（**74%**） |

**结论**：观察区里没有业主确认的真人 —— 真人走**直接建档**路径，或由**LLM 终审**认定。
观察区「靠裸提及自行晋升」这条路径，**服务的是高频词，不是人**。

### 1.3 旁证：现有强判据本身含误报源

`FamilyGraph:645`：
```ts
const NAME_INTRO_BEFORE = ['这是', '叫做', '名叫', '我叫', '他叫', '她叫', '叫', '是'];
```
判定是 `beforeWin.endsWith(w)`（前 6 字窗口**结尾**匹配）。单字 `'是'` 与 `'叫'` 过于宽泛——
实测 `公明` 的语境「以前**是**公明，现在叫光明」中，`endsWith('是')` 命中 ⇒ `strongHits=1`
⇒ 证据分 4/3 ⇒ **转正 active**。**`公明` 是地名，它的转正直接来自这个误报。**

## 二、方案：1 个文件、2 处逻辑 + 1 处测试期望订正

### 2.1 改动 1（核心）— 晋升须有真实上下文

`src/m4/household/FamilyGraph.ts`（`_accumulateCandidateEvidence` 内）

```ts
// 现在
const promoted = evidenceScore >= CANDIDATE_PROMOTE_SCORE && _promoteGateOk;

// 改为 —— 裸提及次数不再单独构成晋升依据
const _hasRealContext = (ev.strongHits || 0) >= 1 || (ev.titleHits || 0) >= 1;
const promoted = evidenceScore >= CANDIDATE_PROMOTE_SCORE && _hasRealContext && _promoteGateOk;
```

**判据语义**：与真人出现在对话语法结构中才算证据 ——
- 强上下文 = 关系词（`朋友/同事/同学/老板/老师/领导/亲戚/家人/老乡/对象/男朋友/女朋友`）或介绍句式（`这是/叫做/名叫/我叫/他叫/她叫` / 后置 `是我`）
- 弱上下文 = 紧邻称谓动词（`说`/`找` 等，见 `NAME_TITLE_BEFORE/AFTER`）

### 2.2 改动 2（判据调优）— 去掉误报源 `'是'`

`src/m4/household/FamilyGraph.ts:645`

```ts
// 现在
const NAME_INTRO_BEFORE = ['这是', '叫做', '名叫', '我叫', '他叫', '她叫', '叫', '是'];
// 改为 —— 删去单字 '是'（误报源，公明实证）
const NAME_INTRO_BEFORE = ['这是', '叫做', '名叫', '我叫', '他叫', '她叫', '叫'];
```

**保留 `'叫'` 的理由**：它是介绍句的核心动词，且已有 `我叫/他叫/她叫/名叫/叫做` 覆盖多数形态；
而 `'是'` 的合法用法（「这是张小龙」）**已被 `'这是'` 覆盖**，剩余场景全是误报。

### 2.3 改动 3 — 订正一处测试期望（**业主明确批准**）

`src/m4/household/__tests__/candidate-zone.test.ts:195`

```ts

```

**该用例明确断言「无任何上下文的裸提及也能晋升」** —— 正是本次要收敛的行为。
改动 1 后它必然失败。**不是测试坏了，是它固化的设计意图已被实测证伪**。

**其余 4 个晋升断言不受影响**（均带上下文）：

| 断言 | 素材 | strongHits/titleHits | 改动后 |
|---|---|:--:|:--:|
| `:162` 首次提及带介绍句 | 「我姐姐叫批12验证」 | strong≥1 | ✅ 仍过 |
| **`:198` 被提及 3 次** | **「一句无关的话」** | **0 / 0** | ❌ **需订正** |
| `:213` 弱上下文 2 次 | 「观察区丙说明天来找我」 | title≥1 | ✅ 仍过 |
| `:223` 强上下文 1 次 | 「我同事观察区辛来了」 | strong≥1 | ✅ 仍过 |

> 本次只影响**纯裸提及**这一条路径，挂 **1 个** —— 影响面差异来自判据维度不同，不是放宽标准。

## 七、文档同步摘要（白皮书 / 蓝皮书）

### 7.1 白皮书更新摘要

**标题：观察区的晋升判据 —— 「被提及过」不等于「被认识」**

1. **晋升须有对话语法证据**（`FamilyGraph._accumulateCandidateEvidence`）。
   原判据 `evidenceScore = strongHits×3 + titleHits + count ≥ 3` 中，**`count` 可独立凑满阈值**
   ⇒ 任何高频词都能晋级。改为「`strongHits≥1 || titleHits≥1`」为**必要条件** ——
   名字必须出现在**关系词/介绍句/称谓动词**的语法结构中，才算「被认识」而非「被提到」。

2. **误报源 `'是'` 从强判据中移除**。单字 `'是'` 在前 6 字窗口结尾即判强上下文，
   导致「以前**是**公明」（地名）获得 `strongHits` 并转正 —— 实测实证。

3. **观察区的定位被正名**：它不是「新人候补区」，而是**高频词计数器**（实测 497/498 为裸提及、
   区内业主确认真人 0 个）。真人的来源是**直接建档**与**LLM 终审**，不是裸提及累积。

4. **长期方向（业主 2026-10-08 指示，归后续批次）**：字面判据已到极限，
   根治路径为「**LLM 定期筛选 + 备选区（临时调用，不直接正式归档）**」。
   实测 `EntityTriageService` 已存在并已接线，但**无定时调度**；备选区**尚无实现**。

### 7.2 蓝皮书更新摘要

**标题：M4 户籍生命周期 —— 证据的语义性要求**

1. **证据判据由「数量」转向「语义」**。`_accumulateCandidateEvidence` 的晋级条件现同时要求
   **分量**（`evidenceScore ≥ 3`，保持 P2-6 阈值不变）与**性质**（有对话语法上下文）。
   阈值未动，避免与 P2-6 的既有断言冲突。

   由**加分项**（×3 / ×1）升为**门控条件**（必要条件）。两个函数本身零改动，

## 八、方法论记录

1. **「补闸门」与「改判据」是两种不同层级的修复**。
   乙1 补闸门（准入同源判据）方向正确但**只覆盖 8.6%** —— 因为闸门是**字面**判据，
   而问题根源在**晋升因果**（纯计数）。⇒ 教训：**当补丁的覆盖面很低时，说明修错了层级**。

2. **「测试挂了」要先问测试对不对，再问代码对不对**。
   `candidate-zone.test.ts:198` 固化的行为在生产中制造了 74% 的垃圾 active。
   ⇒ 教训：**测试是设计意图的载体，意图被实测证伪时，改测试是修复而非妥协** ——
   但**必须经业主明确批准**（本次已获批），不能自行决定。

3. **「设计过但没落实」要以代码为证，不以记忆为准**。
   业主提出「之前反复设计过」，S1 顺手核实的结论是：**机制已建成且已接线，缺的是调度与数据模型** ——
   这比「完全没有」和「已经做好」都更接近事实，也决定了后续批次该做什么。
