# Prompt 拼装规范（PAS v1）— 法律法规草案

> 状态：**草案，待批准**（2026-09-19）
> 适用范围：本仓库**所有**提交给 LLM 的 prompt 拼装
> 立法依据：设计目的（§1）+ 2026-09-19 全链路诊断实测证据

---

## §1 设计目的（北极星，一切条款的裁判标准）

**拼装的唯一目的**：
> 让 LLM 在**本轮对话**中产出「符合角色身份、符合事实、符合当下时空情境」的**高质量回复**。

由此推导出三项不可让渡的要求：
1. **该给的一条不少**（充分性）——信息缺失会直接导致编造或答非所问
2. **不该给的一条不多**（必要性）——冗余会稀释注意力、烧 token、拖慢响应
3. **给的顺序不能错**（层级性）——LLM 的注意力对位置敏感，铁律必须在最前

---

## §2 质量标准（7 条，验收用）

| 编号 | 标准 | 反例（实测） |
|---|---|---|
| Q1 | **不残缺**：本轮回复所需信息齐备 | 会晤实体缺档案 → 编造身世 |
| Q2 | **不臃余**：无重复、无无关内容 | 核心铁律被注入 2 次；记忆 5 条路径 |
| Q3 | **无冲突**：指令自洽，无相互矛盾 | 教编造外貌 vs 绝对禁止编造 |
| Q4 | **层级正确**：铁律在前，参考在后 | kb（1.2 万字符）挤在核心铁律之前 |
| Q5 | **格式规范**：标签统一、分隔清晰、无机器元数据 | YAML `id:`/`title:` 混入 prompt |
| Q6 | **经济**：token 用量与信息量成正比 | 会晤 100% 注入 1945 字符无关人设 |
| Q7 | **高效**：拼装耗时可测量、受控 | 全链路**无任何耗时埋点** |

## §3 分层架构（强制）

```
┌─ L0 硬规则层（每轮必注入 · 固定 · 单一真源 · **分项预算**）
│    · 身份（当前模式下的"我是谁"）
│    · 时间现实（当前时空）
│    · 安全边界
│    · 说话纪律（长度/口语化/禁止内心独白）
│    ⟶ 位置：必须处于 prompt 最前部
│    📌 预算分项（2026-09-19 批4 实测修正）：L0 = systemPrompt 中除 kb 以外的部分，
│       其中含 role prompt。单一 2200 阈值会制造“假绿”（只测 secretary 302 字符）：
│         - **L0 核心**（铁律+身份+时间）≤ **2000**（实测 1934）
│         - **role prompt** ≤ **2500**（实测 secretary 302 / lover L2 2335 / recaller 313）
│       最重组合（lover level=2）L0 总 ≈ 4269。
│       ⚠️ 铁律内容是安全底线，不得为了卡数字而删。
│
├─ L1 本轮任务层（按意图动态 · ≤2000 字符）
│    · 用户本轮消息（原文）
│    · 本轮意图判定结果
│    · 本轮检索命中（知识/记忆）
│    ⟶ 位置：紧跟 L0
│
└─ L2 参考背景层（按需 · 可截断 · ≤4000 字符）
     · 实体/人物档案
     · 长期记忆
     · 对话历史
     · 知识库条目
     ⟶ 位置：L1 之后；每段必须带「仅供参考，不主动提」语义
```

**总预算上限：8000 字符**（超出按 §5 规则裁剪）。

## §4 条款（可检查，违规必究）

### A. 单一真源

- **P-01** 同一事实**只允许一处定义**。禁止在两个模块各写一份（实测违规：核心铁律 2 份，9/24 行重复）。
- **P-02** 同一内容**只允许一处注入**。禁止同一批数据经多条路径进入同一 prompt（实测违规：记忆 5 路径 / 对话历史 3 路径 / PFC 内容 2 路径）。

### P-03 分层归属
任何注入点**必须声明层级**（L0/L1/L2）。未声明者不得注入。

### P-04 必要性准入（目的驱动）
**L2 一律按需注入**——必须满足「本轮意图命中相关域」或「该模式下的保底清单」。禁止无条件全量注入。

### P-05 保底清单（充分性反制）
以下内容在对应模式下**必须**注入，不受 P-04 影响：

| 模式 | 保底项 |
|---|---|
| 实体会晤 | 该实体档案（身份/关系/基本信息） |
| 角色扮演 | 该角色档案 |
| 全部模式 | L0 硬规则 |

### B. 格式

- **P-06** 段标签统一使用 `【】`；段间分隔统一 `\n\n`。
- **P-07** **禁止** YAML frontmatter、JSON、`id:`/`title:`/`type:` 等机器元数据进入 prompt（实测违规：26/26 样本 YAML 撕裂）。
- **P-08** 段落不得粘连（相邻两个 `】` 标签之间必须有分隔符；实测违规：`…不清楚了。"【🚨 核心铁律`）。

### C. 冲突与层级

- **P-09** 同层内**禁止语义冲突**的指令并存。发现冲突必须二选一，并在代码注释说明取舍理由。
- **P-10** L0 必须位于 prompt 最前部（`buildSystemPrompt` 不得把 L2 内容前置）。
- **P-11** 模式隔离：`entity_meeting` / `roleplay` 模式下，prompt **不得包含**玉瑶身份标记（`你是玉瑶`/`你的名字是玉瑶`/`你的名字叫玉瑶`/`玉瑶 · 灵魂伴侣`/`玉瑶的私人秘书兼情人`）。

### D. 预算与截断

- **P-12** 超预算时**按 priority 降序保留**，禁止按到达顺序截断。
- **P-13** 被截断的段必须**记录并告警**（静默丢弃视为违规）。
- **P-14** 每轮拼装必须校验总字符数，超上限必须降级裁剪路径。

### E. 可观测

- **P-15** 拼装必须埋点：`总字符数`、`各层字符数`、`拼装耗时(ms)`、`被截断段列表`。
- **P-16** 模式隔离断言（P-11）必须在**出口**执行且留痕。

### F. 变更受控

- **P-17** 新增/修改注入点必须**登记到注入点清单**（§6），并通过规范合规测试。
- **P-18** 禁止在业务函数中直接写裸字符串拼接注入（`finalKnowledgeText = X + Y`）；必须经装配器。

## §5 意图 → 注入矩阵（L1/L2 的实际依据）

| 本轮意图 | L1 必给 | L2 按需给 |
|---|---|---|
| 日常闲聊 | 用户消息 | 无（或极简情感背景） |
| 事实回忆（问"谁/什么时候/几岁了"） | 用户消息 + 事实快照 | 档案 + 相关记忆 |
| 知识查询（文档/学问） | 用户消息 + 检索结果 | 命中知识条目 |
| 情感表达/倾诉 | 用户消息 + 感受守卫 | 近期记忆（带"不主动提"约束） |
| 实体会晤 | 用户消息 + 会晤实体档案 | 该实体记忆/知识 |
| 角色扮演 | 用户消息 + 角色档案 | 分支内记忆 |
| 工具型（`rawCall`：抽取/判定/排序） | 任务指令 + 输入数据 | 无（禁止注入人格） |

## §7 管控机制（三级防线）

### 第一级：静态检查（提交前）
- **P-17/P-18 合规测试**：扫描 `chat.ts` 等文件，禁止裸拼接模式、要求注入点登记

- **P-01 去重测试**：断言核心铁律等"单一真源"内容在源码中只出现一份

### 第二级：运行时断言（dev + 生产告警）
- **P-11 模式隔离**：出口断言（已有 `prompt-sanitizer`，需扩展到 role prompt 与 messages）
- **P-14/P-15 预算与埋点**：每轮输出 `[PromptBudget] L0=… L1=… L2=… total=… ms=…`
- **P-13 截断告警**：被丢弃段超阈值 → `console.warn`

### 第三级：测试守门（CI）
每个条款至少一个测试用例，落入 `src/__tests__/prompt-assembly-spec.test.ts`：

| 条款 | 测试断言 |

## §9 例外与豁免

任何条款的临时例外，必须：
1. 在代码注释注明 **条款编号 + 例外理由 + 失效条件**

3. 例外不得长期存在（超过 30 天必须复审）
