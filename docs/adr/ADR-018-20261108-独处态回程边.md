# ADR-018 · 独处态回程边（散会后可回到玉瑶私聊）

- **日期**：2026-11-08
- **状态**：已采纳（第 1 批：状态机基线；第 2 批接意图判定与独处文案）
- **相关**：`docs/blueprint/白皮书_空间路由器-v1.md` §2.5、`docs/blueprint/蓝皮书_空间路由器-v1.md` §15、`docs/LEDGER.md` §6.14

---

## 1. 决策

给会话状态机补一条**唯一合法的离开边**：

- 新增状态动作 `RETURN_YUYAO`：仅在**空场**（`participants.length === 0`）且处于独处相位时生效；
  复位 `everHadSeats=false`、`aloneNotified=false`；非空场一律拒绝（会晤中要回玉瑶必须先 `LEAVE`）。
- `GroupSession.reset()` 改为 `LEAVE → RETURN_YUYAO` 两步，兑现「回到玉瑶态」的文档语义。
- 删除零调用的 `clearSession()`。
- `MessageIntent` 增加去向字段 `toYuyao`：由 `detectIntent` 用**同一组**玉瑶专属句式判定，
  上层（`chat.ts`）只消费判定结果，不再各写一份正则。

## 2. 为什么这样设计（追溯依据）

**事故**：2026-11-08 实测发现，会晤散会后系统永久停在 `alone`，玉瑶不再应答，重启也无效。

**根因（结构性，不是漏调用）**：

```
sessionMode(state) = participants.length > 0 ? 'meeting'
                   : everHadSeats ? 'alone' : 'yuyao'
```

`everHadSeats` 由 `WAKE` 置 `true`，`LEAVE` 只做 `old || 有人` —— **全仓没有任何路径把它改回 `false`**。
用一个「历史事实」派生「当前相位」，历史事实天然不可逆 ⇒ 状态机缺边，`alone` 成为终态。

**为什么不是「在散会处补一行复位」**：那正是补丁。缺边的状态机还会被下一个人写成别的死路；
必须在状态机内给出显式转移，并让意图层提供「业主明确唤回玉瑶」这一触发条件。

**为什么 `RETURN_YUYAO` 只在空场生效**：会晤中直接回玉瑶会跳过 `LEAVE` 的副作用
（纪要生成、门卫清除、现场恢复 `restoreSlot`）。顺序必须由调用层保证：
**先 `LEAVE`（结束会晤、产生副作用）→ 再 `RETURN_YUYAO`（离开独处相位）**。

**为什么拆成 `MessageIntent.toYuyao` 而不是新增意图种类**：
`exit` 的语义是「结束」，而「结束后去哪」是去向而非另一种结束。加一个去向字段可以让
既有 `kind==='exit'` 的契约与测试保持不变，同时把「玉瑶专属句式」的判定收敛在
`detectIntent` 一处（不变量 #7：同一规则禁止多处实现）。

## 3. 备选方案与为何放弃

| 方案 | 做法 | 放弃原因 |
|:---|:---|:---|
| A. 散会即回玉瑶 | 删除 `alone` 语义，`LEAVE` 后直接 `everHadSeats=false` | 推翻业主 2026-10-31 明确要求的「散会后房间安静」体验（白皮书 §2.5） |
| B. 在 chat.ts 散会处补一行复位 | 局部修 | 补丁：状态机仍有不可逆分支，任何未来调用路径都可能复现；且无法区分「散会」与「回玉瑶」 |
| C. 独处态加定时器自动回玉瑶 | 超时自动复位 | 模糊语义、不可观测、与「叫谁谁来」的分配器理念冲突 |
| **D. 状态机补 `RETURN_YUYAO` + 意图去向字段（采纳）** | 显式转移 + 单源判定 | 可证明可逆、可审计、不依赖调用纪律 |

## 4. 影响范围与回滚

**影响文件（第 1 批）**：
`src/m5/group/types.ts`、`sessionReducer.ts`、`GroupSession.ts`、`SessionStore.ts`、
`src/m4/household/EntityMeeting.ts`、`src/webui/chat.ts`，以及白皮书/蓝皮书/本 ADR。

**不受影响**：
- `group_session_state` 持久化格式（字段不变、`schemaVersion` 不 bump，旧快照直接兼容）；
- 会晤可见性/隔离、耳语、纪要、门卫逻辑；
- 独处态「不生成回复」的既有行为（通用结束语仍留在独处）。

**回滚**：单批 `git revert`；无数据迁移，回滚后旧行为（`alone` 终态）立即恢复。
若线上出现异常，可临时把 `RETURN_YUYAO` 分支改为 `return prev`（回到旧行为），无需动数据。

## 5. 后续出问题先看这里

1. **散会后说「玉瑶」没反应** → 查 `detectIntent` 是否给出 `toYuyao=true`（第 2 批接线），
   以及 `chat.ts` 里 `_gs.mode === 'alone'` 的判定时刻（必须在 dispatch 之前）。
2. **会晤中说「回玉瑶」只结束不回私聊** → 检查 `LEAVE` 后是否补发了 `RETURN_YUYAO`（第 2 批）。
3. **重启后又变回静默** → 读 `engine_store.group_session_state`：
   `participants=[] && everHadSeats=true` 即独处；若业主已喊回玉瑶，说明 `RETURN_YUYAO` 没有落盘
   （检查 `saveSession` 是否被 `participantLeft` 等 effect 触发）。
4. **不要把 `everHadSeats` 当历史事实理解**：它现在承载的是「散会后尚未唤回玉瑶」这一**当前相位**，
   可置真可置假。字段名是历史遗留，语义以本 ADR 为准。
