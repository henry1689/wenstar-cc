# ADR-011: 记忆「取」的架构 —— 分层候选 + 统一编排

- **状态**: 提议中 — 待实施（P1，P0 止血之后）
- **决策**: 把会晤/常规两条路径上彼此不知情的**十余条注入通道降级为「候选来源」**；新增一层统一的记忆编排器，按「**时间覆盖 × 话题相关 × 情感强度**」三轴分配名额，取代"先到先得"；三库收敛为**结论层（黑钻）/ 事实层（金库）/ 原文层（砂金）**，按层出结果而非按表出结果；**钙化从"最终排序键"降级为"候选池入场券"**；同一规则只允许**一份实现**。
- **日期**: 2026-10-06
- **依据**: 《太虚境户籍法》、ADR-008（钙化统一）、ADR-010（对话块）、`docs/P0-记忆体系止血任务书-V3.md`、V35 三批结论
- **相关**: P0-MEM-STOPBLEED-V3、ADR-010（`8d323e6`/`60516a4`/`2d667f1`）、批 A2/A3（`4c00672`/`53a9fbe`）

## 一、S1 诊断摘要（全部结论来自生产库 / 代码只读实测）

业主的问题不是某一条通道坏了，而是**反复修一条、另一条又成为瓶颈**。诊断指向一个结构性事实：

> **系统有「存」的架构（三库分层很清楚），但没有「取」的架构。**
> 取的时候是十余条路各自为战、按各自的历史惯性（钙化 / 时间 / 关键词）抢名额，没有一层统一的"这次该给她什么"的决策。

### 1.1 一次会晤里，有十几条通道同时往同一个数组里 push

`src/webui/chat/retrieval-stage.ts` 的会晤隔离墙（约 660 行）内：

| # | 通道 | 取数 | 排序依据 |
|---|---|---|---|
| 1 | 作品指称解析 | 1 篇全文 | — |
| 2 | SearchOrchestrator 中枢 | ≤10 | RRF |
| 3 | **近期槽** | 8 | 纯钙化 |
| 4 | **历史槽** | 6 | 纯钙化（全历史） |
| 5 | 回忆问句追加最早 6 | 6 | `seq_pos ASC` |
| 6 | 内容相关关键词召回 | 4 | LIKE |
| 7 | 金库 `vault_log` | 8 | `created_at DESC` |
| 8 | 砂金库高钙 | 3 | 钙化 |
| 9 | **砂金库原文兜底** | 12 / 1440 字符 | `timestamp DESC` |
| 10 | 对话降级（V5.3） | 10 | `timestamp DESC` |
| 11 | 长文直取（V23） | 5 | 主题特征 |
| 12 | LLM 兜底挑选 | 筛选 | LLM |

外加四道**过滤闸门**（低价值拦截 / 隐私过滤 / 编造特征过滤 / 反编造铁律）。

### 1.2 🔴 同一概念有两份实现，且注释声称"同源"

| 实现 | 位置 | 谁在用 |
|---|---|---|
| A | `m4/retrieval/meeting-recall.ts:141 / :157` | `MeetingWallAdapter`（SearchOrchestrator 路径） |
| B | `webui/chat/retrieval-stage.ts:268-279`（**内联 SQL**） | **会晤主力路径** |

`retrieval-stage.ts` 从 `meeting-recall.js` 只导入 5 个符号，**两个槽位函数不在其中**；
而 `MeetingWallAdapter` 的注释写着「共享工具（meeting-recall.ts），**与隔离墙同源**」。

> 这是本仓「**注释写的才是对的，实现与之相悖**」的又一例（V35 三批的根因同族）。
> 后果：修 A 等于没修 —— 主力路径一行没动。

### 1.3 两套时间观

- `Foundation` 融合**有**时间近因：`recencyRatio()` 7 天线性衰减 × 0.10（`fusion.ts:55-62`）
- 会晤的两条槽位**完全没有时间维度**（`ORDER BY calcium_score DESC`，无时间项）

同一个系统里，两条路径对"新近"的态度相反。

### 1.4 通道之间"先到先得"，去重靠字符串前缀

每条通道各自 `memoryFragments.push(...)`；去重判据是
`f.includes(str.substring(0, 20))` —— **前 20 字相同的两条就当作同一条**。
⇒ 谁先 push 谁进上下文；**通道之间不知道彼此存在**，也没有任何一层做全局排序或名额分配。

`Foundation` 侧反而有正确的做法：`dedupeKeyOf(hit)` + RRF + MMR（`fusion.ts`）—— 说明**能力已经存在，只是没有统一到所有路径**。

### 1.5 钙化一身兼二职，导致"时间饥饿"

钙化同时扮演：① 候选质量分 ② **最终排序键**。

实测后果（2026-10-06）：

```
14 条 calcium=10 的记忆 → 全部来自 2026-08-27/28 与 2026-09-08（29~40 天前）
会晤历史槽 LIMIT 6 被这 14 条永久占满
最近 5 天的 176 条记忆，在该排序里最好排名 = 第 43 名
全表 95.8% 的记忆 calcium_score < 1
```

⇒ 「一两天前聊过的」正好掉进四条通道的缝隙：近期槽只覆盖 24 小时、历史槽排不上、
关键词通道也是 24 小时、砂金库兜底 `ORDER BY timestamp DESC` 只回看几小时。
**这不是概率问题，是结构上不可能被召回。**

### 1.6 闸门很多，覆盖为零

四道闸门全是「**剔除坏的**」（低价值 / 他人私密 / 编造特征），
**没有一道是「保证每个时间段、每个话题都有代表」**。

> **过滤 ≠ 覆盖。** 这正是"她把昨天聊的忘光了，却满口一个月前的地标"的直接原因。

### 1.7 三库没有"层"语义

砂金库 / 金库 / 黑钻库各自走各自的通道、各有各的排序：

| 库 | 实测存量 | 取的时候 |
|---|---|---|
| 砂金库 `memories` | 9593 | 钙化序 / 时间序 / 关键词，三种口径 |
| 金库 `vault_log` | 6805 | `created_at DESC`（landmark 3212 与 promote 3152 混在一起抢） |
| 黑钻库 `black_diamond` | 2155 | `LIKE` + `created_at DESC`（**徐诗雨一人 1087 条，占一半**） |

三者在语义上本是**结论 → 事实 → 原文**的层次关系，取的时候却完全平权。

### 1.8 生命周期状态在检索侧不统一生效

`suppressed` 存量 **1391 条**，但会晤槽位的查询里**没有任何 `lifecycle_state` 过滤**
（`retrieval-stage.ts` 全文 grep `lifecycle` = 0 命中）。
⇒ 想用"标记"来治理检索是无效的；而且该字段已被 `SelectiveForgettingEngine`（遗忘落点）
与 `SleepTimeConsolidator`（**会主动复活 suppressed 行**）占用。

## 二、决策

### D1 · 「取」的单一入口

新增 `MemoryOrchestrator`：所有候选来源注册为**候选提供者（candidate provider）**，
由编排器统一收口。现有十余条通道**降级为 provider**，不再直接 `push` 到上下文。

三段式：

```
候选层（providers，并行，各自只负责"捞出候选"）
   ↓
编排层（去重 / 打分 / 三轴名额分配 / 分层）
   ↓
预算层（沿用 MemoryInjector 的 kind + 预算体系，其作为唯一预算分配器的地位不变）
```

### D2 · 三库收敛为「层」，按层出结果

| 层 | 载体 | 语义 | 在上下文中的角色 |
|---|---|---|---|
| **结论层** | `black_diamond` | 已提炼的结论 | 最高优先，少量 |
| **事实层** | `vault_log` | 事实 / 承诺 / 重要沉淀 | 中等，按话题 |
| **原文层** | `memories` + `conversations` | 原始记忆与原文 | 主力，按时间与话题 |

同一层内部再排序；**层与层之间先保证"每层都有代表"**，再谈权重。

### D3 · 名额分配三轴（取代"先到先得"）

| 轴 | 作用 | 判据 |
|---|---|---|
| **时间覆盖** | 保证每个时间段有代表 | 分层配额：<1天 / 1~3天 / 3~7天 / 7~30天 / 30天+ |
| **话题相关** | 与当前消息相关者优先 | 倒排索引命中 + 40D 情感相似度（既有能力，纳入统一打分） |
| **情感强度** | 重要的优先 | 钙化（降级为**轴之一**，见 D4） |

**三轴之外的任何"某条通道固定占 N 个名额"都应视为待清理的历史包袱。**

### D4 · 钙化降级：从"最终排序键"到"候选池入场券"

- 钙化**继续决定**：是否进入候选池、在池内的**基础权重**
- 钙化**不再决定**：跨时间段的最终名次（那由 D3 的时间覆盖轴与话题相关轴共同决定）

理由：钙化的分布是**长尾 + 天花板**（实测 14 条 = 10，95.8% < 1）。
把它当唯一排序键，数学上必然导致"古老地标永久压制近期内容"。
（与 ADR-008「钙化统一」不冲突：本决策不改钙化的**计算**，只改它的**用途**。）

### D5 · 同一规则只允许一份实现

- 槽位逻辑收编到 `meeting-recall.ts`，`retrieval-stage.ts` 改为调用
- 去重判据统一为 `dedupeKeyOf`（域 + 主键），**废弃 `substring(0, 20)` 前缀判据**
- 新增能力前先全仓 grep 同名判据（本仓不变量 #7）

### D6 · 时间近因是全系统统一口径

以 `Foundation` 已有的 `recencyRatio()`（7 天线性衰减）**为唯一实现**，
会晤路径与常规路径都复用它，不再各自造时间窗。

### D7 · 生命周期状态在检索侧统一生效

- `active` / `promoted`：正常参与
- `candidate`：**降权**参与（不排除 —— 它是"尚未确证"而非"无效"）
- `suppressed`：**排除**

配套：`suppressed` 的语义回归"遗忘"，不再被当作通用垃圾标记
（该字段已被两个引擎占用，见 1.8）。

### D8 · 「只增不删」在"取"侧的含义

**数据不删**（原文永久留存，ADR-010 已确立）；
**但"不删"不等于"必须占名额"** —— 通过 D3 的分层配额与 D7 的状态过滤来"不给名额"，
而不是删除记录。

## 六、验收判据

### 机械
- `npx tsc --noEmit` exit 0
- `npm test`（= `vitest run`）零回归
- 全仓 grep：槽位逻辑仅 1 处、去重判据仅 1 处、时间近因仅 1 处

### 定量（生产口径）
- 「1~7 天前」的召回成功率从 **0** 提升到 ≥80%
- 历史槽 TOP6 的时间分布覆盖 ≥3 个时间段
- 会晤上下文里 24h 内 / 1~7 天 / 7~30 天 / 30 天+ 均有代表

### 行为（**唯一能证明问题解决的判据**）
- 问「我们前几天聊的国美那件事」→ 能答出「下雨、去了国美、没看到画展国画」
- 问「我们一个月前说过的那件事」→ 仍能答出（老地标不得被挤掉）
- 连续 15+ 轮后回问中途细节 → 能答上

### 不变量（防退化）
- **数据只增不删**：任何 P1 改动不得删除 memories / conversations / vault_log 记录
- **禁止新增"某条通道固定占名额"**：名额只能由三轴分配产生

## 七、与既有 ADR 的关系

- **ADR-008（钙化统一）**：本 ADR 不改钙化的计算，只改它在检索中的**用途**（D4）。
- **ADR-010（对话块）**：块是**中期记忆的载体**（P1-B/P1-C1 已入库）；
  本 ADR 解决的是「**怎么把块取出来**」—— 二者互补，不重叠。
- **P0 止血任务书 V3**：P0 是止血（先让"记不住"不疼），本 ADR 是止血之后的**结构**。
  P0-1 的改动即本 ADR 的 Phase P1-a。
