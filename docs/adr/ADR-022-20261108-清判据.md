# ADR-022 清理实体判据：合并双闸门、删除死导出与滑窗自检

- 日期：2026-11-08
- 状态：已采纳
- 前置：ADR-020（准入内联取证）、ADR-021（拆除观察区）
- 依据：任务书 `docs/实体提取架构收口任务书-V1.md` §8 批4；业主 2026-11-07「物理清除，避免死灰复燃」

## 1. S1 实测

| 事实 | 证据 |
|---|---|
| 两道 person 闸门在同一点串联且判据同源 | `FamilyGraph.addNode` 先 `GarbageEntityGuard.checkEntity`，再 `EntityWriteGate.checkPersonEntity` |
| 后者是严格超集 | 同一 `ENTITY_BLACKLIST`；`FG_EXTRA_BLOCK` 为超集（多 妈/爸/爱）；额外长度 2-5、`CHAT_RESIDUE` 对话残留；同用 `gradeEntity≥3` |
| 前者无独有判据 | `checkEntity` 仅返回 allowed/grade；grade-3 分支已在批3 删除 |
| 死导出 | `GarbageEntityGuard.filterEntities/auditGarbage`、`EntityCandidateGrader.gradeEntities/filterStableEntities/gradeReport`、`EntityWriteGate.checkEntityWrite` —— 零生产调用 |
| 滑窗自检已失去前提 | `FGHealthCheck.detectSlidingWindowJunk` 的判据是「无档案 + 非名尾字 + 单句低证 = 滑窗片段」；滑窗已死，且会误报「刚被介绍、档案未回填」的合法新实体 |

## 2. 决策

1. **合并双闸门**：保留 `EntityWriteGate.checkPersonEntity`，物理删除 `GarbageEntityGuard.ts` 及其调用与懒加载。
2. **删除零调用导出**：`gradeEntities` / `filterStableEntities` / `gradeReport` / `checkEntityWrite`。
3. **删除滑窗自检**：`FGHealthCheck.detectSlidingWindowJunk` + `_buildActiveNamePrefixes` + `PROFILE_COMPLETENESS_MIN`；maintenance 的定时器/首轮触发/stop 清理与 `entityTriageInterval` 配置。
4. **保留 `gradeEntity`**（与任务书原条款的偏差，见下）；**保留 object 通道**（`checkObjectEntity` + `SQLiteAdapter.ensureEntity`）。

### 与任务书的偏差（明确记录）

任务书原列「删 `EntityCandidateGrader`」。S1 结论：**保留 `gradeEntity`** ——
它是合并后唯一写前闸门的字面判据库（姓氏/停用词/句子片段/非名尾字）；删除它会让新准入的
确定性正则（如「叫」后 2-4 汉字）产出的片段名失去最后一道防线。只删其中零调用导出。

## 3. 附带修正

- `_addNodeInner` 的 fail-closed 日志原直接拼 `node.name`，违反 FG 红线 §16.6（console 不得输出真人名）；
  本次改为 `_maskName` 脱敏。
- 滑窗自检日志同样会输出真实人名，随功能删除一并消除。
