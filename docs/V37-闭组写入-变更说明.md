## 一、P1-A 留下的悬空

P1-A 建好了 `dialog_groups` 表（块级元数据的唯一载体），但**没有任何代码往里面写** —— 表是空的。P1-B 补上写入侧。

同时 S1 实测揭示的另一个事实：**对话组从未成形**。1297 个组里 747 组（57.6%）只有 1 轮、平均 2.4 轮 —— 因为 [chat.ts](../../src/webui/chat.ts) 硬编码 `rounds >= 10` 就封组，长场景在 30 分钟闲置阈值之前就被砍断了。

## 二、三处方案细化（勘察后对原方案的修正，均已在实施前报业主确认）

### 细化 1 · T2「短关窗重开」取消 —— 没有信号源

原方案要求区分「窗口开着闲置」与「关窗重开」两套阈值（T1/T2）。勘察结论：

- 前端**没有任何** `beforeunload` / `visibilitychange` / `pagehide` 监听（全仓 grep 0 命中）；
  服务端只有 observability 的 SSE `req.on('close')`，与聊天主链路无关。
  ⇒ **关窗对服务端不可见。**
- 但不需要它：「窗口开着闲置」与「关窗后重开」在服务端是**同一件事** —— 消息间隔。
  一个阈值即可判定三种会话场景（闲置超时封组 / 短间隔续上 / 长间隔封组）。

⇒ 只做 T1，不引入第二套阈值。

### 细化 2 · 撤销「不再剥离括号场景描写」

分层已给出正解：**氛围留在 `conversations` 原文**（实测带括号比例 79.2%），由后续 P1-C 的块检索带出；
`mem_*` 剥括号是**防「场景复读死循环」机制**（`persistence-stage` 注释写明该风险：LLM 读到自己写的
场景文本 → 重新走进那个场景 → 死循环）。改它 = 把一个已修的 bug 放回来。**本批不动。**

### 细化 3 · 块层衰减类别不迎合 `runDecay` 的关键词

`MemoryAssessor.runDecay` 按 `narrative_tag` 的**关键词**分档（家庭/情人/亲密→emotional 0.02，
朋友/同事→relational 0.05，工作/项目→work 0.08，其余→neutral 0.10）。
而 `dialog_groups` 是**独立表、不走 `runDecay`** ⇒ 正确做法是块层自己输出 `BlockDecayClass`，
**不伪造「家人」之类中文标签**去迎合另一层的匹配。为不存在的消费者写代码 = 打补丁。

## 三、本次改动

### 3.1 `BlockValueScorer`（新） —— 确定性块价值判定

**零 LLM**。两条独立理由：① 撞本仓「Harness 零 LLM 监控」铁律（后台路径必须纯系统级）；
② **不可复现的判据 × 不可逆的持久化决策 = 结构性风险** —— LLM 打分同一块今天 3 分明天 5 分，
而「块进不进检索池」是写定后长期生效的决定 ⇒ 检索池随机漂移且不可归因。
LLM 至多允许**单向增强**（只能捞回被低判的块，无权剔除高分块），本批未启用。

**判据收拢（不变量 #7）** —— 本文件是以下判据的唯一实现处：

| 判据 | 来源 |
|---|---|
| `FEATURE_ROUND_RE` | 原内联在 `dialog-group-stage`，**已迁入此处**，两处共用一份 |
| 场景描写判据 | 原散落在 `persistence-stage` 的剥括号正则 |
| `isDegenerateContent` | **直接复用** `m2/MemoryWriteGateway` 的实现，不重写 |
| 钙化标度 | 复用 `m2/math.computeCalcium`，与逐轮砂金写入**同标度** |

**评分**（0–10，与 `memories.calcium_score` 同标度）：

| 信号 | 分值 | 判据 |
|---|---|---|
| 场景描写 | 0–2 | **有效**括号（内容 ≥30 字）所占**轮次**比例 ×2 —— 修正 D：只判「有没有括号」会让几乎所有块满分（实测 assistant 行 79.2% 带括号） |
| 情绪起伏 | 0–2 | 情绪曲线**极差**（起承转合看峰值与谷值的距离，不是离散度） |
| 承诺/约定 | 0–3 | `FEATURE_ROUND_RE` 命中即得，**不按次数累加** |
| 话题转折 | 0–2 | `close_reason === 'topic_switch'` |
| 退化惩罚 | ≤0 | 问答**两侧都**退化才算退化轮（用户敷衍但角色认真回应仍是有效剧情），按占比最多扣 3 分 |

`scene_anchor_hash` 是**等值指纹**（归一化场景文本 + 话题主类 + 实体名排序 的 sha256 前 16 位），
用于防复读与块去重 —— **不是相似度度量**（相近但措辞不同的场景不会判同），边界已写入注释。

### 3.2 `dialog-group-stage` —— 闭组写 `dialog_groups`

在锚点写入之后落一行块级元数据（钙分 / 场景指纹 / 情绪曲线 / 闭合原因 / 轮数 / 起止时间 / 归属）。
失败不阻塞闭组主流程，但**必须告警可追责**（P-13 精神）—— 块元数据是 P1-C 检索的全部依据，
静默失败会让块层「看起来存在但空白」。

### 3.3 `chat.ts` + `MemoryConfig` —— 封组判据去硬编码

- 新增 `MemoryConfig.compaction.dialogGroup`：`dgMaxTurns`（**80**）、`dgIdleCloseMs`（30 分钟）
- `rounds >= 10` → 读 `dgMaxTurns`。定为 **80**，与 `contextWindowTurns(80)` 对齐 ——
  **一块 ≈ 一个上下文窗口**（两者保持独立可调，因其概念不同：窗口是注入范围、本项是块容量）
- **语义修正**：原 `Date.now() - _dg.startTime` 是「**组时长**上限」而非「闲置超时」——
  一组连续聊满 31 分钟就会被切断，哪怕中间一秒没停。现改为距**上一条消息**的间隔，
  这才是「闲置」本义，也才让三种会话场景用同一个阈值成立。
- 新增 `block_close_reason` 落库（按判定顺序取第一个成立的），是该块「为什么在这里断开」的唯一可追责线索。

### 3.4 🔴 根治既有缺陷：锚点 `seq_pos` 唯一冲突（本批验证中发现）

**缺陷**：`memories.seq_pos` 是 `UNIQUE NOT NULL`（[schema.sql:7](../../src/m2/schema.sql)），
而锚点写入用 `seqPos: -(dg.rounds.length + 100)` —— **按「轮数」算值 ⇒ 同轮数的组算出同一个数**，
同轮数的第二个组起锚点写入**静默失败**。

**生产取证（2026-10-06）**：

```
当天闭合的组：        DG_9340(1轮) DG_9342(1轮) DG_9344(2轮) DG_9348(1轮) DG_9350(1轮)
当天库里的负 seq_pos： DG_9340(-101)              DG_9344(-102)
```

四个 1 轮组全部算出 `-101`，**只有第一个写进去**。另在生产库副本上用真实 `flushDialogGroup`
复现出同一条错误：`UNIQUE constraint failed: memories.seq_pos`。

**后果**：运行期锚点（情感峰值轮**全文、保留场景**）**大部分根本写不进去** ——
而这正是 ADR-010 §1.4 要救回的那份（对比重启重建版的「每行截 150 字符」）。

**修法**：`seqPos: -Math.abs(Number(dg.rounds[0]?.seqPos) || 1)` ——
首轮 `seq_pos` 由 conversations 逐轮递增保证组间唯一 ⇒ 其负值亦唯一，且同组跨重启稳定
（不依赖任何运行时计数器）。`|| 1` 仅兜底 seqPos 缺失/为 0 的退化输入。

**行为验证**：修复前探针输出 `锚点是否照常写入: 🔴` + UNIQUE 报错；修复后 **✅**，`dialog_groups` 行照常写入。

## 四、📘 白皮书更新摘要

**《太虚境持久化与记忆分层》章节（标题：对话块价值判定与闭合规则）**

1. **块价值判定采用确定性规则，禁止 LLM 打分** —— 判据全部复用仓内已有算子并收拢到
   `BlockValueScorer` 唯一实现处；理由为「零 LLM 后台」铁律 + 不可复现判据×不可逆决策的结构性风险。
2. **对话块闭合规则配置化** —— 轮数软上限 80（与上下文窗口对齐）、闲置超时 30 分钟，
   全部落 `MemoryConfig.compaction.dialogGroup` 单一真源；闭合原因落库可追责。
3. **「闲置超时」语义修正** —— 由「组时长上限」改为「距上一条消息的间隔」，
   使三种会话场景（开着闲置 / 关窗短重开 / 关窗长离线）由同一阈值覆盖。
4. **锚点存储修正** —— 运行期锚点的 `seq_pos` 改由组内首轮派生，消除同轮数组的 UNIQUE 冲突
   （原实现导致同轮数组的锚点静默丢失）。
5. **块层衰减类别独立表达** —— `narative_tag` 承载 `BlockDecayClass`，与 `memories` 层
   `runDecay` 的关键词匹配解耦，避免口径混用。

## 五、📗 蓝皮书更新摘要

**《上下文注入》蓝皮书（标题：对话块检索与分层注入 · 规划项）**

1. 块层元数据（钙分 / 场景指纹 / 情绪曲线）已就位，P1-C 将据此把 `dialog_group` 接入
   `UnifiedSearchEngine` 检索单元 —— **本次未改动检索路径**。
2. 分层注入规范不变：原文块（保氛围）/ 摘要块（做索引）分离，注入单元按预算摘取。

**《会晤模式》蓝皮书（标题：对话组闭合规则）**

1. 闭合判据已从「10 轮硬封顶 + 30 分钟」改为「80 轮软上限 + 距上条消息 30 分钟闲置 +
   话题切换 + 退出会晤」，四者择一，且全部可配置。
2. 三种会话窗口场景不需要独立的「关窗」信号源 —— 关窗对服务端不可见，
   而消息间隔已完全表达该语义。
