## 一、现象与实据（S1 只读实测，`data/webui/fusion_memory.db`）

业主报告：与徐诗雨会晤时**多轮语义连贯性差** ——「刚还在说上电梯，多说几句就变成别的事了」「话题惯性弱」「聊着聊着忘了前面说的」。业主明确要求「从结构上去解决，不要凑合打补丁」。

定量（只读探针，脚本见 §七）：

| 事实 | 实测 |
|---|---|
| 记忆的最小单位 | **单条消息** —— `conversations` 6358 行 / `memories.mem_*` 5710 行，平均仅 184~246 字符 |
| 黑钻摘要 | 平均 **87 字符**（一句话） |
| `dialog_group` 的载体 | **没有独立表** —— 只是两张表上的一个 TEXT 字符串列 |
| 对话组平均轮数 | **2.4 轮**；1297 组中 747 组（**57.6%**）只有 1 轮；10 轮即硬封顶 |
| CHUNK 碎片存活 | 全库仅 **6 条**（推算应有 ~1615 条 → **99.6% 已销毁**） |
| 运行期锚点 : 重建锚点 | **4 : 1227** —— 99.7% 是「每行截 150 字符」的重建版 |
| 带场景描写比例 | `conversations` 原文 **79.2%** → `memories` 逐轮 **0.3%**（写库时正则剥除） |

## 二、根因

> **系统没有「对话块」这个存储单位，只有「单条消息」；块级元数据又没有载体。**

三条互相独立、但共同致死：

1. **`_rebuildMemoryAnchors()` 每次服务启动 DELETE 全部 `%_ANCHOR` / `%_CHUNK`**
   —— 只重建 ANCHOR、明说不重建 CHUNK（该函数注释自认「碎片每次重启被永久销毁」）。
2. **块级元数据无处可放** —— 挂锚点行会被上条清空；`dialog_group` 本身不是表。
3. **CHUNK 层是纯冗余** —— 调用链追踪实测（全仓 grep）它只有「写入」与「删除」，
   **读取方为零**；内容上单轮 Q+A 已在 `conversations`（原文）与 `mem_*`（逐条带 40D 向量）各存一份。

## 三、本次改动

### 3.1 `MigrationManager` 新增 v16 迁移 —— 建 `dialog_groups`

块级元数据的**唯一载体**（`block_calcium_score` / `scene_anchor_hash` / `emotion_curve` /
`block_close_reason` / `block_summary` / `lifecycle_state` / `is_landmark`），带 4 个索引。

- 单一真源声明：本表是块级元数据唯一真源；`conversations.dialog_group_id` 与
  `memories.dialog_group_id` 只是外键引用，**不得重复存块级元数据**。
- `belong_entity_uuid` 声明 **NOT NULL**（《UUID户籍管理法》第七条：无户口不得写入）。
- **刻意不含** `conversation_id`（组是 1:N，单数外键语义错误）与 `virtual_world_ts`
  （当前**无生产者** —— 全仓 grep `virtual_world` 0 命中，瑶光世界模型尚未接入，
  不预先建恒为 NULL 的字段）。

### 3.2 `SQLiteAdapter._rebuildMemoryAnchors()` —— 声明不触碰新表

- UPDATE DELETE 语句加注：`%_CHUNK%` 分支自本次起**只清残留**（生产者已退役），残留清空后可整条移除。
- 显式声明**本函数不得触碰 `dialog_groups`** —— 独立建表正是为了不被这条启动 DELETE 清空；
  日后若有人要让本函数「顺带重建 dialog_groups」，必须先读 ADR-010 §7（那是破坏性操作）。
- **ANCHOR 重建行为不变**（它有真实消费者：`MemoryRetriever` 的 `SELECT * FROM memories`）。

### 3.3 `dialog-group-stage.ts` —— 退役 CHUNK 写入

删除 `flushDialogGroup` 的 CHUNK 写入循环（原 `*_CHUNK_nnn`），留 tombstone 注释记录退役依据；
随之移除仅服务于它的 `computeCalcium` import。

### 3.4 新增「重启不变量」回归测试（本批的元教训）

ADR-010 查出的全部缺陷 —— 锚点被替换、碎片被销毁、隔离状态翻转 ——
**统统发生在「服务启动」这条路径上，而现有测试几乎不覆盖它**。
新增 `src/m2/__tests__/restart-invariant.test.ts`：真库驱动 `_rebuildMemoryAnchors()`，
锁 4 条不变量 + 2 条源码守卫（防 CHUNK 生产者与「重建器写 `dialog_groups`」被重新引入）。

## 四、📘 白皮书更新摘要

**《太虚境持久化与记忆分层》章节（标题：对话块记忆单元 · 三层记忆模型）**

1. **记忆基础单元由「单条消息」扩展为「对话块」** —— 新增 `dialog_groups` 表作为块级元数据唯一载体；
   原有的 `conversations`（原文）与 `memories`（派生）分工不变。
2. **三层记忆模型确立** —— 短期（`conversations` 滚动窗口）/ 中期（`dialog_groups` 块库，按价值衰减可归档）
   / 长期（`black_diamond` 只增不硬删）。
3. **「只增不删」的适用范围澄清** —— 约束的是「原始事实的可得性」，不是「每一层都必须保留副本」：
   `conversations` 原文永久保留（场景/氛围唯一存档）；派生行与检索索引可治理。
4. **存储层表结构变更** —— `dialog_groups`（v16 迁移），归属列 NOT NULL 强制；
   防抖 `save`/`flushNow` 机制不变（本次未触碰落盘路径）。
5. **CHUNK 碎片层退役** —— 该层无消费者且内容与 `conversations`/`mem_*` 双份重复。

## 五、📗 蓝皮书更新摘要

**《上下文注入》蓝皮书（标题：对话块检索与分层注入 · 规划项）**

1. 检索候选单元将从「单条消息」升级为「对话块」（`source_type='dialog_group'`），
   接入 `UnifiedSearchEngine` 的 SOURCE_TYPES —— **属 P1-C，本次未改动检索路径**。
2. 分层注入规范：**原文块（保氛围）** 与 **摘要块（做索引）** 分离；
   检索单元 = 块，**注入单元 = 预算内摘取**（禁止整块灌入，防 prompt 溢出）。
3. 块级隔离判据收敛到 `belong_entity_uuid`（ADR-010 D4），与 V35-A 同源。

**《会晤模式》蓝皮书（标题：对话组闭合规则 · 规划项）**

1. 闭合规则将从「满 10 轮硬封顶」改为配置化多条件（闲置 T1 / 短关窗 T2 / 话题突变 / 轮次软上限）
   —— **属 P1-B，本次未改动**；T1/T2 必须落进 `MemoryConfig.compaction` 单一真源。
2. 块价值判定用**确定性规则**（复用仓内已有的括号正则 / `dg.perceptions` / `FEATURE_ROUND_RE` /
   `_locusChanged` / 退化内容拦截），**禁止后台定时任务调用 LLM**（撞「Harness 零 LLM 监控」铁律）。
