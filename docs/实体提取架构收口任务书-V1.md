## 二、根因判断

### 2.1 结构缺陷（不是调参问题）

```
消息
 └─ M1 滑窗切片（2~3 字 × 姓氏表，无证据要求，输出量无上限）
     └─ entity_genes
         ├─ integrateFromEntity      → FG 节点 + 家族边
         ├─ dialog-group 闭组        → acquaintance_of 边
         ├─ RelationshipExtractor    → integrateSocialRelation
         ├─ InductionScheduler       → entities / entity_relations
         └─ post-process             → updatePersonProfile
     └─ 字面闸门（黑名单/尾字表）→ candidate 观察区 → 离线 LLM 终审
```

**核心矛盾**：判定环节需要的信息（这个人是否被文本引入），在生成环节就已经丢失。`阿珍一` 与 `阿珍依`、`全芬倒` 与 `王全芬` 仅靠 2~3 个字无法区分。因此：

- 字面闸门必然退化为黑名单军备竞赛；
- 观察区把判定推到异步批处理，LLM 看不到原句、也没有「是否被介绍」的信息，只能猜；
- 排空速度追不上生产速度 → 垃圾持续累积。

**结论：问题在生成器，不在闸门。只有换掉生成器才能根除。**

### 2.2 治理失败的教训（为什么修了这么多次还在）

历次修复都发生在**下游**：`GarbageEntityGuard`、`EntityWriteGate`、`NON_NAME_TAIL_CHARS`、`candidate` 晋升闸门、`EntityTriageService`。下游再严密，也只是在给一个**无证据生成器**做善后。本任务书要求把治理点上移，并**删除下游的补偿装置**，避免旧结构再次被「复用」。

## 五、目标架构

### 5.1 唯一准入契约

```ts
// 一次 LLM 调用，两个产物：提取 + 判定 + 举证
export interface AdmittedEntity {
  name: string;
  type: 'person' | 'place' | 'org' | 'object' | 'event' | 'emotion' | 'self';
  evidence: string;        // 必须在原文中精确出现
  relation?: string;       // 可选：与用户的显式关系词
}

// 代码侧强制校验（不可由 LLM 决定）
function verifyAdmission(raw: AdmittedEntity, message: string): boolean {
  if (!raw.name || !raw.evidence) return false;
  if (!message.includes(raw.evidence)) return false;   // 反幻觉
  return true;
}
```

### 5.2 数据流

**取证并入每轮已有的主回复调用**（不新增 LLM 请求，删除独立提取调用）：

```
消息
 ├─ 已登记人名精确匹配（确定性、只读）
 ├─ 主回复 LLM 调用（唯一一次）
 │    └─ 输出：entity: 名称|类型|证据原文 … / --- / 正文
 │         └─ HeaderGate：剥离头块 → 正文流式转发 / TTS
 │              └─ verifyAdmission()：message.includes(evidence) 硬校验
 ├─ admitted: true  → entity_genes → 允许的一切写入（回复后）
 ├─ admitted: false → 丢弃（不写 entity_genes、不写 FG、不写 entities）
 └─ LLM 不可用 / 协议缺失 → 确定性降级：hasExplicitPersonIntro（已实现）
```

**净效果**：每轮少一次 LLM 调用（当前 `extractEntitiesLLM`），token 与首字延迟均下降。

### 5.3 不变量

1. `entity_genes` **只含 admitted 实体**；
2. 任何写 FG / `entities` / `entity_relations` 的路径，输入必须是 `admitted`；
3. 不存在「先写入、后判定」的池子（无 candidate、无观察区）；
4. 识别（read-only 匹配已登记名）与建档（write）彻底分离；
5. **emotion / event 不是准入实体** —— 只写 `entity_genes` 与记忆标注（供检索/感知/情感轨迹），永不触发 `addNode` 或 `entities` 新建；证据校验失败只丢标注，不影响回复。
