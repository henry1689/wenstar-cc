## 二、目标架构

```
                     ┌────────────────────────────────────────────┐
                     │      记忆表达法（单一法源 MEMORY-LAW-V1）     │
                     │ 三档 · 自信回忆 · 主动义务 · 三重奏 · 憧憬自由 │
                     └──────────────────┬─────────────────────────┘
                                        │ 所有 prompt 只从此处取文本
┌──────────────────────┐   ┌────────────▼─────────────────────────┐
│ 写入总线              │   │          召回总线（唯一入口）          │
│ conversations（原始） │   │ mode: casual / standard / deep / proactive │
│ memories（语义块）    │──▶│ 各路并行 → 层保底 → 单一闸门 → 配额    │
│ black_diamond（长期） │   │ → 要素集打包 → 整编（回味→叠加→憧憬） │
│ 证据层（知识/档案/作品/记事）│                                     │
└──────────────────────┘   └────────────┬─────────────────────────┘
                                        │
                       唯一反馈点：recall_count / 钙分 / 元素权重
```

三条铁律：

1. **UUID 是唯一隔离通道**；DNA/40D 只做聚类与语义，不做隔离；禁止按正文内容做召回闸门。
2. **写入一次、派生另算**；同一语义单元不得因多路径写多份。
3. **表达法单一源**；任何提示词/守卫/过滤器不得以"反编造"之名压制记忆表达。

## 四、归属与编码契约

### 4.1 三态归属（唯一策略）

```
OwnershipPolicy
├─ owned(uuid)        白名单内可见
├─ shared             仅 knowledge_base / 公共档案域；全体可见
└─ unregistered(NULL) 私有域：仅户主钥匙；会晤态拒绝
```

- `policyFor(domain, visibleUuids, { ownerMode })` 是**唯一**产出处；
- 删除 `allowUnowned` 双轨（或降为只读派生），`buildSqlClause` / `passes` 只从 policy 推导；
- 私有域新写入无归属 → **拒绝写入 + 健康报告**（不得静默 NULL）；
- 知识库新写入默认 `shared`；需要私有则显式 `belong_entity_uuid` 或 `visible_entity_uuids`；
- 所有查询/注入/适配器禁止手写 UUID SQL。

### 4.2 语义块强制字段（`memories` 私有域）

| 字段 | 要求 | 缺失处置 |
|---|---|---|
| `belong_entity_uuid` | 必填（FG 存在性校验） | 拒绝写入 |
| `global_uid` | 必填 | 从 source/dna 派生，否则拒绝 |
| `dna_root_id` | 必填 | 从 source/dialog_group 派生，否则拒绝 |
| `perception_40d` | 必填（M3 原生 40D） | 标 `encoding_incomplete`，语义路跳过（不填 0、不投影） |
| `entity_genes` | 必填（roleplay 豁免） | 拒绝写入 |
| `source_conversation_ids` 或 `dialog_group_id` | 至少一个 | 拒绝写入 |
| `namespace` / `seq_pos` / `calcium_score` / `calcium_level` / `lifecycle_state` | 必填 | 默认值必须来自配置 |

### 4.3 编码职责（不得混用）

| 编码 | 职责 |
|---|---|
| `belong_entity_uuid` | 隔离/归属（唯一硬闸门） |
| `global_uid` / `dna_root_id` | 聚类、去重、溯源（同根一簇一票） |
| `perception_40d` | 语义相似度（唯一合法 `cosineSimilarity40D`） |
| `entity_genes` | 实体要素（标签/图谱/要素集） |
| `source_conversation_ids` / `dialog_group_id` | 溯源锚点 |
| `namespace` | 物理分区 |

### 4.4 前后一致性验收

- **Round-trip 测试**：写入一条完整编码语义块 → UUID 路 / DNA 路 / 40D 路 / 关键词路四路都能召回；
- **完整性看板**：按表统计归属/40D/DNA/global_uid 缺失率，目标 0；
- **隔离探针**：会晤/玉瑶各一组，跨实体命中 = 0。

## 五、表达法（MEMORY-LAW-V1）

新建 `src/m5/prompts/memory-expression-law.ts`，唯一导出：

1. 三档：【记得】原文锚点，可口语化复述；【印象】要素集内重组 + 轻标记；【线索】邀对方给由头；
2. 自信回忆：记忆里有的直接讲，不等用户确认；
3. 主动义务：节日/情绪/日常/话题关联时主动调用回忆与元素；
4. 深度应答：用户刻意铺垫往事时全面回忆、最大限度合法发挥；禁止"对不上号式回避"；
5. 三重奏：回味 → 叠加 → 憧憬；
6. 憧憬自由：未来想象不受要素集约束；
7. 守卫禁令：任何 prompt/守卫/过滤器不得以反编造之名压制表达。
