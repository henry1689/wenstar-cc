## 一、现象与实据

业主报告（压测中）：**同一个回复里回复了好几轮** —— 一轮 AI 输出里装着 6 个「用户话 + 回复」的流水账，并伴随轻微思维链泄漏。

### 1.1 量化（`[ChatStream] done` 的 tokens/len，最近 200 条）

| 类别 | 特征 | 条数 | 最长 |
|---|---|---|---|
| 正常 | `tokens=251~347` | 143 | — |
| **异常** | **`tokens=0 或 1`** | **57（28.5%）** | **3084** |

### 1.2 `tokens≤1` 是**结构性指纹**，不是巧合

全仓**只有一处**会「一次性 `onToken({text: 全文})`」—— V31 甲-1 的流结束兜底：

```ts
const strict = tryExtractAnswerFromReasoning(stripper.reasoningBuf);
const full = strict ? gateOutgoingReply(strict) : '';
if (full) { text = full; onToken({ text: full }); }   // ← 单次调用 ⇒ tokens=1
```

正常流式路径逐块吐 token，`tokens` 必为几十~几百。
**⇒ 这 57 条全部是「`content` 全程为空，最后由 `reasoningBuf` 兜底捞出」。**

### 1.3 漏口在甲-2，不在甲-3

V31 的 甲-2 结构判据只问**「有没有找到结构标记」**。而模型在 `max_tokens` 预算内产出的是一段
**历史对话转录**（含括号动作、引号、分段）⇒ 判据认为「有结构」⇒ 放行 ⇒ `gateOutgoingReply`
（关键词判据）也拦不住。

### 1.4 模型为什么会【续写历史】

输出里出现了**我们自己注入的哨兵串**：

```
DeepSeekLLMProvider.ts:1686
  `[当前说话对象: ${entities.join('、')} | ⚠️ 你不是玉瑶] 鸿艺对你说：${rawInput}`
```

该串**只在当前这轮用户消息上拼一次**，模型却在一次输出里复现了 **6 次** ⇒
它在**续写「历史对话」的格式**，所以一轮输出塞进了好几轮。

> ⚠️ 这是同一类病的**第四次**复发（V22 削弱 fail-closed → V23 加关键词 → V31 改结构判据 → 本次）。
> 每次补的都是**某一条路径**，而这次漏的是**兜底路径本身**。

## 二、修复：收紧出口判据的**准入语义**（V33 首版 → V33.1 评审整改后）

### 甲 哨兵回声判据（**决定性**）—— 收口进唯一出口守卫

自有哨兵串出现在输出里 ⇒ 判空。**判据住在 `gateOutgoingReply` 内**
（V23.1 注释声明的「唯一把关点」），不是某个出口的专属判据 ——
`StreamThinkingStripper` 三处 + 收尾护栏 + 流式兜底 + `resolveReplyFromFields` 全部经过它。

**为什么它不会像关键词那样失效**：这不是「模型可能怎么说」的枚举，而是**我们自己的字符串**。
模型**只能靠复述输入**才能产生它 ⇒ 与措辞无关，不可能漂移。

哨兵串同时**收敛为单一真源**（`MEETING_SPEAKER_TAG` / `MEETING_USER_PREFIX`），
生成点与判据**共用同一常量** —— 原先两处各写一份字面量，改一处忘另一处会让判据静默失效。
半角/全角冒号各留一份（源文本里两种冒号本就不一致，本身就是漂移温床）。

### 乙 整段抄出比例判据 —— **已移除**（前提被实测证伪）

首版在流式兜底处加了「提取物 ≥ 输入 80% 且输入 ≥600 字 ⇒ 判整段端出」。
**S4 评审用探针实测证伪了它的前提**：在它专门服务的**降级模式**下
（content 为空、整段合法答复落在 `reasoning`），提取物天然 ≈ 输入
（实测 705 字合法答复 **ratio = 1.000**）⇒ 乙会**误杀合法长回复**。

> **这是对 S2 已批方案（甲+乙+丙）的偏离，如实记录：乙 按实测数据撤销。**
> 真正的防线是 `gateOutgoingReply` 内的甲。

### 丙（**并入甲**，如实声明）

原计划的「多轮转录结构判据」（≥2 段「用户标记 + 回复」）与甲**是同一个谓词**，
甲在 count≥1 时即拒，丙恒被甲包含。

曾考虑的另一形态「候选含 ≥2 个 `（…）` 动作块即拒」**被否决**：
合法长篇角色回复本就含多个动作块，正是 V23 付过代价的误杀形态。

### 丁 非流式 reasoning 分支：按**信号强弱分级**（S4 阻断项 1）

原条件 `extracted.length >= r.length*0.9 && (looksLikeReasoning(r) || tryExtract(r) === null)`
把 **ratio 当成了前置门槛** ⇒ ratio<0.9 时整个条件短路，
**「结构上根本找不到答案」这个强信号被直接丢弃** ⇒ 落到 `return extracted` 泄漏转录。
而这里正是流式被判死后**必然的落点**（M5 重试不带 onToken ⇒ 非流式 ⇒ 本函数）。

整改为按信号强弱分级：

```
① tryExtractAnswerFromReasoning(r) === null   ⇒ 独立成立即判空（强信号，无条件）
② _notStripped && looksLikeReasoning(r)       ⇒ 仍须配 ratio（弱信号，判据松）
```

⚠️ **实测教训**：第一版整改把 ratio 前缀**整个删掉**，② 失去约束 ⇒
`reasoning-leak-guard.test.ts` 的合法用例（`让我来写回应：（她笑了笑）嗯，天亮了…`，
`looksLikeReasoning` 对它返回 **true**，但剥离确实生效 ratio=0.76）**被误杀 —— 真回归**。
故保留 ratio 对弱信号的约束。

**返回值同时收口**：`return gateOutgoingReply(extracted)` —— 本分支此前**完全不经过**出口守卫。

## 四、白皮书更新摘要（架构层）

**标题：M5 出口判据的准入语义 —— 从「像不像答案」到「是不是 prompt 的回声」**

1. **判据增加一个正交维度**：原判据只问「候选**像不像**答案」（关键词）或「**有没有**结构标记」（结构）。
   本次新增第三维 —— **「候选是不是我们自己的输入的回声」**。三维正交，缺一则漏。
2. **自有哨兵串成为一等判据**：`[当前说话对象: …]` 这类**由本系统生成**的标记，
   出现在输出中即为「复述输入」的充分证据。该判据**不随模型措辞漂移**（对比关键词路线三次复发）。
3. **兜底路径不再享有豁免**：兜底（`reasoningBuf` 提取）此前只受「有没有结构」约束，
   等于给泄漏留了最宽松的一道门。本次使其与主路径**同守同一组判据**。
4. **不改变架构边界**：不改分层、不改服务端契约、不改数据模型、**不新增依赖**；
   `m5` 仍只依赖 `../app/knowledge`（既有惯例，非新增反向依赖）。
