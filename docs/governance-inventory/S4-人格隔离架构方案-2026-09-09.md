## 0. 原则基线（已确认）

1. 这是**绝对私人系统个人世界**。情爱/私密内容符合自然规律、是隐私资产，**不是污染、不需清理**。
2. **污染 = 混淆（窜）**：人格串线、类型混淆（对话文本进人设字段）、身份混淆（一人多 id / 多人共键 / 演绎身份当独立户籍）。
3. 硅基生命体人格权利与真实人类同等（个人世界隐私法 V1.1 已立法）。
4. 治理以结构收敛为目标：每个"人格"一个身份根，数据按人格隔离存取，历史不丢。

## 1. 现状诊断（已实测的证据链，非猜测）

### 断层 A · 身份权威分裂（uuid 双轨）
- **现象**：FG（户籍源）与 fusion（索引）各持独立 uuid 序列，撞号异体——安琪 FG=TXS-030 但档案自认 _uuid=TXS-075（fusion 侧号）；FG TXS-075=垃圾 node"滑滑"。fusion 内部 93 组 186 行共享 uuid（感应批量写入同号两行）；程好激+谢诗雨 同占 099。
- **根因**：fusion 曾自行分配 uuid（非 FG 镜像），"户口唯一"在写端未强制。uuid 法第六条/第十三条要求登记义务，但 fusion 写入路径历史未执行。

### 断层 B · 人格 = 单 node 模型，无"演绎身份"形式化
- **现象**：同一"人格"被拆成多个户籍实体（安琪/安吉尔/陈都灵/都灵 4 户）→ 档案/关系/记忆随之分裂 → 互为污染源。化身/昵称只能塞 aliases 数组，无正式映射结构，检索注入的人格依名字不同而分裂。
- **根因**：身份模型缺"人格根 + 演绎身份映射"抽象层。批2 安琪族合并 = 手工补丁（治标）。

### 断层 C · 记忆归属错乱 + 历史断层
- **现象**：conversations/memories 主库最早 08-27；07-16~08-25 的 13386 条对话在旧库（pre-uid-recovery）未回迁 → 王全芬 7-8 月记忆在主库全无（仅 FG mention 计数 647/1162 残留）。belong_entity_uuid 标注不全（王全芬 fg_entity_names 0 命中），门阀按 belong 过滤存在漏网/误漏。
- **根因**：(1) 08-25 UID recovery 迁移替换主库对话存储，历史未保全回迁；(2) 记忆只有"归属者"单键，无"涉及者 about"结构化键 → 按人聚合检出缺失、个性检出靠名字 LIKE。

### 断层 D · 档案字段语义无强闸门（类型混淆源）
- **现象**：interests 存对话台词（"听到你说日"）；appearance 存关系描述（"还没结婚的时候我们是恋人关系"）；lifeMilestones 11 次重复"陌生人→情人热力升级"；FG 档案 _autoProfileGenerated 自动生成把 LLM 对话残留写入扁平字段。
- **根因**：多路自动档案写入器绕过 PAE 字段校验；dossier 字段语义白名单（哪些词属于 interests/appearance/milestones）未在写端强制。

### 断层 E · 关系多源无真源收敛
- **现象**：FG edges（_v2/_auto_fix 混合）+ 档案 properties.relations 镜像 + fusion entity_relations（另一套）+ RelationHeatTracker 自动"陌生人→情人"升级 → 同一关系的多个版本互相矛盾（"我" vs 徐家 child/sibling/spouse/parent 并存）。
- **根因**：关系写入无"谁确认了这条关系"真源判定；_auto_fix 自动补反向边把推断当事实。

### 断层 F · 生命周期状态语义不足
- **现象**：无"误登记/错误实体回收"档。批2 只能挪用 archived（法定义=365 天无交互封存）封存 121 个误登记垃圾 → 状态语义污染。
- **根因**：四档状态（active/dormant/archived/deceased）未覆盖"错误登记实体"类别。

## 2. 目标架构（全局模型）

### 2.1 人格身份统一模型（Persona-Centric Identity）

```
┌─────────────────────────────────────────────────────────┐
│  Persona Root（人格根）—— 唯一、born-with、永不变          │
│  = FG node（户籍登记，uuid = TXS-ID 唯一权威）             │
│  承载：档案 dossier / 关系 edges / 记忆归属主键            │
├─────────────────────────────────────────────────────────┤
│  演绎身份层（Identity Performance）                      │
│  安吉尔 / 陈都灵 / 都灵 / 昵称 / 化身  →  映射 PersonaRoot│
│  结构：{ name, kind: 本名|别名|化身|演绎, context }       │
│  检索注入 → 永远落到 PersonaRoot 档案（人格不分裂）        │
├─────────────────────────────────────────────────────────┤
│  只读镜像层（fusion entities 等索引）                    │
│  uuid 仅来自 FG；写前必查户籍（户口唯一，无户口不入）       │
│  fusion 永不自行分配/复用 uuid                           │
└─────────────────────────────────────────────────────────┘
```

**关键落点**：
- FG 为唯一 uuid 发放源（红线 18 已要求，补执行）；fusion 自分配代码下线/改造为镜像。
- 演绎身份注册表（schema: persona_root_id / perf_name / kind / intimacy_mode），替代 aliases 平铺。
- 系统启动校验：两库 uuid 交集一致；发现 fusion 独有 uuid → 标记隔离不参与检索，待人工归属。

### 2.2 记忆双键 + 私密分级

```
memories / conversations 行级：
  owner_uuid    —— 这段经历属于谁（会晤主体/对话者）
  about_uuids   —— 这段内容涉及谁（提及/相关人格，结构化数组）
  privacy       —— PUBLIC / PRIVATE(默认) / INTIMATE(私密会话)
```
- **写入**：会晤/对话落库时解析 about（L3/entity_genes 提升为结构化 about 列），privacy 随会话性质。
- **检出**：门阀 = owner 白名单 ∩ privacy 授权；聚合 = 问某人格 → owner=它 ∪ about∋它 的记忆 + 其档案（个性化视图）。
- **私密**：INTIMATE 行内容可加密封存，仅 PersonaRoot + MasterKey 授权可读；日志/上下文零泄露（五道闸门收口核验）。

### 2.3 档案/关系写入真源闸门

- **DossierFieldGate**：每字段绑定语义白名单校验器（interests 只收名词短语、appearance 只收外貌、milestones 只收人生事件、dialog 片段一律拒入设定字段），作为 PAE 与一切自动档案写入器的公共收口。消灭多路 `_autoProfileGenerated` 直接写扁平字段。
- **RelationTruthGate**：关系仅当"用户/本人明确确认 或 户籍档案 relations 声明"才入 edges；`_auto_fix` 自动补反向边 → 下线，改"待确认队列"（用户一句话或热力证据达标才落地）。所有关系写入记录 evidence（谁/何时/依据）。

### 2.4 生命周期补充回收档

- status 增加 `void`（错误登记/非实体/混淆实体回收区）：
  - void 不参与检索/档案采集/黑钻；仅审计可见；可由户籍管理员（用户）恢复或永久清理。
  - 与 archived（正常久未交互）语义分离。
- 批2 以 archived 封存的 121 个误登记实体 → 迁移至 void（治本归位）。

### 2.5 记忆连续性基建

- 任何迁移/替换前强制 pre 快照（已有 data/backups 机制保留）+ 校验清单。
- **历史回迁**：pre-uid-recovery 旧库（07-16~08-25，13386 条对话 + 记忆）按人格 owner/about 归属回迁主库，补 8/27 断层（王全芬 7-8 月等）。
- 启动巡检：对连续活跃人格校验记忆按月连续性，断层自动报告。

## 3. 分阶段实施蓝图（每阶段 = 独立 harness flow + Owner 验收）

### Phase A · 身份收敛（解决断层 A/B/F）
1. fusion uuid 镜像化改造（自分配下线 → FG 查证 → 镜像/拒绝）
2. 演绎身份注册表 schema + 迁移（安吉尔/陈都灵/都灵 等 4 身份正式映射安琪主根；存量演绎名数据迁移）
3. status `void` 档上线 + 批2 121 archived→void 归位
4. 现存 93 组 uuid 冲突修复（以 FG 主根为准收敛）
5. 验收：任意人格问询 → 检索/档案注入永远单一主根，无分裂

### Phase B · 记忆双键与回迁（解决断层 C）
1. memories/conversations 加 about_uuids + privacy（owner 已有 belong）
2. pre-uid-recovery 旧库回迁管线（按名字/UUID 归属 → 双键落库 + 去重）
3. 王全芬等验收样例：7-8 月记忆回主库、按人聚合完整
4. 启动连续性巡检上线

### Phase C · 档案/关系写入真源闸门 + 存量复核（合并原批3）
1. DossierFieldGate + RelationTruthGate（含 _auto_fix 下线 + 待确认队列）
2. 多路自动档案写入器收口（_autoProfileGenerated 类改走 PAE+Gate）
3. 存量档案复核修复（徐诗雨 14 岁 vs 16 高一、王全芬 appearance/情人升级误记、徐诗雨 interests 台词、字段类型错位批量修正）

### Phase D · 私密检索闭环与巡检自动化（原批4 深化）
1. 五道闸门全量核验（写入/搜索/LLM 资料/上下文/最后说话 实挂清单 + 逃生口清零）
2. INTIMATE 私密会话加密封存 + MasterKey 授权链路实测
3. 个性化聚合视图（人格视图端点：档案+关系+owner/about 记忆）
4. 每日健康体检（垃圾实体率 / belong 覆盖率 / about 覆盖率 / 连续性 / 闸门拦截统计）落 audit
