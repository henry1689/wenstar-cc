## 一、现状诊断（已完成，2026-10-06）

### 1.1 两个根因级缺陷

#### 根因A：钙化机制名存实亡

| 指标 | 实测值 | 问题 |
|---|---|---|
| memories 钙化分 avg | **0.407**（满分10） | 95.8%记忆钙化分<1，晋升门槛6.5仅35条达标 |
| 钙化分分布 | 0-0.99: 9186条(95.8%) | 几乎全部记忆在最低分区间 |
| 全零向量 | 1,538条(16%) | 其中ANCHOR锚点行1318条(86%) |
| 零召回记忆 | 7,341条(76.5%) | 绝大多数记忆从未被检索命中 |
| auto_induct产出 | **8条** | 自动事实归纳链路几乎空转 |
| 黑钻库分布 | 徐诗雨1087条(50%) | 晋升标准偏向对话密度而非事件权重 |

**钙化死亡螺旋**：低钙化→检索排序低→不被召回→recall_count不增长→无法靠recall_count≥3晋升→永远低钙化。

#### 根因B：UUID校验多路径逃逸

| 逃逸点 | 数量 | null率 |
|---|---|---|
| memories无UUID | 166条 | 持续产生至2026-10-06（不是历史遗留） |
| vault_log landmark | 327/3212 | 10.2% |
| vault_log promote_sand | 139/139 | **100%** |
| vault_log auto_promote | 5/5 | **100%** |
| search_index有UUID | 586,851/1,457,913 | 仅40.3% |
| knowledge_base有UUID | 5/1058 | 仅0.47% |

**核心问题**：persistence-stage 直接调 `sqlite.writeMemory()` 绕过 MemoryWriteGateway，写入前无过滤、无UUID强制校验。

### 1.2 九个结构性问题（Claude Code扫描确认）

1. 🔴 会晤路径无统一名额分配器，十几条通道先到先得
2. 🔴 两套融合标准不一致（Foundation有7天线性衰减，会晤槽无时间因子）
3. 🔴 过滤只有"剔除坏的"，缺少"保证话题/时间段覆盖"
4. 🔴 金库auto_induct链路几乎空转（仅8条）
5. 🟡 黑钻库分布极度倾斜（50%集中在徐诗雨）
6. 🟡 memory_kind='roleplay'误判泛滥（38%）
7. 🟡 candidate状态大量停滞（3433条，36%）
8. 🟡 历史槽被29-40天前高钙地标永久霸占
9. 🟢 生产残留临时探针（MEMPROBE/console.error）

### 1.3 B链路现状

**不存在独立B链路**。conversations表（6623条）是裸原文存储，具备只增不减和原始留存，但缺少：EventState_40D冻结向量、Wiki多层摘要、AppendLog追加日志、内容哈希防篡改、EventUUID单点读取API、禁止全局检索的闸门。

## 二、目标架构（ADR-0012 待写）

### 2.1 双链路模型

```
┌─────────────────────────────────────────────────────────┐
│                    用户输入                              │
└──────────────────────┬──────────────────────────────────┘
                       │
                       ▼
┌─────────────────────────────────────────────────────────┐
│  即时记忆（上下文蓄水池，会话结束丢弃）                    │
│  10/20/30/80/100轮对话块                                 │
└──────────────────────┬──────────────────────────────────┘
                       │ 记忆网关评估
                       ▼
┌──────────────────────────────────┐  ┌──────────────────────┐
│  A链路：钙化心智记忆链路           │  │  B链路：沉睡真值卷宗链路 │
│  （模拟人脑选择性沉淀）            │  │  （利用计算机存储优势）  │
│                                  │  │                      │
│  砂金库 → 金库 → 黑钻库           │  │  Wiki结构化卷宗        │
│  索引+摘要+动态RecallState_40D   │  │  原始素材+冻结EventState│
│  EventUUID指针                   │  │  多层摘要+AppendLog    │
│  开放检索+钙化晋升                │  │  只增不减+只读冻结      │
│  控制注意力噪声                   │  │  仅EventUUID单点读取    │
└──────────────────────────────────┘  └──────────────────────┘
                       │                          ▲
                       └──────── EventUUID双向锚点 ┘
                                  （A检索命中→B单点唤醒）
```

### 2.2 核心原则

1. **A链路负责思考**：选择性记忆、钙化沉淀、召回权重、注意力调度
2. **B链路负责保真**：完整原始存档、只增不减、按需唤醒、高保真回放
3. **两条链路共享**：统一40D向量空间、SubjectUUID人格隔离、EventUUID双向锚点
4. **B链路禁止**：全局批量检索、向量检索、修改原始快照
5. **钙化公式**：`Score = αF + βS₄₀ᴰ + γT + δC`（F=召回次数, S=向量得分, T=时间衰减, C=B链路消费次数）

### 2.3 法典优先级

```
最高：生效版法典/专项规范（系统必须遵守）
  ↓
第二：ADR工程决策（解释设计意图）
  ↓
第三：代码实现（必须对齐法典，不一致=bug）
  ↓
最低：改错/迭代记录（仅历史备查）
```

- 检索第一步过滤非本主体UUID，杜绝跨户籍串扰
- 不同户籍主体B卷宗物理/逻辑隔离

#### 3.4 新增《记忆系统运维审计规范》

- 所有记忆操作写入不可删除审计卷宗
- Bug修复记录≠行为规范，仅历史备查
- 法典修订流程：提案→关联ADR→评审→版本升级→代码对齐→合规巡检
- 法典与代码冲突处理流程：代码不符合=缺陷修复；法典落后=启动修订

#### 3.5 ADR-0012编写

- 标题：《WenStarOS 记忆五层模型：即时记忆/砂金库/金库/黑钻库 与独立沉睡Wiki卷宗库》
- 内容：双链路架构决策、钙化公式、B链路读写约束、EventUUID锚点设计、迁移策略
- 时机：Phase 1启动前完成初稿，Phase 2完成后定稿

## 八、重要铁律（执行全过程必须遵守）

1. **归属是结构事实，只能从写入路径拿，不能从正文猜**——禁止按角色名推断UUID
2. **只增不减是存储层不变量，不是检索池约束**——原始卷宗永不删除，检索激活可分层调度
3. **回放渲染文本绝不回写原始卷宗**——事实回放允许叙事重组，但原始档案禁止改写
4. **钙化是候选入场券，不是唯一排序键**——高钙化不能永久碾压近期记忆
5. **B链路只允许EventUUID单点读取**——禁止全局批量检索、禁止向量检索
6. **所有数据改动必须在停服窗口内**——sql.js会整库覆盖，不停服改了白改
7. **法典>ADR>代码>改错记录**——代码与法典冲突=缺陷，必须修复或修订法典
8. **会晤路由指令不进入钙化记忆链路**——只写conversations原始留存，不写memories
