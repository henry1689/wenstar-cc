# MemArch v2 数据交接判定清单（2026-11-05 实测）

> 目的：为「旧链路彻底清除 + 数据完美交接」提供逐表判定依据。
> 数据来源：`data/webui/fusion_memory.db`（主库，128 MB，46 张表）与 `data/memarch-v2.db`（v2 库，82.9 MB，17 张业务表）实测行数。
> **状态：判定待业主确认，未执行任何删除。**

---

## 〇、先纠正一个口径

此前台账写「21 张表一张未迁」，容易被读成「v2 缺表」。**实测不是这样**：

- v2 库业务表共 **17 张**：`audit_ledger` `black_diamond_v2` `conversations` `entity_edges` `episodes` `forget_requests` `memories` `migration_checkpoint` `namespace_registry` `prospective_items` `reinforcement_events` `schema_migrations` `semantic_facts` `sleep_runs` `tombstones` `trace_entities` `wm_buffer`
- 逐一比对设计方案 §二「数据模型」的 CREATE TABLE 定义（episodes / semantic_facts / entity_edges / trace_entities / black_diamond_v2 / prospective_items / tombstones / forget_requests / audit_ledger / sleep_runs / reinforcement_events，加上 conversations / memories 改造、namespace_registry、wm_buffer、两张迁移元表）——**数量与名称完全一致**。

所以正确说法是：**v2 的表结构是完整的；缺的是旧库 21 张表里的数据向这 17 张表的转换迁移。**

## 六、执行顺序建议（不停服做完前两步）

1. **只读核对**：逐表比对字段，产出「旧列 → v2 列」映射表（读主库，零风险）
2. **影子迁移**：迁到 v2 库的**副本**，跑一致性校验（行数 + 抽样字段 + 实体边连通性）
3. **停服窗口**：确认无误后再迁正式库，并同步重启服务（此时标签修复也一并生效）
