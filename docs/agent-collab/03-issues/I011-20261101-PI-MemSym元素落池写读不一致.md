# I011 · MemSym 元素落池写读不一致（M7 extractMemSymElements）

- **发现**: 2026-11-01 MemSym-v1.0.0 全面验证（PI）
- **状态**: ✅ **已根治（2026-11-01，结构性修复 `8ba7dfb`）**
- **根因（代码级实证）**: `KnowledgeEngine.add` 的 FTS 去重命中即**静默 UPDATE 旧条目并 return 成功**（不插新行不抛错）——元素内容为真实记忆文本必然撞中 → 落池申报N/插入0。
- **结构解（非补丁）**: 要素独立成池——`memsym_elements` 专表（MigrationManager v30），软遗忘/钙化/归属/溯源字段自治；element-picker/M7萃取/boost 全部改读写专表，与文档管道（去重/cabinet/隐私守卫）彻底解耦。
- **全链实证**: ①落池申报=29 专表实证=29（写后自验）②落盘29条按户口分池（TXS-007诗雨18/0089/0032，跨实体隔离成立）③`[MemSym·元素拾取] TXS-000000007 → 3 条` B路首次真实拾取+注入；诗雨回应温暖贴合无人工忆旧痕迹。
- **结论**: MemSym「越来越懂」闭环（M7萃取→专表沉淀→B路拾取→浸润注入→B钙化增强）首次完整转动。
- **现象**: M7 元素萃取 `kb.add` 申报成功 13 条，但**同实例同进程**回查 `source_type='memsym_element'` = 0；落盘（data/webui/fusion_memory.db flush 后）= 0。写后自验日志永久可观测：`[MemSym·元素萃取] 落池申报=N 库内实证=0`
