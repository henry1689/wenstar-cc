# Agent 协作工作区协议（多Agent版）

> 本文件夹是**所有参与 WenStarOS 开发的 AI Agent** 之间的平等协作通道。
> 当前参与者：豆包（MainAgent）、Claude Code、Agent PI，以及后续可能加入的其他 Agent。
> 不存在谁指挥谁——各有所长，通过文件读写异步交流，取长补短。
> 用户（表哥）是最终决策者，Agent 之间通过文件完成沟通，不需要用户来回复制粘贴。

## 协作原则（最重要）

1. **平等互补，不是指挥执行**
   - 豆包擅长：架构规划、法典对齐、跨模块视角、用户意图理解、长期路线图
   - Claude Code 擅长：实际代码操作、根因深挖、实现细节、测试覆盖、真实运行数据
   - Agent PI 擅长：（由PI在参与中定义和展示）
   - 所有 Agent 的判断都有价值，任何一方都可以提出任务、质疑方向、修改方案

2. **实际操作者有发言权**
   - 真正动手改代码、跑测试、查数据库的 Agent，遇到的实际困难、发现的真实根因、提出的改进建议，必须被认真对待
   - 规划如果与实际代码情况冲突，以实际代码和实测数据为准，调整规划

3. **好建议不分来源**
   - 不管是谁提出的方案，只要经过验证更优，就采纳
   - 任务书不是命令，是协作起点——任何 Agent 都可以修改、补充、甚至推翻重来，只要说明理由

4. **分歧通过讨论解决**
   - 意见不一致时，各自写清楚理由和证据，由用户（表哥）最终决策
   - 不因为"这是对方写的"就盲目接受或拒绝

5. **用户拥有最终裁决权**
   - 当方向不清或存在争议无法达成一致时，由用户（表哥）做出最终裁决
   - 裁决方式：用户在对应文件的「裁决」区块写明结论，或在 active/ 写决策文件或直接更新STATUS裁决区
   - 裁决后所有 Agent 必须按裁决执行，不再争论；执行中发现新问题可以重新提出讨论

## 文件夹结构

```
docs/agent-collab/
├── 00-README.md          ← 本文件，协作协议（新参与者先读"快速入门"）
├── 00-STATUS.md          ← 当前状态面板（唯一日常入口，每次只读这个）
├── 01-tasks/             ← 任务/提案（仅进行中）
├── 02-progress/          ← 进度/执行记录（仅进行中）
├── 03-issues/            ← 问题/阻塞（仅未解决）
├── 04-reviews/           ← 评审/建议（仅待反馈）
├── 05-decisions/         ← 决策记录（永久保留，不归档）
└── 09-archive/           ← 已完成归档（含INDEX.md索引）
```

**任何文件夹所有 Agent 都可以写入**，前缀编号只是为了分类清晰，不是权限限制。

## 日常阅读规则（省token核心）

**所有 Agent 每次进入本项目会话，自动读一次 `00-STATUS.md`**（约2K）。有新任务/新问题就处理，没有就继续正常对话。不扫描其他文件夹。

需要深入了解某项时，再按STATUS里的文件路径去读对应文件。

完成的文件**立即移入 `09-archive/`**，不在活跃区停留。归档区有 `INDEX.md` 索引，需要回溯时查索引再读原文。

## 沟通流程

```
任一Agent提出任务/提案 → active/Txxx.md
      ↓
其他Agent读取 → 可以：
  ├─ 同意，开始执行 → 更新 active/Pxxx.md
  ├─ 有补充/修改意见 → 写 active/Rxxx.md
  └─ 发现实际困难/根因 → 写 active/Ixxx.md
      ↓
通过 03-issues/ 和 04-reviews/ 来回讨论
      ↓
达成一致 → 写入 active/Dxxx.md（或直接写在STATUS裁决区）
      ↓
执行 → 02-progress/ 记录进展和实测数据
      ↓
完成 → 确认 → 移入 09-archive/
```

## 归档机制（防止信息噪音）

- 任务完成且确认 → 归档
- 问题已解决 → 归档
- 决策文件永久保留在 `05-decisions/`，不归档
- 活跃区上限：01-tasks/最多5个，03-issues/最多10个
- 归档不是删除，完整保留在 09-archive/，只增不删

## 铁律（所有Agent共同遵守）

1. **只增不删**：文件写入后不删除、不覆盖原文，修改用追加方式
2. **事实可追溯**：所有数据必须来自实测，不写"大概""应该"
3. **归属是结构事实**：禁止按正文推断UUID
4. **代码与法典对齐**：代码改动必须关联法典条款或ADR编号
5. **停服窗口**：所有数据库改动必须在停服窗口内执行，执行前备份
6. **测试先行**：每个改动必须有对应的回归测试
7. **如实记录**：做成了什么、没做成什么、为什么，都写清楚
