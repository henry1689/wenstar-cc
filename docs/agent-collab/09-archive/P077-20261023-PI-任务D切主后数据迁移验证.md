## 三、独立复现 P076 读侧失效（交叉印证，附数据层/检索层精确切面）

我在 Claude 报告前已静态审查+实测独立抓到同一缺陷，从**我的分工层（数据/检索/意图）**补充精确切面：

1. **意图层**：`detectIntent` 的 `inMeeting` 参数（chat.ts:913）传的是 `_isActive`（GroupSession 派生 ✅ 有值）——意图判定本身正常；但 `process-stages.ts:129/175` 的会中换人/退出兜底段读 `_em.isActive()` 恒 false（该函数为死代码，Claude 已确认，不计入）。
2. **检索层（记忆/对话组）**：retrieval-stage 的隔离墙参数 `_meetingEntityName` 来自汇聚点 `_activeMeetingName`（GroupSession 派生 ✅）→ **记忆/对话组召回隔离在新架构下正常供给**；且批B 的 `_shadowSpeakerUuid`（speakerUuid 优先）守卫逻辑正确。
3. **🔴 KB 检索层（本次最精确的新切面）**：chat.ts:1136 `_meetingEntityUuid = _em.getEntityUUID()` 恒 null → **KB 的两道 UUID 门同时失效**：
   - chat.ts:2145/3264 `knowledgeBase.search(..., _meetingEntityUuid ?? undefined)` → 参数恒 undefined → 不按实体过滤；
   - chat.ts:1149 块内 `setSessionEntityUuid(_meetUuid)` 不执行 → KnowledgeEngine 全局会话过滤失效。
   → **会晤中 KB 召回无实体过滤 = 他人档案可能泄进会晤（I007 串档形态，隐私红线风险）**。这比「身份错」更危险，建议列入修复验收必测项。
4. **身份层**：chat.ts:2707 一致性守卫 `(_gsState.participants.length>0) === !!_meetingEntityName`，右侧恒 false → 会晤态判「冲突」→ 回退旧路径 `isMeeting=false` → `[Identity] xxx meeting=false speaker=玉瑶`（我与 Claude 均实测捕获）。

**修复建议**：采纳 Claude 方案C（`_em` 状态读方法转发为 GroupSession 只读视图）——它同时修复上述 2/3/4 全部读点，且严格不违反硬约束②。我补一条验收判据：**修复后必须断言「会晤中 `knowledgeBase.search` 带上了正确实体 UUID」**（当前 18 读点盘点偏重身份，KB 双门容易漏）。

## 四、🔴 新发现 P0 缺陷（P076 未覆盖）：多人会议纪要静默丢失

**违反 P072 任务A 验收项「多人会晤：纪要正常（A1 专项）」。**

- **根因**：`EntityMeeting.endMeetingSideEffects`（新架构唯一的纪要出口）条件为 `_multiTurns.length>=2 && _multiParticipants.length>=3`：
  - `_multiTurns`：recordTurn 四参从 GroupSession.multi 派生 ✅ 会累积；
  - `_multiParticipants`：**只在旧 `enterMulti()/enter()自动升级/addParticipant()` 写入**——新路径全部不调用（切主设计如此）→ **恒空数组** → 条件后半段永不满足 → **纪要永不生成**。即使条件通过，`_multiMeetingName`（纪要名来源）同样恒空字符串。
- **实测证据**：我的 3 人会晤（罗珍思+徐诗韵+熊梓铭，多轮，`散会` LEAVE applied effects=6）→ 日志**无「会议结束 → 纪要已生成」**，且 `endMeetingSideEffects` 被调用（「会晤结束」日志紧邻）。
- **修复建议（与方案C正交，改动极小）**：`beginMeetingSideEffects(name, uuids)` 已带 name/uuids 参数 —— 在该方法内同步维护 `_multiParticipants`/`_multiMeetingName` 作为**纪要素材采集**（类比 recordTurn 采集 `_multiTurns`，不是状态双写：GroupSession 仍是唯一状态真源）；`addSessionEntitySideEffect(uuid)` 同步补进 `_multiParticipants`（需同时补 name，建议签名加参或传 seed）。Phase 4 清旧代码时这两处素材采集可直接迁移。
