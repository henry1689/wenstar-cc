# 重启后 webui 孤儿进程链覆盖写入

## 一、现象

Phase 1 验收期间出现自相矛盾的状态：

- `[BlockSummary] 批完成: 扫描2 成功2 跳过0 失败0 待处理0`（日志说处理完了）
- 但库里那 2 组的 `block_summary` 仍是 NULL、`summary_state` 仍是 NULL
- 同样的「扫描 2 → 成功 2」在多个批次重复出现

## 二、取证

`Get-CimInstance Win32_Process` 发现**两条完整的 webui 进程链**同时存在：

| 链 | 进程 | 说明 |
|---|---|---|
| A（孤儿） | `36160`（pm2 ProcessContainerFork）→ `43120`（tsx）→ `3688`（server） | `pm2 restart` 后未退出 |
| B（当前） | `36264`（pm2 管理的 start.cjs）→ `22668`（tsx）→ `36752`（server） | 占用 3000 端口 |

pm2 的 `list` 只显示 B（pid 36264），看不到 A —— 与 memory 中「webui 多实例覆盖」是同一类问题。

**机理**：A 持有重启前的内存库副本，按自己的防抖周期 `export()` 落盘；
B 刚写入的 `block_summary` 被 A 的整库覆盖抹掉。sql.js 是「整库导出覆盖磁盘」，
两个实例共享同一个 db 文件时，后落盘者胜。

## 三、处置（已完成）

```
taskkill /PID 36160 /T /F
```

清理后只剩 `36264 → 22668 → 36752`，重新核对：

- `dialog_groups` 归属错配 = 0（v21 结果稳定）
- 摘要索引归属不一致 = 0
- 摘要状态：688 done / 38 skipped / 2 pending（持续新增组正常消费）

## 四、根因与永久修复建议

`pm2 restart` 只向主进程发信号，但 `start.cjs → tsx → node server` 是多级子进程；
若某级没有正确转发 SIGTERM（或子进程处于阻塞态），会留下孤儿链。

建议（下一批）：

1. **重启脚本加单实例校验**：`pm2 restart` 后等待若干秒，统计 `start.cjs` 进程数，
   仍 >1 则对旧链 `taskkill /T`；
2. 或给 webui 加与 harness 相同的**单实例锁文件**（启动时探测并拒绝第二实例）；
3. 落盘前增加「实例身份」守卫：非当前实例的进程拒绝 `export()`。

## 五、教训

- 「日志显示成功」不等于「数据落盘成功」——**落盘路径存在多写者时，必须核对磁盘状态**（与 I003 同一教训）；
- 重启类操作之后，第一件事应是**确认进程树只有一份**，而不是直接看业务日志。

## 六、根因已查清并修复（R013 差距5，2026-10-19，提交 `e5798b9`）

第四节的三条只是**建议**，本次按 R013「必须查清根因，不是加了 kill 就算完」挖到了两处代码级真因（都在 `start.cjs`）：

1. **端口被占用时只 WARN 却继续 spawn**（I005 真根因）
   原实现发现 3000 已 LISTENING 只打一条 warning 就继续 `spawn(server)`。
   新实例绑端口失败，但**照常 `initPipeline` 并挂上定时 `export()`** —— 两个进程各持一份 sql.js 内存库，
   整库导出覆盖磁盘 ⇒ 「日志成功、库里 NULL」（v21 结果被回退就是这条）。
   → **修复**：`_portBusy` 为真直接 `console.error` + `process.exit(1)`，连 prestart 写库脚本一起跳过。

2. **陈旧锁误判导致第二实例被放行**
   日志实测出现 `[Start] 清理陈旧锁 (PID 34160, host DEREK)`，而该 PID **当时仍存活** ——
   陈旧判据把活实例当死实例，`ServerLock` 约束随之失效，第二条链得以上线。
   → **修复**：锁 PID 存活时**先等其优雅关停**（最长 45s，不打断 `shutdownFlush` 落盘）再清理；
   另加启动前 PowerShell 扫描 `*webui*server.ts*` 孤儿进程并清理（只匹配真正写库的 `server.ts`，不碰自身）。

**验收（R013 要求「模拟 restart 进程链恒为 1」）**：2026-10-19 13:55 `pm2 restart wenstar-webui` 实测 ——
单链启动、`[ServerLock] 已持有锁 (PID 46416)`、20/20 模块校验（健康分 100）。
**重启 3 次幂等复验**并入 R013 任务C（交叉验证）执行，见 `02-progress/P008`。

原文第 3 条「落盘前实例身份守卫」暂未实现：端口占用即拒绝启动后，第二个写库进程不再存在，
该守卫的边际收益需在 3 次重启复验时一并评估 —— 如仍出现双写，再补上。
