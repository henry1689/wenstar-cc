## 二、核心问题定性

### A链路问题（4个）

**A1. 钙化机制名存实亡**
- 钙化分avg 0.389，96%记忆<1，晋升门槛6.5仅34条达标
- 零召回76.7%，形成"低钙化→不召回→永远低钙化"死亡螺旋
- block_calcium_score（对话组级钙化分）已存在但检索完全没用

**A2. 召回单位仍是单条memory，不是对话组**
- 检索逻辑还是逐条memory排序、逐条注入上下文
- 对话组只是个挂接字段，没有成为召回和注入的基本单位
- 应该是：先召回对话组，再从组内取1-2条代表性片段

**A3. 对话组无lifecycle流转**
- 679个对话组全部active，没有衰减、suppressed、archived
- A链路"允许遗忘"的核心能力在组级完全缺失
- candidate状态4463条记忆也无超时流转

**A4. UUID泄漏未根治**
- 617条无UUID(5.4%)，最近24h仍有55条
- promote_sand通道179条全null，根因（MemoryAssesser.ts:334 + server.ts:1545 sourceId=undefined）未修
- P0-2a只修了记事子系统，对话主链的UUID解析在某些场景仍失败

### B链路问题（4个）

**B1. wiki摘要完全没生成（最核心缺口）**
- 679个对话组block_summary全空
- 这是B链路"通过wiki模式小结、摘要、关键词分类存储"的核心能力，目前为零

**B2. 无冻结40D向量**
- dialog_groups没有perception_40d列，只有emotion_curve（维度不统一，是数组不是40D）
- B链路"冻结EventState_40D原始向量快照"的要求未满足

**B3. 无B链路读取API和消费计数**
- 没有按dialog_group_id单点读取的接口
- 没有USER_CONSUME（深度回忆消费）和OPS_BACKFILL（运维回填）的区分
- B链路消费次数无法回写到A链路钙化分

**B4. 无防篡改和AppendLog**
- 无内容哈希（content_hash）
- 无追加日志区（钙化晋升日志/回放唤醒日志/勘误记录）

### 共同问题（2个）

**C1. A/B锚点未打通**
- A链路检索命中memory后，不通过dialog_group_id去加载B链路完整原文+摘要
- 用户触发深度回忆时，没有路径拉起B链路高保真回放

**C2. 法典/ADR未同步**
- ADR-0012（双链路架构）未编写
- 《真值规范》V3.0未修订
- 代码已经走在前面，文档严重滞后

## 三、分阶段落实计划

### Phase 1：B链路wiki摘要生成（最优先，因为679个组全空）

**目标**：每个对话组闭组时自动生成三层wiki摘要，存量679个组补全。

**任务**：
1. 设计摘要生成器：闭组时（block_close_reason触发），读取组内全部conversations原文，生成三层摘要：
   - 标签摘要：narrative_tag + 关键词列表（5-10个）
   - 叙事摘要：2-3句话概括这个对话组讲了什么
   - 情感摘要：primary_emotion + emotion_curve总结 + 情感强度峰值
2. 写入dialog_groups.block_summary（JSON格式，包含三层）
3. 存量679个组批量补全（异步任务，分批处理，不阻塞主流程）
4. 摘要生成质量测试：抽样10个人工检查

**验收**：
- [ ] 新闭组的对话组100%有block_summary
- [ ] 存量679个组补全率≥95%
- [ ] 摘要包含标签/叙事/情感三层
- [ ] 有对应的单元测试

### Phase 2：A链路块级召回（核心架构变更）

**目标**：检索召回从单条memory改为以对话组为单位。

**任务**：
1. 检索逻辑改造：先按dialog_group聚合召回，计算组级综合得分（组内记忆钙化均值×0.4 + block_calcium_score×0.3 + 向量相关性×0.3），取TOP N组
2. 每组取1-2条代表性片段（组内钙化最高的 + 时间最近的）注入上下文
3. 对话组级lifecycle状态机：active→decaying（随时间衰减）→suppressed（不进常规检索）→archived（只增不删）
4. 块级钙化公式落地：`block_calcium = α×组召回次数 + β×组内情感峰值 + γ×时间衰减 + δ×B链路消费次数`
5. candidate状态记忆超时流转：30天未晋升→suppressed

**验收**：
- [ ] 检索结果以对话组为单位展示，不是单条memory
- [ ] 对话组有lifecycle流转，不是全部active
- [ ] 块级钙化分参与检索排序
- [ ] candidate无永久停滞（30天流转）
- [ ] 有回归测试锁住"单条召回"不复发

### Phase 3：B链路规范卷宗化

**目标**：把dialog_groups从"简单分组"升级为规范的B链路沉睡卷宗。

**任务**：
1. dialog_groups新增列：
   - `event_state_40d`：冻结40D向量快照（闭组时生成，写入后只读）
   - `content_hash`：SHA256内容哈希（组内原文+摘要，防篡改）
   - `append_log`：JSON数组，追加钙化晋升日志/回放唤醒日志/勘误记录
2. BArchiveReader API：`getByGroupId(groupId)` 单点读取，返回原文+摘要+冻结向量+append_log
3. 禁止B链路全局检索：代码守卫，任何扫描dialog_groups全表的检索都要拦截
4. B链路消费计数：USER_CONSUME（用户深度回忆触发）和OPS_BACKFILL（运维回填）区分，USER_CONSUME回写A链路块级钙化δ因子

**验收**：
- [ ] 新闭组的对话组有event_state_40d + content_hash
- [ ] BArchiveReader可按groupId单点读取
- [ ] 无全局批量检索B链路的代码路径
- [ ] USER_CONSUME消费次数回写A链路钙化分
- [ ] 有防篡改校验（哈希不一致时告警）

### Phase 4：A/B锚点打通 + 存量迁移

**目标**：A链路召回命中后可拉起B链路完整原文，存量数据全部迁移到新结构。

**任务**：
1. A链路检索结果中，每个对话组附带"可加载完整原文"的指针
2. 用户触发深度回忆（"详细说说那天的事"/"完整回忆一下"）时，通过groupId加载B链路完整原文+wiki摘要，渲染高保真回放
3. memories剩余50.2%未挂对话组的存量补挂（按时间窗口+语义相似度）
4. 存量679个对话组补event_state_40d和content_hash
5. promote_sand通道修复（MemoryAssesser.ts:334 + server.ts:1545传sourceId）

**验收**：
- [ ] 深度回忆可加载B链路完整原文
- [ ] memories挂对话组率≥90%
- [ ] 存量对话组100%有冻结向量和哈希
- [ ] promote_sand写入携带source_id和belong_entity_uuid
- [ ] UUID泄漏根治：新写入UUID覆盖率=100%

## 四、铁律约束（全过程必须遵守）

1. **记忆单元是对话组/语义块**，不是单条message。所有新功能以组为单位设计
2. **归属是结构事实**，禁止按正文推断UUID
3. **只增不删是存储层不变量**，B链路原始卷宗永不删除，A链路可以suppressed但不删原文
4. **B链路只允许单点读取**（按groupId），禁止全局批量检索
5. **钙化是候选入场券，不是唯一排序键**——高钙化不能永久碾压近期记忆
6. **所有数据库改动在停服窗口内执行**，执行前备份
7. **测试先行**，每个改动有回归测试，红用例锁住已修复缺陷
8. **法典>ADR>代码>改错记录**，代码与法典冲突视为缺陷
