## 三、I005 单实例锁根因（R013 差距5）

**根因（两处，都是 `start.cjs` 的启动守卫失效）**：

1. **端口占用时只 WARN 仍继续 spawn**：新 server 绑不上端口，但依然 `initPipeline` 并定时 `export()`，与旧进程**各持一份内存库**，后落盘者整库覆盖前者 ⇒ 「日志成功、库里 NULL」。
2. **陈旧锁误判**：日志出现 `[Start] 清理陈旧锁 (PID 34160)`，把**仍存活**的实例判成陈旧 → 约束解除 → 第二条链起来。

**修复（已落地，`e5798b9`）**：
- 端口被占用 → `console.error` + `process.exit(1)`，**拒绝启动第二实例**，不再走 prestart 写库脚本
- 启动前用 PowerShell 扫 `*webui*server.ts*` 找孤儿进程；若锁 PID 仍存活，**先等其优雅关停**（最长 45s，不打断落盘）再清理
- `ServerLock` 语义注释保留：锁由真正写库的 `server.ts main()` 持有

**验收（R013 要求「模拟 restart 进程链恒为 1」）**：**已连续重启 3 次，每次均为单链**（明细见 §二），
三次扫描数据完全一致（done 747、各验收项 0）。

原文第 3 条「落盘前实例身份守卫」**本次未实现**，理由已写入 `03-issues/I005` §六：
端口占用即拒绝启动后，第二个写库进程不再存在，该守卫的边际收益待后续双写复发时再补 —— 属**有意暂缓**，非遗漏。
