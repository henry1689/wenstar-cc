## 二、🔴 批B 真缺陷（本次实测发现并已修复）

**症状**：开关已开、投影块确实执行（探针证实 `enabled=true emActive=true`），但影子侧**零日志、零 dispatch**，即批B 的投影在最常用的**单人会晤场景下完全不工作**。

**根因**：`chat.ts` 构造投影快照时用 `EntityMeeting.getParticipants()` 取参与者，而该方法返回的是 `_multiParticipants`，**只在多人路径赋值**（`EntityMeeting.ts:165/230/327/815`），单人会晤从不碰它 → 恒为 `[]` → `projectMeetingState` 命中「无效快照」守卫 `if (snap.active && seeds.length === 0) return []` → 返回空 action 序列。

**讽刺点**：`project.ts:31` 的接口契约注释写的就是「参与者（多人时 `getParticipants()`，**单人时只含主发言者**）」—— 契约写对了，调用方没兑现。与「注释写的才是对的」这一既往模式一致。

**修复**：`chat.ts` 快照构造处，`getParticipants()` 为空且 `getEntityUUID()`/`getEntityName()` 均有效时，补为单元素 `[{uuid, name, category:''}]`。多人路径逐字不变。未在 `project.ts` 内做被调方兜底 —— 契约已在调用方声明，在被调方偷偷兜底会掩盖契约违反，未来其它调用方仍会踩同一坑。

**为什么批B 的 20 例单测没抓到**：单测直接构造 `MeetingSnapshot`，绕过了 `chat.ts` 这段构造代码。**这是本次最有价值的教训：投影逻辑的单测必须覆盖「快照构造」这一段，否则测的是契约不是实现。**

## 四、🔴 发现的既有缺口（非 T013 引入，记录待业主裁决）

**EntityMeeting 的 exit 意图覆盖缺口**：实测中我先用「结束，回玉瑶这边」试图退出，但**没触发 exit**，会晤继续。查 `EntityMeeting.detectIntent`，exit 只认四类句式：

- `散会|不聊了|不开了|今天就到这儿|今天就到这里|先这样|下了|拜拜|再见`
- `^结束(了|吧|啦)?(会议|对话|会晤|话题|我们|聊天)?(吧|了|啦|~|～|!|！)?$` —— **要求整句匹配**
- `^(切回|回到|换回|变回)玉瑶$` —— **要求句尾就是"玉瑶"**
- `^(和|跟|找|叫|让)?玉瑶(聊聊|谈谈|...)?$`

「结束，回玉瑶这边」四条都不命中（`^结束…$` 要求整句、模式3 要求句尾为"玉瑶"），被判成 `normal`。而 EntityMeeting 自身有「消息无会晤意图时自动恢复上次会晤」的逻辑，配合 LLM 的自由发挥，用户会看到实体自己说出「那我先走了」但**会晤实际未退出**——观感上像退出了、实际没退。

本次实测改用「散会」才触发 exit。**建议业主裁决是否扩大 exit 覆盖**（如允许 `结束` + 尾随宾语），但这是既有行为、非 T013 引入，不在本任务范围。
