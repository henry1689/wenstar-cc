## 二、问题定性

**核心矛盾**：A链路的设计目标是"按人脑记忆允许遗忘，加权频次钙化记忆和召回"，但当前：
1. **组级评分已算好但闲置**：block_calcium_score avg 3.85，257组高钙，但召回路径零引用
2. **组级生命周期不存在**：804组全部active，无巩固/归档流转
3. **单条记忆钙化崩坏**：95.7% memories <1分，靠单条钙化排序无区分度
4. **两路召回未融合**：B链路（DialogGroupAdapter）按关键词+摘要召回，A链路（meeting-recall）按单条钙化召回，两路独立无统一编排

**Phase 2 方向**：不以修复memories钙化为目标（那是历史包袱，单条记忆粒度太细），而是**以对话组为A链路的基本单元**，把block_calcium_score接入召回，建立组级生命周期，让"重要的对话组"被记住不遗忘。

## 三、Phase 2 子阶段计划

### Phase 2.1：组级生命周期建立（PI 主导）
- 给dialog_groups建立lifecycle流转：active → consolidating（高钙组巩固）→ archived（低钙/老组归档）
- 流转规则：block_calcium_score >= 5 → consolidating；创建>30天且score<2 → archived
- 归档不删除（只增不减），archived组降低召回优先级但仍可被关键词命中
- 沉淀窗：排除30分钟内闭组的组（已裁决）
- 验收：804组有明确生命周期分布，非全部active；流转规则有回归测试

### Phase 2.2：block_calcium_score接入召回（Claude 主导）
- DialogGroupAdapter增加钙化排序维度：当前打分0.40*conv + 0.30*summary + 0.15*共振 + 0.15*calcium，calcium项应从单条memory改为dialog_groups.block_calcium_score
- 会晤召回增加"高钙对话组"通道：block_calcium_score >= 5的组，在会晤时按时间近因注入（不看单条memory钙化）
- 高钙组召回不占用memories的槽位，独立配额
- 验收：高钙组（257组）在会晤时能被召回；钙化排序有区分度（高钙组排名高于低钙组）

### Phase 2.3：A/B链路统一召回编排（两人协作）
- 召回编排器（MemoryRetriever）统一调度：A链路（高钙组+单条记忆）+ B链路（摘要+原文），按场景分配配额
- 会晤模式：A链路高钙组占40% + B链路摘要占40% + 近期记忆占20%
- 非会晤模式：B链路摘要占60% + A链路钙化占40%
- 验收：两路召回不重复、不冲突；配额可配置；有回归测试

### Phase 2.4：存量数据迁移 + 法典同步（豆包主导）
- 存量804组按新规则初始化生命周期
- ADR-010更新：组级生命周期+钙化召回
- 法典同步：《真值规范》V3.0修订A链路部分
- 验收：存量数据迁移完成；ADR/法典更新；全量扫描无违例
