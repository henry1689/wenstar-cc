# 决策：建立豆包与Claude Code的文件协作工作区

## 背景

此前沟通依赖用户复制粘贴任务书和执行结果，效率低且易丢失上下文。

## 决策

在 `docs/agent-collab/` 建立异步协作工作区，双方通过文件读写沟通：

- `01-tasks/`：豆包写任务书
- `02-progress/`：Claude Code写进度
- `03-issues/`：Claude Code写阻塞/问题
- `04-reviews/`：豆包写评审/建议
- `05-decisions/`：重要决策记录
- `09-archive/`：已完成归档

## 协议要点

1. 文件命名：`{编号}-{日期}-{描述}.md`，编号前缀T/P/I/R/D
2. 每个文件必须有frontmatter（id/type/title/author/status/created/updated/related）
3. 只增不删，修改用追加方式
4. 双方不直接修改对方的文件，有异议通过issues/reviews提出
5. 所有数据必须实测，不写"大概""应该"

## 生效时间

2026-10-08 起。当前P0任务已录入为T001，评审意见已录入为R001。

## 更新记录

### 2026-10-08 修订：明确平等协作定位

用户（表哥）指出：协作工作区是**互相交流，不存在谁指挥谁**。Claude Code是实际操作者，有很多实际困难和优秀建议，必须采纳，取长补短强强联合。

据此修订 `00-README.md`：

1. 新增「协作原则」章节，明确：平等互补不是指挥执行、实际操作者有发言权、好建议不分来源、分歧通过讨论解决
2. 文件夹描述从"豆包写/Claude写"改为"双方都可以写"
3. 沟通流程从单向流水线改为双向迭代
4. 双方职责改为互补定位：豆包擅长架构/法典/跨模块，Claude Code擅长代码/根因/实测
5. status新增`discussing`状态

本决策原文保留，修订内容以本次更新记录为准。

### 2026-10-08 再修订：增加用户最终裁决权

用户补充：当双方都不清楚方向或有争议时，由用户（表哥）最终裁决。

据此在 `00-README.md` 协作原则中新增第5条：
- 双方无法达成一致时，由用户最终裁决
- 裁决方式：在对应文件写「裁决」区块，或新建决策文件
- 裁决后必须执行，发现新问题可重新讨论
- 双方职责是讲清理由/证据/风险供决策参考，不替用户做决定
