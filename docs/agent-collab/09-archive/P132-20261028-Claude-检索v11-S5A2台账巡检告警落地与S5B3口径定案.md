## 一、做了什么

### 1. S5-A2 缺口台账「每日自动对账 + 异常告警」

任务书原文只写了「`GapLedger` 增加每日自动对账 + 异常告警」。实测发现三处缺口：

| 缺口 | 后果 |
|---|---|
| `reconcileDate()` 全仓**零调用方** | 「对账」有函数、无人调用 |
| 自检失败只 `console.error` + exit 3 | 计划任务把 stdout 丢掉 ⇒ **失败=无声** |
| 台账只在写入那一刻自检 | 任务根本没跑时（机器未登录）**静静缺一天，没人知道** |

**交付**（`src/m4/retrieval/GapLedger.ts` + `scripts/v11-gap-audit.ts`）：

- `patrolLedger()`：断档扫描（含多日断电，折成一条）· 写入时自检失败 · 基线缺失/损坏 · 库复算不符
- `appendAlert()`：告警落 `data/retrieval-v11/alerts.jsonl`，**同 `kind+date+detail` 24h 只落一条**
  （15 分钟节拍 × 永久性异常 = 每天 96 条重复告警），但**每轮巡检仍判定失败**（exit 3）
  ⇒ 文件不刷屏 + 问题不解决就一直红
- `pendingReconcileDates()`：**先纯文件判断有无新记录要复算**，无则不载库
  （sql.js 把整个库读进内存，不能每 15 分钟来一遍）
- 00:00–00:10 **宽限窗**：00:05 的写入任务还没跑完，此时不把昨天判成断档
- CLI `--patrol`

### 2. 顺带修 F-33：`reconcileDate` 跨日复算必然误报

原实现无条件把 `stored.conversations_total` 与**当前库总量**比对。总量每天都在涨 ⇒
**昨天写的记录拿今天的总量一比必然不等**，巡检上线第一天就会刷满假阳性。

根因是**口径错位**：B4「总量零误差」本来就是 `buildDailyRecord` **落盘前**的自检，不能事后倒查。
改成 `{ snapshot }` 选项——巡检复核历史日期只比**日期域**字段（`n_gap` / 首尾 id）。

### 3. S5-B3 度量口径定案（改文档，不落码）

蓝皮书 §8.3「统计前必须剔除 `<2s` 的 run」**照搬到逐查询影子日志上不成立**，已实测证伪：

- 该条款的 `run` 是**审计 run**（整条流水线总时长）；
- 影子日志的 `stage_ms` 是单次检索耗时，**实测 P50 78 / max 496 ms**；
- 照字面执行 ⇒ `isRealRun()` 每条都返回 false ⇒ **样本归零、统计作废、与 S5-A3 基线自相矛盾**。

正式口径三条（见基线文档 §2.2）：围栏 SQL 已排 `is_test` 域 · 全仓核验当前**无污染写入路径** ·
`isRealRun` 保留给有真实 run 时长的场景。**业主裁决：写口径说明、不落冗余码**。

## 四、方法论教训

1. **Harness 令牌是单次使用**（`harness-pre-check.cjs:498-502`）。我用一个令牌连做 6 次编辑，
   第 1 次消耗掉后后 5 次变「无令牌写入」，Sentinel 计满 3 次 → **`attrib +R` 物理锁定文件**，
   写入报 `EPERM`。**正确姿势：一个文件一次写入**（完整 Write），或每改一处就重跑 `run_flow`。
2. **被锁后不要改属性位绕过**：走锁文件给出的官方解锁命令（需管理员密码）。本次是业主明示豁免后才清的。
3. **S4.5 会因「共性/个性归类错误」扣分**：我把「单测断言修正」归成共性底层修复，被 DS-23 扣 20 分。
   归类错不是小事——它决定要不要全仓横向核验。
4. **测试断言也会写错**：16 条新断言里挂的那条，是我构造的场景里根本不存在断档却断言有断档。
   **实现是对的，测试是错的**——别一看到红就先怀疑实现。
