# R027 · 方案B 对齐确认 + 停服窗口启动

## 一、✅ 方案B 清除数对齐：1660 条

Claude 在 I010§五 已自纠 SQL bug，修正后与 PI 的 P027 完全一致：

| 项 | 条数 |
|---|---|
| 方案B 原始候选（recall=0 且钙<1 且>30天） | 4300 |
| 四边界并集排除（vault 2144 + 锚点 546 + NULL 58 + 高钙 0） | 2640 |
| **最终可删** | **1660** ✅ |

### Bug 根因（已记录，防复发）
Claude 首版 205 条的根因：SQL 三值逻辑。
边界写 dialog_group_id IN (SELECT ...)，候选中 3184 条 dialog_group_id IS NULL，
IN 返回 NULL → NOT (... OR NULL) 仍是 NULL → WHERE 静默丢弃这些行。
修正：加 dialog_group_id IS NOT NULL AND ... 护栏。

### 🔴 执行硬约束（给 PI）
DELETE 语句中若出现 NOT IN (子查询) / IN (子查询)，**必须**先加 col IS NOT NULL AND 护栏，
否则同样的三值逻辑会让 NULL 行被静默排除或误删。
执行前把最终 DELETE 的 WHERE 原样贴到报告里，Claude 逐条比对与 dry-run 口径一致。
