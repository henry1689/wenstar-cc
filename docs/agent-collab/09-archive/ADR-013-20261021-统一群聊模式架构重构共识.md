# ADR-013 · 统一群聊模式架构重构（共识版）

> 本文由 Claude（架构层/prompt层/输出层）与 PI（数据层/意图层）设计建议合并而成，业主裁决确认。
> 三大红线：数据零丢失、人格零串档、加人减人零误操作。

## 一、背景与目标

### 1.1 问题
- 现有三套状态机（聊天/单人会晤/多人会晤）分裂，累积 10 项缺陷（P037/P039）
- 身份泄漏：角色路由早于状态机 314 行，6 份会话状态副本，_effectiveRole 覆盖身份
- 多人会晤不持久化，重启永不恢复
- 情感/场景基线不对称，退出时 reset 归零导致玉瑶基线丢失

### 1.2 目标
- 统一为群聊模式：默认用户+玉瑶，动态加人减人，LLM 判断发言者
- 七层人格隔离全部实现，压测 1000 轮零串档
- 旧数据零丢失，871 对话组+11598 记忆+1036 FG 节点必须被新架构继续调用

## 二、核心架构设计

### 2.1 会话状态单一真源（Claude §1）

**消灭 6 份副本，收敛为一个可序列化对象：**

```ts
interface Participant {
  uuid: string;          // FG 实体 UUID（唯一键，所有隔离按它取）
  name: string;          // 显示名（主名）
  aliases: string[];     // 别名（PI 白名单用）
  category: string;      // human | celestial
  joinedAt: number;
  turnCount: number;
}

interface SessionState {
  mode: yuyao | meeting;      // 派生：participants.length > 0 => meeting
  participants: Participant[]; // 玉瑶默认不入列；空数组 = 玉瑶态
  speakerUuid: string | null;  // 当前发言者（玉瑶态为 null）
  turnIndex: number;
  contextStack: ContextSlot[]; // 情感/场景/角色现场
  lastActivityAt: number;
}
```

**三条硬约束：**
1. 禁止冗余布尔：isMulti 由 participants.length >= 2 派生
2. 状态只有一处写：所有变更走 dispatch(action) 单入口
3. 身份解析在状态之后：resolveIdentity(state) 只接受 SessionState

### 2.2 状态流转（reducer 风格）

```ts
type Action =
  | { type: WAKE;   targets: string[] }   // 进会晤（1人或多人，同一入口）
  | { type: JOIN;   target: string }      // 加人
  | { type: SPEAK;  target: string }      // 换主发言
  | { type: LEAVE;  target?: string }     // 减人（缺省=散会）
  | { type: RESUME; state: SessionState } // 重启恢复
  | { type: IDLE;   now: number };        // 时间分隔/闭组

interface GroupSession {
  getState(): SessionState;
  dispatch(a: Action): SessionState;  // 同步、纯、不变（返回新对象）
  serialize(): string;                // 持久化（engine_store 单键）
  restore(s: string): boolean;
  onEnter(fn: (prev, next) => void): void;  // PI 加人减人回调挂这里
}
```

**reducer 风格的好处：**
- 每次状态变更自动可审计（action 序列即日志，零额外代码）
- 第七层校验失败需回滚一轮时，只需重放 action
- 序列化天然支持（JSON.stringify 即持久化，修掉多人不持久化缺陷）

### 2.3 chat.ts 接入（适配层+逐段替换）

- 不整体搬迁现有代码，采用薄适配层：groupSession.dispatch(intentToAction(intent))
- _currentRole 三份副本一次性消灭：身份由 resolveIdentity(state) 在调用 M5 的那一个点算出并传入
- _effectiveRole 地雷随同清除：身份参数与长度参数分属不同对象

## 三、七层人格隔离设计

### 第一层：发言者判断隔离（Claude）

**分层判断，默认路径零 LLM 调用：**

```
① rule-first（PI 白名单，零成本）
   点名命中 + 状态判定（无会晤=>WAKE；会晤中=>JOIN/SPEAK）
   ↓ 未命中
② 粘性保持（默认路径，零成本）
   会晤中 => speakerUuid 保持不变，记 speaker_sticky_hold 告警
   玉瑶态 => speakerUuid = null
   ↓ 仅会晤首轮且无人点名才走
③ LLM 兜底（结构化输出，一次调用）
```

**LLM 兜底 prompt 规范：**
- 输入：参与者列表 + 最近 N 轮 + 本轮消息
- 输出：{speaker_uuid, speaker_name, confidence, reason}
- confidence < 0.6 => 按粘性规则处理，不采信
- 不确定时不得输出玉瑶（除非玉瑶在 participants 中）

### 第二层：身份 prompt 隔离（Claude）

**resolveIdentity(state) 纯函数：**

```ts
resolveIdentity(state): {
  speakerUuid: string | null;
  speakerName: string;
  dossierText: string;        // 只有发言者的完整 dossier（PI 产出）
  participantsDigest: string; // 其他人只给 name+relation+一行摘要
  rulesText: string;          // 自称铁律（会晤态：只能自称 speakerName）
}
```

**结构性保证（不是清洗）：**
- 会晤态根本不经过玉瑶 role 通道——不是经过再洗掉，而是分支上就没有玉瑶模板
- 玉瑶态才走玉瑶 persona 模板，不经过任何 isEntityMeeting 条件

### 第三层：记忆检索隔离（PI）

**咽喉函数 applyMeetingUuidFilter，deny-by-default：**

```ts
export function applyMeetingUuidFilter(ctx, uuid: string | null): PolicePolicy {
  if (!uuid) return { visibleUuids: new Set(), searchScope: strict, enforce: true };
  return { visibleUuids: new Set([uuid]), searchScope: strict, allowUnowned: false, enforce: true };
}
```

- 无 uuid => 空白名单（不召回他人），绝不 enforce:false（I007 根因）
- 编译期强制：会晤态 RetrievalContext 类型要求 meetingUuid: string（非可选）
- 所有检索入口必须过它：runSearch / FoundationRoutes / MeetingWallAdapter / 高钙 / 关键词 / 锚点
- 防回归：grep 断言会晤路径 enforce:false 零命中

### 第四层：FG 档案隔离（PI）

- 只注入当前发言者 dossier（复用 EntityContextBuilder.buildEntityContext(uuid)）
- 其他参与者只注入摘要（name+relation+一行简介），不注入完整档案
- relationMap 只注入当前发言者 <-> 用户那条边

### 第五层：情感状态隔离（Claude）

**ContextSlot 压栈弹栈（不是 reset）：**

```ts
interface ContextSlot {
  uuid: string | null;        // null = 玉瑶
  emotion: { pleasure, arousal, intimacy };
  sceneAnchor: SceneAnchor;
  contextMemory: ContextMemoryState;
  savedRole?: RoleType;       // 玉瑶态保存
  savedAt: number;
}
```

- WAKE（从玉瑶态进会晤）压玉瑶现场
  - LEAVE 至 participants 为空时弹回玉瑶现场
  - 换人（SPEAK）不压栈（同一会话内换人）
- 兼容旧数据：emotion_snapshots 表原样保留，WAKE 时从它读初值（additive）
- 修掉：reset 归零=>基线丢失、玉瑶快照无人维护、角色不复原

### 第六层：场景锚点隔离（Claude）

- 每人独立场景锚点，切换时加载对应锚点
- 进入会晤时不 reset 玉瑶锚点，而是压栈保存
- 退出会晤时弹栈恢复玉瑶锚点（不是归零）

### 第七层：输出校验隔离（Claude）

**结构化合并生成，默认路径 +0 次 LLM 调用：**

主回复单次输出结构化头 + 正文：
```
speaker: 徐诗雨
---
（正文，自然语言）
```

**校验在同一个响应体上做（正则抽头，~1ms）：**
1. speaker 头缺失/不在参与者列表 => 正文仍可用，按粘性规则重新归属，记告警
2. speaker 头与正文自称冲突 => 二次 LLM 校验（~1-2s）
3. 二次校验也不确定 => 降级 + 告警（不自动重生成，避免延迟雪崩）

**实现约束：**结构化头必须用字段边界而非正则枚举，否则重演 V45 纯 JSON 削坑。

## 四、加人减人严格控制（PI）

### 4.1 正则白名单

```
ADD:  /(?:叫|让|喊|把)\s*(?:上)?\s*(NAME)\s*(?:也)?\s*(?:来|过来|参加|加入|进来)/
ADD2: /(NAME)\s*也(?:来|过来|加入)|把\s*(NAME)\s*拉(?:进来|入)|让\s*(NAME)\s*加入我们/
REMOVE: /(NAME)\s*(?:先走|先回|先回去|不用来|先撤)|让\s*(NAME)\s*(?:离开|先走)|散会|结束|就到这吧|下次再聊/
```

- NAME 动态匹配：先切候选中文段，再经 getUUIDByName/别名归一解析为 FG active 实体
- 解析失败（非 FG active 实体）=> 不操作（模糊情况不操作）

### 4.2 状态机消歧

| 当前状态 | 指令 | 动作 |
|---|---|---|
| 无会话 | ADD | 唤醒 enter（单/多） |
| 群聊(>=2人) | ADD | addParticipant（NAME 不在参与者中） |
| 单人会话 | ADD | addParticipant（变多人） |
| 任意会话 | REMOVE | removeParticipant / 散会类=>exit |
| 任意 | 多人目标(>=2 NAME) | 一律走唤醒 enterMulti，不走加人 |

### 4.3 日志（所有操作写日志）

```
[GroupOp] add +王全芬 (by=叫XX来, uuid=TXS-3, participants=3)
[GroupOp] remove -阿珍 (by=XX先走, uuid=TXS-2, participants=2)
[GroupOp] deny add 诗韵 (reason=非FG实体/不在参与者中)
```

## 五、数据保护与兼容（PI）

### 5.1 红线
- 旧数据只读：dialog_groups/conversations/memories/nodes/edges 不迁移、不改格式
- 检索接口 runSearch/runRetrieval 签名不变（23 测试套兼容）
- Schema additive：新格式用新列/新表，不改旧列

### 5.2 数据兼容层
- 启动时检测旧表/列，标记 inMemory
- 检索时 UNION 新旧，按现有接口返回
- 新对话写新格式；旧对话保持原样

### 5.3 时间分隔
- 显示分隔线：距上次消息 >1min 且新一轮开始 => 写一行时间分隔（纯显示，不闭组）
- 闭组：保持现有 30min（_dgIdleCloseMs）
- 两者解耦：1min 只影响显示，30min 才闭组

## 六、回滚方案（Claude）

| 层 | 措施 |
|---|---|
| 开关 | WS_GROUP_V2（环境变量/config），默认关闭，Phase 4 前不切 |
| 旧代码 | Phase 4 之前不删 EntityMeeting 任何一行，回滚=关开关 |
| 数据 | 新状态只写 engine_store 新 key（KV），旧代码不读新 key，回滚零数据丢失 |
| 读路径 | 新架构只读旧数据，不迁移不改格式 |

**回滚演练判据：**
1. 关开关后服务正常启动
2. 871 对话组/11598 记忆/1036 节点可读
3. 旧会晤可继续
4. 新架构写入的对话在旧架构下可召回

| 顺序 | 阶段 | 内容 | 负责人 |

## 八、压测设计（PI）

### 双轨
| 轨 | 目的 | LLM | 轮数 |
|---|---|---|---|
| 结构轨 | 验状态机/隔离/加人减人/时间分隔 | Mock | 1000 轮 |
| 真LLM轨 | 验 prompt/自称/人格隔离真实效果 | 真 DeepSeek | 50 轮 |

### 结构轨断言（每轮）
- 人格隔离：speaker === 期望发言者，1000 轮零串档
- 加人减人：1000 轮零误加/误减，模糊 100% 不操作
- UUID 隔离：召回 hit.entityUuid === 会晤 uuid
- 时间分隔：>1min 写分隔、>30min 闭组

## 九、协作接口
