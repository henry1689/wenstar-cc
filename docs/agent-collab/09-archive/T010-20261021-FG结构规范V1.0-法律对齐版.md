# T010 · FG 结构规范 V1.0（法律对齐版）

## 🎯 业主裁决

> 1. 按系统内部法律法规（宪法、户籍法、白皮书蓝皮书）先把FG结构固定下来
> 2. 固定采集类别、词目、内容、编写规范（前缀）、关系边的确立
> 3. 取词来源：①完整对话组/语义块 ②上传的个人档案类文档
> 4. 定时通过LLM提取，去重后按规则写入FG
> 5. 读取按同样结构进行，前后结构一一对应
> 6. 跑通后旧规则彻底清除（RAG提取、词表法、旧路径全部删除，不留兼容层）

## 🏗️ 一、数据结构固定（法律对齐）

### 1.1 nodes 表（户籍登记表）

**必填字段**：
| 字段 | 类型 | 法律依据 | 说明 |
|---|---|---|---|
| id | TEXT | 第七条 | TXS-{9位自增流水号}，纯流水号无分类前缀 |
| name | TEXT | 第十二条 | 法定本名，关系称谓不得存入 |
| type | TEXT | 第二条 | person/org/place/object/event |
| uuid | TEXT | 第六条 | 全域唯一，户籍铁律 |
| status | TEXT | 第三十条 | active/dormant/archived/deceased（**法律四档，删除candidate/void**） |
| category | CHAR(1) | 第八条 | S/U/A/B/X/G |
| entity_source | TEXT | 第十五条 | real/ai/fictional/historical/placeholder |
| properties | TEXT | 第九条 | JSON，dossier七子卷 |
| created_at/updated_at | TEXT | — | |

**可选字段**：aliases（JSON数组，曾用名/昵称/称谓别名）

**删除字段**（Phase 5）：security_level(归记忆域) / tags / circle_level / legacy_ids(迁移完成后) / family_gene / social_group_genes / entity_source外露

### 1.2 dossier 人生卷宗（七子卷，法律第十九条）

| 子卷 | 字段 | 法律依据 |
|---|---|---|
| ① basicInfo | gender, birthYear, birthPlace, education | 第十九条(一) |
| ② selfProfile | traits[], appearance, bodyFeatures, style, voice, preferences[], taboos[] | 第十九条(二) |
| ③ socialIdentity | occupationTimeline[], marriageTimeline[], currentOccupation, currentWorkplace | 第十九条(三) |
| ④ lifeMilestones | [{date, event, type, sourceRef}] | 第十九条(四) |
| ⑤ boundDocuments | [{docId, type, title, boundAt}] | 第十九条(五) |
| ⑥ _changeHistory | [{time, operation, field, before, after, reason, source}] | 第十九条(六)，上限10000条 |
| ⑦ misc | 自由JSON | 第十九条(七)，结构化内容禁止写入 |

**删除子卷**（Phase 5）：imageTraits / personalityPrefs / health / relationMap / familyNetwork / socialCapital / lifeResume / contact（迁入对应标准子卷）

### 1.3 edges 表（关系网络，法律第二十四条）

**必填字段**：
| 字段 | 类型 | 说明 |
|---|---|---|
| id | TEXT | |
| source_id | TEXT | FK→nodes.id |
| target_id | TEXT | FK→nodes.id |
| relation | TEXT | 必须∈RELATION_TYPE_DEFS（单一真源） |
| properties | TEXT | JSON: confidence, evidence, source, created_from |
| created_at/updated_at | TEXT | |

**properties 规范**：
- confidence: 0-1（LLM提取置信度）
- evidence: 对话原文片段或文档摘录（证据）
- source: conversation / document（取词来源）
- created_from: dialog_group_id / document_id（溯源）

**关系边规则**：
- 反向边自动建立（如 mother_of → child_of）
- source+target+relation 三元组去重
- 低置信度（<0.7）不写入，存PendingItem

### 1.4 RELATION_TYPE_DEFS 单一真源

- 补齐法律允许的全部关系类型（家庭/亲属/朋友/职场/社交/其他）
- 其余词表（FG白名单/HWG KINSHIP_MAP/RelationLabels/EntityContextBuilder内置）**全部删除**，从DEFS派生
- 启动断言：写入白名单 ⊆ DEFS

## 📥 二、取词来源（双来源）

### 2.1 来源一：对话组/语义块
- 定时扫描（默认每天凌晨）最近 N 个**已闭组**的对话组
- 从完整对话组上下文提取（不是逐句RAG）
- LLM语义理解判断：哪些是真正有意义的实体和关系

### 2.2 来源二：上传文档
- 知识库中的个人档案类文档（.md/.txt/.pdf等）
- 文档上传/更新后触发提取
- 同样走LLM语义理解提取，禁止关键词匹配

### 2.3 统一提取流程（双来源共用）
`
输入（对话组/文档）
  → LLM语义提取（统一prompt + JSON schema）
  → 准入门槛判断（有交互+有特征+有持续提及）
  → 置信分层（≥0.7入库 / 0.4-0.7待确认 / <0.4丢弃）
  → 三级去重（实体/关系/字段）
  → 写入FG（nodes + edges + dossier）
  → 变更流水记录（_changeHistory）
`

## 🔍 三、提取规范

### 3.1 准入门槛（不是所有提到的名字都录入）
实体必须满足以下至少2条：
1. 有明确交互（用户与该实体有对话）
2. 有特征描述（职业/关系/外貌等）
3. 有持续提及（不是一次性提到）
4. 有明确关系（与用户或其他实体的关系）

### 3.2 置信分层（法律第二十二条）
| 置信度 | 处理 |
|---|---|
| ≥0.7 | 直接写入Dossier正式字段 |
| 0.4~0.7 | 存入PendingItem，同一事实独立重复采集3次自动转正 |
| <0.4 | 直接丢弃 |

### 3.3 禁止事项（法律第三十四条）
- ❌ 禁止RAG逐句碎片提取
- ❌ 禁止关系称谓写入name列
- ❌ 禁止无人工复核覆盖高置信档案
- ❌ 禁止绕过LLM采集直接写入

## 🔄 四、去重规则（三级）

### 4.1 实体去重
1. UUID精确匹配 → 同一实体
2. 别名模糊匹配（aliases数组）→ 合并
3. LLM语义判断（名字不同但是同一人）→ 标记待确认，人工裁决

### 4.2 关系去重
- source+target+relation三元组去重
- 重复时保留置信度高的，合并evidence

### 4.3 字段去重
- 已有字段不覆盖（卷宗只增不删，法律第十一条）
- 新增字段合并
- 冲突内容存PendingItem，不直接覆盖
