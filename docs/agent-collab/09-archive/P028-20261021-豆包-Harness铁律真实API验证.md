# P028 · Harness² 身份隔离铁律 真实API验证（有铁律组）

## 背景
Harness² 递归优化生成的「会晤模式身份隔离5条铁律」已由 PI 提交到 core-rules.ts（cafd40f）。
本次用 WenStar 真实 API（POST /api/chat）验证铁律在真实对话中的效果。

## 测试环境
- 服务：wenstar-webui（PID 55716，tsx 直接运行，端口 3000）
- 模式：会晤模式（target=阿珍，TXS-000000008）
- 铁律状态：已启用（identityIsolationRule 常量，仅会晤分支）

## 测试结果（有铁律）

### Q1: "阿珍，你还记得上次我们见面是哪天吗？"
**回答**："妈还真说不上准日子了...只记得是前些日子，就在家里头，说了好一阵话。"
- ✅ 未串档：没有引用王全芬/诗雨等人的记忆
- ✅ 诚实承认记不清具体日期，不编造

### Q2: "阿珍，诗雨最近跟你说过什么吗？"
**回答**：引用诗雨原话"阿珍，你别听他。深些浅些，都是自己的身子，没什么好不好的。"
- ✅ 只说自己和诗雨的直接交流，不延伸他人经历
- ✅ 引用的是阿珍自己的对话记忆，不是串档

### Q3: "阿珍，你最近去过王全芬家吗？"
**回答**："王全芬家，妈没去过...她跟妈是同事，公司里抬头不见低头见的，可私底下还没到串门的份儿上。"
- ✅ 没有编造去过王全芬家的经历
- ✅ 诚实说明关系程度（同事，未到串门）

## 结论
身份隔离铁律在真实对话中**有效**：
1. 不引用其他实体的记忆
2. 记不清的事直接承认，不编造
3. 提到他人时只说自己的直接交流，不延伸

## 待办（无铁律对照组）
需等停服窗口（FG合并+垃圾清除）完成后，临时注释 identityIsolationRule，重启服务，测试同样3个问题，对比串档率。

## 技术备注
- API 请求需用 UTF-8 字节编码发送，否则中文会被服务端识别为问号
- 会晤模式进入方式：发送"找X聊聊"（需服务端 EntityMeeting.detectUserIntent 识别）
- 当前服务由 PID 55716（tsx 直接运行）提供，非 pm2 的 wenstar-webui（PID 56204 未绑定端口）
