## 一、模块概述与边界

### 1.1 模块定位

MemSym 呈现层是记忆系统的"用户-facing 界面"，负责把检索到的记忆候选，以**诚实、自然、有温度**的方式呈现给用户。它是**记忆不是原始快照，是经过权重筛选、情绪加权、离线巩固之后的要素子集**这一理念的最终落地。

### 1.2 模块边界

**本模块负责**：
- 概率分发（p_A 判定 → 通路 A / 混合 / 通路 B）
- 证据标签判定（记得 / 印象 / 线索 / 不说）
- OutputGuard 两级校验（断言抽取 + 蕴含验证）
- 强化归因（confirm / engaged / ignored / correct）
- 再巩固处理（用户纠正时生成新版本）
- B → A 降级（用户追问时切到通路 A）

**本模块不负责**：
- 检索与排序（→ M4）
- 写入与巩固（→ M2 / M3）
- 用户主权操作（→ M6）

## 二、核心功能清单

### 2.1 概率分发

| p_A | 呈现模式 | 说明 |
|---|---|---|
| ≥ 0.65 | 通路 A | 诚实回溯，带标签 |
| 0.35–0.65 | 混合 | 以通路 B 为主，允许最多一条带标签的轻量回溯 |
| ≤ 0.35 | 通路 B | 只融元素，不叙述往事 |

**B → A 降级**：通路 B 之后，用户追问"你还记得吗""那次是什么时候"，下一轮强制切到通路 A，并且提高 R1 原文路的权重。

### 2.2 证据标签判定

| 标签 | 证据要求 | 话术示例 |
|---|---|---|
| 「记得」 | 原文仍在（raw_available = 1）、rel ≥ 0.75、未进墓碑 | "记得，那天你说……" |
| 「印象」 | 只有 gist 或 L4 事实，或原文已压缩/遗忘，rel ≥ 0.55 | "我印象里是……细节有点模糊了" |
| 「线索」 | rel 在 [0.35, 0.55)，或只有实体重合 | "好像和小林有关？你再提醒我一下" |
| 不说 | rel < 0.35 | "这个我不太记得了，跟我讲讲？" |

```typescript
export function decideTag(ev: Evidence): RecallTag | null {
  if (ev.lifecycle === 'tombstone') return null;
  if (ev.rawAvailable && ev.rel >= 0.75) return '记得';
  if ((ev.hasGist || ev.hasFact) && ev.rel >= 0.55) return '印象';
  if (ev.rel >= 0.35 || ev.entityOverlap) return '线索';
  return null;
}
```

**设计要点**：遗忘机制和诚实标签自然连通——原文被遗忘后，系统最多只能说"印象"，不会凭空说"记得"。

### 2.3 OutputGuard 两级校验

**第一级：断言抽取**
- 从生成的回复中抽取"往事断言"
- 规则识别"那次 / 上次 / 你说过 / 我们一起"等句式
- 存疑再交给小模型

**第二级：蕴含验证**
- 每条断言与 elementSet 做蕴含判断（NLI 模型或 LLM 判定）
- 通路 A：断言必须被证据蕴含，标签不能高于证据允许的档位
- 通路 B：`hasNovelFactualElements = false`，即不允许出现证据里没有的事实要素

**失败处理**：
1. 先降低标签档位重写
2. 仍然失败就删去该句
3. 记录一次"虚构拦截"指标

### 2.4 强化归因

**五种信号**：

| 信号 | 判定 | 效果 |
|---|---|---|
| used：模型确实用了这条记忆 | 回复与记忆元素的实体或 n-gram 重合超过阈值 | 前提条件，不满足则什么都不做 |
| confirm：用户确认 | "对""是啊"或补充细节 | 通路 A 用 η = 0.15 |
| engaged：用户接话 | 下一轮话题延续，情绪不转负 | A 用 0.09，B 用 0.03（有冷却） |
| ignored：用户转移话题 | 话题切换 | 不强化，只计入曝光次数 |
| correct：用户纠正 | "不是这样""记错了" | 不强化，触发再巩固 |

### 2.5 再巩固处理

- 用户纠正时，生成新版本痕迹（supersedes_id 指向旧版本）
- 旧版本的置信度下调
- 如果涉及 L4 事实，旧事实设置 invalidated_at
- 系统自然地说一句"原来是这样，我记下了"
- 对应 Nader 提出的提取后记忆可修改理论

## 三、技术实现要点

### 3.1 与 v1.0 组件的变化

| v1.0 组件 | v1.1 处理 |
|---|---|
| 要素萃取器 | 离线部分并入 M3 睡眠步骤 7，在线部分保留轻量版 |
| 双通路分发器 | 输出 p_A，增加混合模式 |
| 要素池沙箱 | 不变，元素统一带 source_id 和证据类型 |
| 钙化增益调节器 | 改为强化归因器，统一调用 reinforce() |
| OutputGuard | 增加断言抽取 + 蕴含验证 |

### 3.2 通路 B 习惯化

- 通路 B 曝光惩罚：最近 7 天曝光越多，分数越低
- 防止反复用同一元素（对应习惯化理论）
- 冷却 24h，每日上限 1 次/元素

### 3.3 强化归因的时序

```
用户下一轮输入
  ↓
判断用户回应类型（confirm / engaged / ignored / correct）
  ↓
used 检查：模型上一轮是否真的用了这条记忆？
  ↓
如果 used + confirm → reinforce(c + 0.15)
如果 used + engaged → reinforce(c + 0.09 或 0.03)
如果 used + ignored → 只计曝光，不强化
如果 used + correct → 触发再巩固
  ↓
写 reinforcement_events 遥测
```

## 四、验收标准

### 4.1 功能验收

| 验收项 | 通过标准 |
|---|---|
| 概率分发 | p_A ≥ 0.65 时确实走通路 A，≤ 0.35 时确实走通路 B |
| 混合模式 | 0.35-0.65 时以通路 B 为主，最多 1 条轻量回溯 |
| B → A 降级 | 用户追问"你还记得吗"时，下一轮确实切到通路 A |
| 证据标签 | 原文还在时标"记得"，原文已忘时最多标"印象" |
| OutputGuard 断言抽取 | 测试 20 个含"那次/上次/你说过"的句子，召回率 ≥ 90% |
| OutputGuard 蕴含验证 | 通路 B 回复中不出现证据里没有的事实要素 |
| 强化归因 confirm | 用户说"对"后，巩固度确实增加 0.15（乘以间隔增益） |
| 强化归因 engaged | 用户接话后，巩固度增加 0.09 或 0.03 |
| 强化归因 ignored | 用户转移话题后，巩固度不增加 |
| 再巩固处理 | 用户纠正后，生成新版本，旧版本置信度下调 |

### 4.2 质量验收

| 验收项 | 通过标准 |
|---|---|
| 虚构率 | < 1%（私有评测集） |
| 「记得」准确率 | ≥ 95%（标"记得"的确实有原文证据） |
| 标签校准度 | 各档位标签的实际证据强度与预期一致 |

### 4.3 安全验收

| 验收项 | 通过标准 |
|---|---|
| 墓碑记忆不可见 | tombstone 的记忆不会被呈现 |
| suppressed 记忆通路 B 排除 | 用户说"别再提"的元素不出现在通路 B |
| 通路 B 无叙事 | 通路 B 回复中不出现"那次/上次/你说过"等往事叙事 |

## 五、⚠️ 加固防篡改要求（验收合格后强制执行）

### 5.1 加固时机

**本模块全部验收通过后**，由模块负责人执行加固，加固完成前不得交付给 M6 调用。

### 5.2 加固内容

#### 5.2.1 呈现规则冻结

- 对外只暴露 `MemSymPresenter.present(candidates, queryContext)` 单一入口
- 内部的概率分发、标签判定、OutputGuard、强化归因全部**私有**
- 三档表达模板、证据标签判定表、强化归因规则**冻结**
- 修改阈值（p_A 阈值 / rel 阈值 / η 系数）必须走配置文件

#### 5.2.2 内部代码保护

- 模块核心文件（MemSymPresenter.ts / EvidenceTagger.ts / OutputGuard.ts / ReinforcementAttributor.ts / ReconsolidationHandler.ts）标记为只读
- 提交时强制要求：commit message 中必须包含 `[M5-MemSym-改动说明]`
- 所有阈值（pA_thresholds / tag.remember / tag.impression / eta 系数）只能通过配置文件改，不能硬编码
- 三档表达模板存放在独立目录，修改需走评审

#### 5.2.3 外接部分预留

- 保留以下必要外接点：
  - `onPresentComplete` 钩子：呈现完成后的回调（供审计/统计扩展）
  - `onReinforce` 钩子：强化事件回调（供 M3 巩固扩展）
  - `onGuardBlock` 钩子：守卫拦截事件回调（供监控扩展）
  - 自定义标签规则注册接口：允许其他模块添加自定义证据标签
- 除上述预留外接点外，**模块内部逻辑不允许外部直接修改**

#### 5.2.4 Harness 监管接入

- 模块状态上报到 Harness：虚构率、标签分布、强化次数、再巩固次数
- 每次守卫拦截记录日志
- Harness 定期校验：虚构率是否上升、标签校准度是否下降、强化分布是否异常
- 发现篡改或异常 → 自动告警 + 冻结呈现模块

### 5.3 修改权限

| 操作 | 权限要求 |
|---|---|
| 正常呈现 | 所有模块可用 |
| 阈值参数调整 | 模块负责人 + Harness 备案 |
| 表达模板调整 | 模块负责人 + Harness 备案 |
| 守卫规则修改 | 必须业主授权 + ADR 评审 |
| 强化归因规则修改 | 必须业主授权 + ADR 评审 |
| 内部代码修改 | 必须业主授权，否则视为篡改 |
