## 三、运行时验证救回的两个生产缺陷（测试期未暴露）

**缺陷1：sql.js 数组参数**。`db.run()` 写成 variadic——sql.js 约定是 `run(sql, params数组)`
（与批次1-5同风格）。测试夹具包 better-sqlite3（原生 variadic）⇒ **测试全绿、生产静默错绑**
（WHERE 匹配 0 行、不抛错）⇒ 状态只在内存、每次重启重流转 259 组（幂等失效）。
修正：数组参数 + **夹具改严格 sql.js 约定（变参直接抛错）**，封死该 bug 类。

**缺陷2：强制落盘条件缺 dialogGroups**。repairDataIntegrity 绕过脏计数，落盘条件仅
entityUuid/globalUid/entityGenes——仅流转发生时不触发 export。
修正：补 `(repairResult.dialogGroups ?? 0) > 0`。

**教训**：① 夹具必须与生产**同 API 约定**（宽松夹具=制造假绿）；② 「重启幂等」必须用
真实重启验证，日志成功 ≠ 库里生效（本次靠每次重启读生产库文件才发现）。
