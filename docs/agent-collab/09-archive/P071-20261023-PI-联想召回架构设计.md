# P071 · 全方位召回架构（V2 重写版 · 待业主过目）

> V1（同日早版）把联想召回做窄成"40D 亲密维度召回情感记忆"，业主裁决纠正：
> **DNA+UUID+40D 是全部记忆的写入→存储→召回统一索引体系，重来、全面落实**。
> 本版按业主裁决 + 顶层法规 + 摸底实测重写。

## 一、业主裁决记录（2026-10-23，最高优先）

1. **全方位**：DNA+UUID+40D++ 标签体系是**全部记忆**的统一索引主干（顺藤摸瓜），不只情感类、不只召回精排。重来，全面落实。
2. **32D 作废，以 40D 为准**（DNA 双螺旋白皮书"32D 永久锁定"条款由本裁决更新）。
3. **原则上写入与召回只能走 DNA+UUID+40D 原生体系，不加其它方法**——先摸底原设计系统是否已落地、只是改来改去没起作用（摸底结论见 §三：**属实**）。
4. **凡人名没按 UUID 规则的一律更新**（entity_belong_id 人名→TXS-ID），**留到收尾阶段**。
5. **召回池必须覆盖四库**：砂金(conversations) + 金库(memories) + 黑钻(black_diamond) + 知识库(knowledge_base)。
6. **先验证再写大代码**：40D 查询质量与 DNA 数据先摸清，不埋头盖楼（探针结论见 §四）。
7. 分阶段：候选生成标签化收益最大最对 DNA 藤次之，写入/存储侧对齐最后。

## 三、摸底结论：原设计已落地一半，原生召回路被"改来改去"改残

完整报告：`D:\work\原设计系统摸底报告-20261023.md`。要点：

**写入侧（约 80% 在跑）**：三底座写入在线（DualHelixWriter 挂 persistence-stage），memories.global_uid **100%**、state_spines/ATL 覆盖 **95.6%**。但：
- **A** 语义链口径停在 24D（DualHelixWriter"24D 拆 24 行"），**40D 没进 state_spines**——40D 的现实真源是 `memories.perception_40d`（JSON 列）
- **D** ATL `vine_group_id`（DNA 藤法定载体）**0% 填充**
- **E** `entity_belong_id` 存人名非 TXS-ID（违反户籍法，业主裁决④→收尾统一修）

**召回侧（原生路被架空）**：现行主链 chat→searchV13→retrieveMultiRank **六路并行**（emotion/keyword/spine/locus/entity/work），骨架即原设计。但：
- **B** spine 路（语义链召回）残废：会晤场景整体跳过（P2-A2 防泄漏副作用）、只用 4 维、30 天窗、候选 raw_input 为空
- **C** 五级闸门挂在旧入口 retrieveMemories；**现行主链 retrieveMultiRank 全程 0 闸门**——被绕过
- 关键词/n-gram 掌握候选生成权，40D 只做精排（本任务根因）

**结论：不需要发明新召回方法——修好原生路即复活法定体系。** V1 版 associativeRecallByPerception40D 本质是"在 perception_40d 上补做 spine 路该做的事"，收编进 spine 路，不另立山头。

**三个必须一起治的缺陷**（不治则 top 被噪声淹没）：

3. **平局无 tie-break**：同向量簇按 DNA 根（同刻多视图天然一族）合并为一票，命中后按藤带出多视图——**退化治理与 DNA 藤天然融合**。

## 五、架构设计（修原生路 = 全方位启用）

### 5.1 语义链真源：`memories.perception_40d`（40D 为准）

- 现实与 codec 成熟度均已在此；state_spines 保留为寻址附属/兼容层，**不作为召回真源**（口径 24D，升 40D 或退役列入 Phase 3 裁决）。
- 联想距离 = **语义扇区余弦**：D9-D20（精神内核+圈层人际）+ D33-40（亲密纹理），共 20 维；排除 D1-D8（肉身）、D21-D32（时空环境）等瑶光客观维。
- 需在 PerceptionVector40DCodec 增加 `cosineSimilarity40DSemantic()`（新函数，不动现有 `cosineSimilarity40D`，避免影响既有精排）。

### 5.2 G1 候选源改造：六路并集 + 四库覆盖（候选生成标签化）

retrieveMultiRank 六路升级为**全方位候选生成**：

| 路 | 现状 | 改造 |
|---|---|---|
| **spine（语义链）** | 残废（会晤禁用/4 维/30 天窗） | **重修**：全 40D 语义扇区、全实体（去会晤禁用，改挂 UUIDPoliceFilter）、**无时间窗**（SEMANTIC_ONLY 本无时空绑定）、退化治理（全零向量跳过语义路、同向量簇按 dna_root 合并投票） |
| keyword | 掌握候选生成权 | 降为六路平等一路（保留，"关键词也用模糊+联想发散"——V1 的模糊概念图在此落地） |
| emotion/locus/entity/work | 现状保留 | 不变 |
| **四库覆盖** | 只有金库为主 | spine/keyword 两路的候选源扩为 **conversations + memories + black_diamond + knowledge_base**（统一 UUID 过滤） |

- **收编**：`associativeRecallByPerception40D` 的逻辑并入 spine 路（同一件事），V1 的 retrieval-stage 并行注入点退役（消除旁路）。
- 语义扇区余弦 + 退化治理后，**top 命中按 dna_root_id 藤蔓带出同刻多视图**（顺藤摸瓜第一藤）。

### 5.3 五级闸门挂载（消除旁路，合规硬项）

- 把 `getFiveStageGate()` 从 retrieveMemories 提升为 **retrieveMultiRank 共享出口**：六路并集 = G1 候选 → G2 时空 → G3 衰减 → G4 意图 → G5 话题壁垒 → 输出。
- G1 语义初筛阈值 cosine≥0.3 按语义扇区口径校准。

### 5.4 DUAL_CHAIN 寻址先行（Phase 2，"顺藤摸瓜"完整态）

- **vine_group_id 填充**：写入侧由 dna_root_id/dialog_group_id 映射生成（法规寻址链字段激活）。
- **G4 意图区分接线**：主动回忆触发词（昨天/上次/以前/曾经/记得…）→ 寻址链先行（时间段/藤蔓组/实体过滤，亿→百）→ 语义链在子集内精排。
- 被动闲聊 → SEMANTIC_ONLY（纯语义联想）。

### 5.5 收尾阶段（Phase 3，业主裁决④）

- entity_belong_id 人名→TXS-ID 全量更新（停服改库纪律：停服→改→export 写盘→复验→重启）。
- state_spines 口径处置（升 40D 或退役）最终裁决。
- 三量纲统一（P053 遗留，系统稳定后）。
