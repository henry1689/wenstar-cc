## 一、根因链（PI 实测 + 本方独立重核，结论一致）

1. P088 任务1 给 R1 恢复块加了 `beginMeetingSideEffects(...)` 调用；
2. 该块位于 `if (isGroupSessionEnabled() && !ctx._groupSession)` 创建块内，
   而 **`ctx` 是每请求新建的字面量** ⇒ 该块**每轮都执行**（运行时佐证：`[Gatekeeper]` 日志每轮打出）；
3. 函数内 `this._multiTurns = []`（原 `:476`）变成**每轮清空**轮次记录；
4. 散会轮：入口清空 → `recordTurn` 推 1 条 → `endMeetingSideEffects` 判 `_multiTurns.length >= 2`
   → **1 < 2 恒不满足** ⇒ **多人散会纪要静默丢失**（无 warn、无失败日志）；
5. `_multiParticipants >= 3` 此轮成立（每轮由视图重采）—— **唯一破口是 `_multiTurns`**。

### 🔴 我在 P088 自检里的错误

我在 P098 §一 的五要素自检中对第 4 项写了「`_multiTurns` 语义对吗 ✅ **重启后为空，与 enterMulti 清零一致**」。
**这个判断是错的** —— 我只验了「恢复后值为空」这个**看得见的输出**，没有验证它**是否每轮被重置**这个
**看不见的状态传递**。这与 S4 评审反复强调的教训是同一类：**只验输出不够，必须验状态流**。

## 二、修法（PI §二 方向①）

`beginMeetingSideEffects` 增第4参 `opts?: MeetingBeginOpts`（`{ restoring?: boolean }`）：

- **恢复路径**（chat.ts R1 恢复块）传 `{ restoring: true }` ⇒ **不清 `_multiTurns`**；
- **正常 WAKE/enterMulti 路径**不传 ⇒ **清零语义逐字保留**（新会晤仍从零计轮）。

原则（PI §二）：**进入路径清零语义保留，恢复路径不得清累积。**

**否决了 PI 方向③（改为「仅当空时初始化」）**：那会让正常 WAKE 路径也失去清零语义 ——
上一场会晤残留的 `turns` 会被带进新会晤 ⇒ 纪要轮次虚高，**引入新 bug**。

**未动 `_isFirstTurn` 置位**：该项是 P078 期既有、非本次引入，且 PI 实测「未见于实际回复影响」，
按最小变更原则不动，**留待单独裁决**（是否也要按 restoring 区分）。

## 三、过程中踩到的一个守卫陷阱（建议 PI 也知悉）

修完第一版后 `switch-master.test.ts` 报「找不到 beginMeetingSideEffects」。

我以为是多行签名打断了定位前缀 `'beginMeetingSideEffects(name:'`，改回单行后**仍然失败**。
**真根因**：`methodBody()` 靠**花括号深度**切函数体，且 **`<>` 内的花括号会被忽略**
（所以 `participants?: Array<{...}>` 一直没干扰过）。但我新增的**内联**
`opts?: { restoring?: boolean }` 落在 `<>` **之外** ⇒ 多出一对裸 `{}` ⇒ 提前闭合
⇒ **把签名本身当成了函数体** ⇒ 守卫误报「纪要素材名单未采集」。

**修法**：第4参类型提为 `MeetingBeginOpts` 别名，签名内不再有裸花括号。**守卫测试一字未改**（15 用例全过）。

> **教训登记**：给被「源码断言型测试」守着的函数加参数时，
> **参数类型的书写形式本身就是接口的一部分** —— 内联字面量会被 `methodBody` 的花括号深度误伤。
