## 四、落码过程中查出并当场修掉的 4 个问题

1. **注册表按 domain 作 key（一域一适配器）** —— 高钙路按 `dialog_group` 注册会**静默覆盖 B 链路的
   DialogGroupAdapter**（我写的回归测试当场变红）。解法：**不进注册表**，由会晤链路直接调用适配器；
   新增独立 domain 还得补 `backref.BACKREF_TABLE` 穷举映射（该文件不在豁免内，编辑被回滚），
   代价与收益不成比例 ⇒ 记为 2.3 统一编排的前置条件。
2. **无关键词判据时被误压成「保底 1 条」** —— 该规则本该只在「有判据但无人命中」时生效。
   现为三情形：无判据→取满 limit；有判据有命中→只注入命中者；有判据无命中→保底 1 条。
3. **候选池只按时间近因取 `limit×5`** ⇒「重要但更早」的高钙组进不了池子，相关性门形同虚设
   （实测 recall@3 仅 41.4%）。加**相关性驱动补选**：在全部高钙组上按摘要 LIKE 补到 limit 条。
4. **相关者之间只按近因排** ⇒ 同词组互相挤占。改为**命中强度（Σ 词长）优先**，再近因、再钙分。
