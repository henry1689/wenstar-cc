# 批B-3 · 聊天模式核查结论 + 会晤寻址先行设计

> 业主指令：认真核查聊天模式有几种（疑"混合多会晤"）→ 摸清修复 → 稳定 → 设计 → 批准 → 落实 → 批C

## 一、聊天模式权威矩阵（全代码核查结论）

| # | 模式 | 权威状态源 | 判定/触发 | 权限镜头 | 召回栈 | 判定 |
|---|---|---|---|---|---|---|
| 1 | **normal 私聊** | ctx 无会晤态 | 默认 | ChatPolicy.normal | 主链 retrieveMultiRank 六路 + searchV13 | ✅ 清晰 |
| 2 | **secretary 秘书模式** | `_currentRole='secretary'`（V4.0） | 角色设定（鸿艺私人秘书） | 注入门 ['normal','secretary'] | 同主链 | ✅ 真实存在 |
| 3 | **entity_meeting 单人会晤** | **GroupSession 视图（V2）/ legacy _meeting 回滚双源**（EntityMeeting 状态读方法自动回退，ADR-013 回滚设计） | detectIntent wake 句式（找X聊聊/开会/@X）→ enter | ChatPolicy.meeting（多人态由 `getEntityName()` 回填，权限链完整） | 会晤栈：MeetingOrchestrator 中枢 + MeetingWallAdapter + EntityMem + 联想V1 | ✅ 双轨=设计内（回滚=关 WS_GROUP_V2） |

| 6 | task | 枚举+taskMode 工厂 | **零消费者** | — | — | ⚠️ 死残留 |

**"混合多会晤"判定**：**不是失控混合**——是 ADR-013 设计内的新旧双轨（GroupSession 主 + EntityMeeting 回滚，关 `WS_GROUP_V2=1` 即完整回滚）；四个真实模式判定链完整、权限链完整（多人态 _meetingEntityName 回填验证）；**稳定性已有重证**：P078 端到端五项全过 + P079 30 轮真 LLM 四不变式全过 + P084 结构轨 1000 轮全绿 + 隔离红线零串档。模糊点仅 roleplay/task **两个死枚举残留**（零行为，违"彻底清除"精神）。

## 二、批B-3 实施方案（批准后执行）

### 步骤-1 · ADR-013 Phase 5 退役（业主更正项，本批主轴之一）
- **开关永久化**：`isGroupSessionEnabled` 默认 false→**true**（保留 env 应急刹掣一个周期，待全清后移除）
- **废弃旧状态机读取**：EntityMeeting 状态读方法去 `this._meeting` 回退（只读 GroupSession 视图）；legacy `enter()`/side-effects 路径停用
- **清旧分支**：chat.ts 旧路径分支（P075 实测的"关开关 tag=2"路径）拆除
- **测试同步**：P075 关开关回滚用例转历史存档；旧路径断言删除
- **规模**：EntityMeeting 1,127 行（旧状态机 51 处引用+16 处回滚标记）+ chat.ts 分支 + 测试——分两小批 Harness 执行，每批全量差集+重启验证
- **风险控制**：应急刹掣（env 覆盖）保留至全清验收后才移除——万一线上发现 V2 未覆盖场景可秒级回退

### 步骤0 · 死枚举清理（卫生项，并入本批）
- ChatPolicy：删 `roleplay`/`task` 两个 ChatMode kind + `roleplayMode`/`taskMode` 工厂（零消费者实证）；同步 identity-stability 测试
- **保留 secretary**（真实身份链使用）与 normal/entity_meeting

### 步骤1 · 会晤栈 DUAL_CHAIN 寻址先行接入（本批核心）
现状：主链（retrieveMultiRank）已有 DUAL_CHAIN（批B `766ce12`：G4 意图 + ATL 历史 GlobalUID 扩展候选）；**会晤栈没有**（走 MeetingOrchestrator/EntityMem/联想V1 自有通道——V1 本就全历史 40D 扫描，可达性已满足，缺的是"寻址先行优先序"）。

设计：**在会晤分支 EntityMem 候选组装处注入 DUAL_CHAIN 候选**（镜像主链实现）：
- 触发：`isActiveRecallIntent(message)`（G4 同源正则，复用 FiveStageGate 导出——防口径漂移）
- 取数：ATL `WHERE entity_belong_id IN (会晤白名单) ORDER BY absolute_timestamp DESC LIMIT 200`（**UUID 主线铁约束**：白名单非空才启用，fail-closed）
- 并入：histories→memories（global_uid 关联，双 UUID 守卫 + namespace 排除 + p40 存在性）→ 与联想V1 结果并集去重后进 `_entityMems`（下游 fabrication 过滤/40D 重排/条数配额统一处理）
- **零删减**：只扩候选并集；联想V1（全历史语义扫描）保留为兜底与精排基础
- 文件：`retrieval-stage.ts`（会晤分支一处注入，~25 行）；复用既有 `isActiveRecallIntent`

### 步骤2 · 稳定性验证
- 定向测试（m3/m4/chat）+ 全量基线差集
- 重启后 API 实测：会晤中发"上次我们聊的X"→ 日志见 `DUAL_CHAIN` 注入行 + 实体数=1 防线正常 + 回答正常
- 复核 P078/079/084 四不变式断言脚本可重跑
