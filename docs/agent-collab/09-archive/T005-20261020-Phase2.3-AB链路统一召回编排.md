# T005 · Phase 2.3 — A/B链路统一召回编排

## 一、背景

Phase 2.1（组级生命周期）+ 2.2（钙化接入召回）已双向交叉验证通过（R019）。

当前问题：A链路（高钙组+单条记忆）和B链路（摘要+原文）**独立运行，无统一编排**——
- 高钙组通道未进注册表（一域多适配器问题），由会晤链路直接调用
- 两路召回配额无统一分配，可能重复注入或互相挤占
- lifecycle_state（archived/consolidating）未被召回侧消费

## 二、目标

召回编排器统一调度A/B两路，按场景分配配额，消费lifecycle_state降权，解决「一域多适配器」注册表限制。

## 三、任务分解

### 任务 E：PI — 注册表改造 + lifecycle降权

**E1：注册表「一域多适配器」改造**
- 当前：注册表按domain作key，一域一适配器，高钙路按dialog_group注册会静默覆盖B链路
- 改造：支持一域多适配器，或给高钙路独立domain并补BACKREF_TABLE映射
- 验收：高钙路和DialogGroupAdapter可同时注册，互不覆盖；回归测试覆盖

**E2：lifecycle_state降权消费**
- archived组：召回排序降权（不排除，仍可关键词命中，但优先级降低）
- consolidating组：正常召回（高钙组的标记，不影响）
- active组：正常召回
- 验收：archived组排序权重低于active/consolidating；关键词命中不受影响

**E3（前置）：收口 memory-write-value-guard.test.ts 红测试**
- P016 §三发现1例红（PI在途去重闸门改动所致）
- 2.3开工前必须收口或明确记录豁免

### 任务 F：Claude — retrieval-stage统一编排

**F1：会晤模式配额编排**
- A链路高钙组：40%配额（独立通道，不占memories槽位）
- B链路摘要+原文：40%配额
- 近期记忆（单条memories）：20%配额
- 泛词/无判据查询：降低高钙组权重，更多依赖近期记忆+B链路摘要（P015发现：泛词recall@3仅33%）

**F2：非会晤模式配额编排**
- B链路摘要+原文：60%配额
- A链路钙化：40%配额

**F3：去重与冲突处理**
- 同组被A/B两路同时命中时，去重保留信息更全的版本
- 注入文本前20字去重（现有机制保留）
- 总字符上限：5000（现有MemoryInjector上限）

**F4：配额配置化**
- retrieval-fusion-config.yaml 加会晤/非会晤配额配置
- 默认值可配置，不需改代码

### 任务 G：两人协作 — 回归测试 + 交叉验证

- 新增统一编排回归测试（配额分配/去重/lifecycle降权/泛词兜底）
- 交叉验证：PI验F，Claude验E
- 全量测试通过后提交
