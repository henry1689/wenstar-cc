## 二、P108 设计先行交付（意图层，不落码）

### 2.1 意图定义（MessageIntentKind 扩展）

```ts
type MessageIntentKind = ... | 'startMeeting' | 'adjourn';
// startMeeting / adjourn 均 targets: []（全员/收尾由适配层从 GroupSession 取）
```

| 意图 | 触发域 | 语义 |
|---|---|---|
| `startMeeting` | **仅 `inMeeting && isMulti`**（已激活的群聊中） | 标记本群聊为「开会式」（mode=meeting），供 P107 散会分支强制纪要；targets 空 |
| `adjourn` | **仅 `inMeeting && isMulti`** | 会议性散会：按 mode 分支收尾（chat=普通收尾 / meeting=纪要+存知识库）；收尾链路复用既有 exit（LEAVE + endMeetingSideEffects + 转场重置，P077 已验证），不重复造轮子 |

**触发词表（宁窄勿滥）**：
- `startMeeting`：开个会 / 开个短会 / 开小会 / 开会吧 / 开会了 / 会议开始 / 我们讨论一下 / 讨论一下X / 开始讨论。**疑问守卫**：句尾「了吗/了吗？/如何开」等问状态句不触发（"开会了吗"=询问非指令）；
- `adjourn`（仅会议性结束语，与泛结束语区分）：散会 / 休会 / 结束会议 / 会议结束 / 今天先到这(里) / 先休会。**「再见/拜拜/先这样/不聊了」不入表**（保持既有 exit 语义，普通对话结束零变化）。

### 2.2 判序设计（与任务书 §2.3 的偏差及理由）

任务书字面判序把 adjourn 放 askAll 之后——但既有 exit 正则已含「散会/结束会议」，若 exit 在前，adjourn 永不可达。**实际设计**：

```
adjourn(群聊域) → exit → addParticipant → 点名/switch → wake → startMeeting → askAll → normal
```

- **adjourn 前置 + 域限定**：置于最前但**仅 `inMeeting && isMulti` 生效**——单人会晤/玉瑶态说「散会」照旧走 exit（零回归）；群聊态的会议性结束语优先归 adjourn（P107 mode 分支）；
- 泛结束语（再见/拜拜）不入 adjourn 词表 ⇒ 任何域仍走 exit ⇒ exit 在其余域语义不变；
- **startMeeting 位于 wake 之后**（任务书一致）：「叫X和Y过来开会」被 wake 先拦（进会晤不自动标 meeting，进入后说「开个会」标记——或 P107 自行扩展 wake 携带标记，状态机层裁量）；「我们讨论一下」无召集句式 ⇒ 落到 startMeeting；
- **askAll 位置不变**（wake 后、normal 前）：startMeeting 词表无「复数词×疑问」组合 ⇒ 结构上不与 askAll 抢判（交叉用例见 2.4）。

### 2.3 社团判定接口设计（供 Claude P107 消费）

位置：`src/m4/household/FamilyGraph.ts` 纯读方法（数据源：nodes.social_group_genes，实测 1109/1109 person 全覆盖，值形态单值 `CO01`/`WW` 或规范多值 `A|B`）：

```ts
/** 社团编码列表；缺失/空/异常 → null（fail-closed：无法判定） */
getSocialGroups(entityUuid: string): string[] | null;
/** 同社团判定：两方编码集交集非空 ⇔ 同社团；任一方 null ⇔ false（视为不同社团） */
isSameSocialGroup(uuidA: string, uuidB: string): boolean;
/** 批量：参会者中「与主会人不同社团/无法判定」的成员 UUID（P107 提醒路径用） */
getOutsiders(participantUuids: string[], hostUuid: string): string[];
```

- 解析：`String(v).split('|').map(trim).filter(Boolean)`，空数组归一为 null；
- 一人多社团语义：交集非空即同社团（徐诗雨 CO01 与 徐诗韵 WW = 跨社团实测样本）；
- fail-closed 方向与 FG 户籍管理法一致：**无法判定 ⇒ 不同社团 ⇒ 走提醒+用户授权**（宁严勿放）；
- 性能：FG nodes 常驻内存，uuid→node 复用既有查找，零额外 IO。
