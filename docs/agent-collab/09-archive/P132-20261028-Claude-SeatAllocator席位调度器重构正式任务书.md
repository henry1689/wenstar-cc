## 一、背景与现存问题

### 1.1 业务实测故障现象

业主真实测试多角色群聊会话，复现 6 类高频故障：

| # | 故障症状 | 现象简述 |
|---|---|---|
| 1 | 块内多角色台词 | 单轮输出块同时混入多个人物对白，角色归属错乱 |
| 2 | 跨角色记忆泄漏 | 角色可以读取其他角色的私密对话内容，隐私失效 |
| 3 | 多人点名只响应一人 | 指令同时点名多角色，仅第一个角色应答，其余完全不参与 |
| 4 | 发言人不同步漂移 | 用户没有切换对象，系统自行跳转到其他角色回复，上下文 speakerUuid 与输出角色不匹配 |
| 5 | 结束指令无效 | 用户发送"结束"，会话不会终止，角色继续反问唤醒 |
| 6 | 角色台词互相窜台 | A 角色输出属于 B 角色的私密台词，身份归属标记错误 |

### 1.2 源码实读得到三层技术根因

1. **outputGuard.ts 只做自称检测**，不检测输出块内混入多个角色台词；仅依靠 LLM 自律保证输出格式。
2. **speakerUuid 不同步**：LLM 输出角色昵称与系统内部 speakerUuid 发生错位，持久化时对话归属实体标记 belongEntityUuid 写错，触发 fallback 全局对话读取，造成记忆跨角色泄露。
3. **speakerResolver.ts 点名解析只识别第一个匹配角色**，多角色点名被截断忽略。

**表层 bug 背后是架构范式原罪**：旧会话层是"玉瑶为主、其他人附加"的单主体会话范式。

- 会话永远仅有单个 speakerUuid，一轮输出只设计支持单一发言人；
- 全部在场角色共享同一套上下文，无源头隐私隔离；
- LLM 参与调度决策，可以自主切换发言人、自主新增角色入场；
- 隐式兜底逻辑：无发言人时自动回退玉瑶应答。

仅对现有逻辑打补丁无法根治整套问题，会持续累积技术债务，必须重构会话调度内核。

## 二、重构总体目标

1. 废除多会话模式（private/group/meeting）枚举，全系统只保留唯一「房间会话模型」；业务差异完全由调度器内部状态驱动，不再切换会话类型。
2. 构建独立确定性状态机组件 SeatAllocator，席位变更、隐私可见域、发言令牌分配全部为代码硬计算，LLM 无权修改房间状态、无权派发发言令牌；大模型仅负责拿到令牌后生成角色台词。
3. 建立两层硬隔离：
   - **隐私隔离层**：不在席位白名单的 UUID，源头就不注入本轮对话切片、不推送消息，而不是仅靠后置过滤补救；
   - **发言令牌层**：只有持有令牌的参与者才允许输出对白；旁听角色可见对话，但永远不能获取发言令牌。
4. 完整审计链路，每一次房间状态变更落盘审计日志，支持故障回放、隐私审计、回归测试回放。
5. 强可测：相同输入 + 相同初始房间状态，输出结果稳定可复现；全套单元测试覆盖业务分支。
6. 灰度兼容存量会话：提供旧会话适配器、开关回滚能力，禁止一刀切直接替换。
7. **不改动检索 v11、记忆层 UUID/DNA/40D 体系**；只改造会话状态与上下文组装层。

## 三、模块职责边界（开发必须对齐，禁止跨层越权）

| 模块 | 职责 | 权限红线 |
|---|---|---|
| **SeatAllocator（本次新建）** | 解析控制指令、维护 RoomState 房间状态、计算 visibleUuids 隐私可见集合、计算 permittedSpeakers 授权发言人集合、写入审计日志 | 系统唯一可以修改席位、派发发言令牌的模块；LLM、outputGuard、分发器均不允许直接修改房间状态 |
| **Prompt 组装器** | 读取 SeatAllocator 输出结果；仅加载 visibleUuids 内角色档案、对话切片；根据 permittedSpeakers 渲染 LLM 约束 Prompt | 只读取结果，禁止修改席位与令牌 |
| **LLM 推理引擎** | 仅为令牌列表内角色生成对白文本 | 禁止自主新增角色、自主切换发言人、修改房间业务状态 |
| **outputGuard（下游防线）** | 校验输出 speakerUUID 是否属于本轮 permittedSpeakers；拦截越权输出；P1-A/B-C 格式、自称、括号校验走独立迭代 | 仅拦截非法输出，不分配令牌，不改席位；本迭代只新增合法性校验规则 |
| **消息分发器** | 严格按照 visibleUuids 名单分发消息 | 不能自定义接收对象 |

**铁则**：调度器决定谁能看、谁能说；LLM 只负责轮到角色时说什么。

## 四、术语与数据结构定义

### 4.1 枚举定义

```typescript
type SpeakPolicy = "free" | "point" | "round-robin" | "token-lock";
type SeatKind = "participant" | "auditor";
```

- **free**：自由闲聊，在场参与者按需应答；
- **point**：点名模式，指定一个或多个角色发言；
- **round-robin**：全员轮询应答，对应"大家都知道了吗？"场景；
- **token-lock**：令牌锁会议模式，同一时刻仅一人持有发言令牌；
- **participant（参与者）**：可以被分配发言令牌；
- **auditor（旁听者）**：可见对话，永远不能拿到发言令牌。

### 4.2 核心数据结构

```typescript
interface SeatEntry {
  uuid: string;
  kind: SeatKind;
  enterAt: number;
  allowHistoryBackread: boolean; // 默认false，新入场默认看不到历史对话
}

interface SeatAuditRecord {
  ts: number;
  rawUserCommand: string;
  beforeState: Partial<RoomState>;
  afterState: Partial<RoomState>;
  action: "seat_add" | "seat_remove" | "policy_switch" | "token_assign" | "token_revoke" | "clear_all" | "history_grant";
  remark: string;
}

interface RoomState {
  roomId: string;
  seats: Map<string, SeatEntry>;
  policy: SpeakPolicy;
  targetSpeakers: Set<string>;
  replied: Set<string>;
  tokenHolder?: string;
  host?: string;
  auditLog: SeatAuditRecord[];
  maxAuditLogLen: number;
}

interface AllocResult {
  ok: boolean;
  errorMsg?: string;
  visibleUuids: Set<string>;      // 本轮隐私可见UUID集合
  permittedSpeakers: Set<string>; // 本轮持有发言令牌集合
  policy: SpeakPolicy;
  auditAppend?: SeatAuditRecord;
}
```

### 4.3 隐私硬规则（代码固化，不可配置）

1. 不在 seats 席位内的 UUID：源头不注入本轮对话、不接收消息分发；
2. 新加入席位的角色，allowHistoryBackread=false，默认看不到入场之前历史；必须收到授权指令才加载历史摘要；
3. 角色移出席位，立刻停止接收后续消息；已经读取过的历史保留在角色私有记忆；
4. auditor 旁听角色永远不会分配发言令牌；
5. 房间席位全部清空（present 为空），不自动填充任何默认角色（玉瑶等），房间保持实例，静默等待指令。

### 4.4 指令解析约束

本迭代首期只使用窄正则解析控制指令，不使用 LLM 做意图识别，规避语义幻觉风险。

**支持指令集合**：
- `@XX 进来` / `@XX 进来旁听`
- `@XX 离场` / `@XX 休息`
- `所有人离场`
- `@XX 回答`（point 点名）
- `大家依次回答` / `都知道了吗`（round-robin 轮询）
- `开启会议模式`、`@XX 当主持人`、`交还发言`
- `把之前的记录给@XX看`（授予历史回看）

**口语化变体**（例如"叫 XX 过来聊聊"）不在本迭代范围，后续版本迭代扩展，防止需求范围蔓延。
