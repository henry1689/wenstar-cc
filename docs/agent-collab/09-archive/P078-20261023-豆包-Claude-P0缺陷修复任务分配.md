## 三、任务 2：多人会议纪要静默丢失修复（必须修）

### 缺陷回顾

`EntityMeeting.endMeetingSideEffects` 条件为 `_multiTurns.length>=2 && _multiParticipants.length>=3`：
- _multiTurns：recordTurn 四参从 GroupSession.multi 派生 ✅ 会累积
- _multiParticipants：**只在旧 enterMulti()/enter()自动升级/addParticipant() 写入**——新路径全部不调用 → **恒空数组** → 条件后半段永不满足 → **纪要永不生成**
- _multiMeetingName（纪要名来源）同样恒空字符串

### 修复方案

`beginMeetingSideEffects(name, uuids)` 已带 name/uuids 参数——在该方法内同步维护 `_multiParticipants` / `_multiMeetingName` 作为**纪要素材采集**：
- 类比 recordTurn 采集 _multiTurns，不是状态双写（GroupSession 仍是唯一状态真源）
- `addSessionEntitySideEffect(uuid)` 同步补进 _multiParticipants（需同时补 name，建议签名加参或传 seed）
- Phase 4 清旧代码时这两处素材采集可直接迁移

### 验收

多人会晤（≥3人，多轮）散会后，日志出现"会议结束 → 纪要已生成"，纪要内容非空、参与者正确。
