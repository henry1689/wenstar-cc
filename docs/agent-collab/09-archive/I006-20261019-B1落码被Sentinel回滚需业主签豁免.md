## 二、根因

**Harness Sentinel：无有效写入令牌/豁免时，写入会被回滚（这是治理设计，不是 bug）**。
- 这些文件**没有**任何豁免记录（台账查询：`meeting-recall.ts` / `DialogGroupAdapter.ts` / `fusion.ts` / `types.ts` / `index.ts` / `retrieval-stage.ts` 全部「无记录」）
- 本轮尚未跑 `harness_run_flow` 取令牌 —— 而按流水线设计，**S4.5 的 DS-21 按磁盘现状评分**，代码不先落盘就取不到令牌 ⇒ 典型死锁
- 已知解法（本仓多次实践）：**先由业主签豁免 → 再落码 → flow → 提交**

> 与 `CLAUDE.md` 的 Harness 宪法一致：跳过 S1-S7 的写入必须被拦。本次没有绕过的意图，走的是标准豁免通道。

## 三、⚠️ 一条改进建议（提给 Harness，非本项目改动）

`harness_pre_check` 对 `src/m4/retrieval/meeting-recall.ts` 返回：
```json
{ "blocked": false, "instruction": "✅ 路径不在 Harness 保护区内，可以继续。" }
```
**这句话是误导的**：它只回答了「路径是否在保护区」，没回答「**当前是否有权写入**」。
Agent 照此继续 → 编辑被静默回滚 → 还要多花两轮才定位到 Sentinel。

**建议**：pre_check 增加「写权限」判定（有未过期豁免 / 有匹配未消费令牌 / 否则 blocked=true 并提示签发途径）。
本项属 Harness 自身改动，需另行按 SelfGuard 流程立项，**不在 B1 范围内**。
