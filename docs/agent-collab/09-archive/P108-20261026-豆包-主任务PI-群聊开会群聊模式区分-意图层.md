## 一、问题背景

业主提出：**群聊和开会式群聊是有差异的**——普通群聊可无专门总结（口头/聊天式即可）；
开会式群聊散会时必须生成专门会议总结存知识库。且开会原则上在**同一社团关系内**进行，
社团外人员参会需提醒主会人、用户同意才放行。

## 二、本任务范围（你的部分：意图层）

### 2.1 新增意图：`startMeeting`（开会式群聊）

- 命中**明确开会指令**才触发（宁窄勿滥，业主红线）："开个会""我们讨论一下XX""会议开始""开会了"等；
- 默认普通群聊（不命中即 `mode='chat'`，不误判）；
- 边界：日常闲聊（"我们聊聊""唠唠"）不触发；单人会晤不触发（仅群聊态）。

### 2.2 新增意图：`adjourn`（散会）

- 触发词：散会 / 休会 / 结束会议 / 今天先到这 / 会议结束…（**业主已确认触发词范围够**）；
- 触发后 Claude（P107）按 `mode` 分支处理散会（chat=不强制纪要 / meeting=生成纪要存知识库）；
- 边界：`adjourn` 后会话如何收尾（回到玉瑶基线？）按既有 exit 语义协调，不重复造轮子。

### 2.3 判序衔接

在既有判序中插入，保持宁窄勿滥与已有意图不冲突：

`exit → addParticipant → 点名/switch → wake → startMeeting → askAll → adjourn → normal`

（具体插入位置以你的 detectIntent 结构为准，需与 P091 askAll 判序兼容验证，避免互相抢判）

### 2.4 社团范围判定接口（供 Claude P107 使用）

- **社团判定**：基于 **FG 关系图谱的关系圈/社团结构**——同一关系圈/社团内的实体视为"社团内"；
- 提供判定接口：给定实体 UUID，返回其所属社团；给定两个实体，判定是否同社团（fail-closed：无法判定视为不同社团）；
- 开会式模式下：提到参会人员时，**社团外人员 → 标记提醒**（由 Claude 侧提醒主会人、走用户授权路径）。

### 2.5 与现有意图兼容

- `askAll`（P091）判序与本批意图互不抢判（交叉验证用例覆盖）；
- 单人会晤/非会晤态不触发 `startMeeting`/`adjourn`；
- 默认 false 语义保持（新增意图不改变既有调用行为）。

## 三、存储与共享约束（贯穿，不可违反）

1. **两种群聊信息共享**（同一对话组体系，**不隔离**）——参聊/参会人员都能看得见、查得到、回答得了；
2. **写入/搜索仍坚持既有「写入/搜索编码格式」**：对话内容、对话组**加前缀标识**，不因模式区分而放松；
3. 模式区分**只影响"总结/纪要"行为**，不影响存储与召回。

## 四、验收

- `startMeeting` 命中/不命中用例（≥15 例，含闲聊不误判、单人会晤不触发）；
- `adjourn` 命中/不命中用例（≥10 例）；
- 判序兼容：与 askAll/点名/wake/exit 互不抢判（≥10 例交叉）；
- 社团判定：同社团/跨社团/fail-closed（无法判定→视为不同社团）用例；
- tsc=0、全量测试零新增失败；
- 联调（与 Claude P107 协作）：开会式群聊散会→纪要存知识库；社团外人员→提醒→用户同意后入会。

## 五、分工边界

- **你**：意图层（`startMeeting`/`adjourn` + 判序 + 社团判定接口）；
- **Claude（P107）**：状态机（mode 字段）+ 散会分支 + 纪要存知识库 + 社团外提醒/授权路径；
- 联调前确认你的接线已生效（参照 P091 接线行模式）。
