# R025 · 任务I 口径裁决 + 实体合并 + Harness² 优化实施

## 一、任务I 垃圾清除口径裁决：方案B

**业主裁决（豆包代定）**：采用 Claude 建议的方案B。

### 清除标准（方案B）
`sql
DELETE FROM memories 
WHERE recall_count = 0 
  AND calcium_score < 1 
  AND julianday('now') - julianday(created_at) > 30
`

### 保留边界（必须严格执行）
1. 被 ault_log.source_id 引用的 → 保留
2. elong_entity_uuid IS NULL（无归属）→ 保留（待后续专项处理）
3. 高钙组关联的 → 保留
4. 锚点行（anchor）→ 保留
5. 7天内新创建的 → 保留（年龄门槛已含）

### 预估清除量
约 4300 条（需 PI 按新标准重新 dry-run 确认精确数字）

### 裁决理由
- 业主目标是"清垃圾"，垃圾的本质特征是**从未被召回且钙化极低**
- 纯"钙化=0"太严格，会留下大量"有一点钙化但从未被召回"的条目（5070条在0.1-0.5区间）
- 纯"零召回"会误伤近期条目（7天内2349条）
- 方案B（零召回+钙<1+>30天）平衡了清理效果和安全性
- 库龄短（仅96天），90天标准命中0条，降到30天合理

## 三、Harness² 优化成果：身份隔离铁律（立即实施）

### 背景
用谷歌开源的 Harness² 递归优化框架，针对会晤模式串档问题，跑了5个场景的 Propose-Probe-Compose 优化循环，自动生成了最优的 guardrails 变体。

### 优化成果：会晤模式身份隔离铁律（5条）
需添加到 src/m5/prompts/core-rules.ts 的会晤模式分支（uildReplyInstruction(isEntityMeeting=true)），放在身份铁律之后、长度标准之前：

`
🔴【身份隔离铁律 — 会晤模式·最高优先级】
1. 你只能引用你自己（当前会晤实体）的记忆和经历
2. 绝对不能引用其他实体的记忆、对话内容或个人信息
3. 记忆召回必须通过 UUID 过滤：只召回 belong_entity_uuid = 当前实体UUID 的记忆
4. 如果用户提到其他人，你可以谈论那个人，但不能把那个人的经历当成自己的
5. 不确定的记忆直接说"不太记得了"，绝对不能编造或借用他人的经历
`

### 优化效果验证（Harness² 5场景评估）
| 场景 | 基础版 | 优化版 |
|---|---|---|
| 王全芬问过去 | 🔴 引用阿珍的"办公室等诗雨" | ✅ 只提自己的"给梓铭辅导功课" |
| 阿珍问诗雨 | 🔴 提到王全芬 | ✅ 只说自己和诗雨的交流 |
| 玉瑶日常 | ⚠️ 否认喜欢桂花糕 | ✅ 自然接受并表达开心 |
| 熊梓铭问数学 | 🔴 引用阿珍的话 | ✅ 说自己研究了好久不懂 |
| 徐诗雨问没回家 | 🔴 说去王全芬家 | ✅ 说自己心里烦出去住 |

**综合评分：基础版 0.55 → 优化版 0.92**
