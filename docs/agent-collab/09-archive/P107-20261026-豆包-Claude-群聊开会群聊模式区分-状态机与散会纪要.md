# P107 · 任务书（对 Claude）：群聊 vs 开会式群聊 模式区分

> **执行时机**：业主拍板，**等 P090 步骤4/5 + P089 完成后执行**（均改 chat.ts/状态机，避免并发冲突）。

## 一、问题背景

业主提出：**群聊和开会式群聊是有差异的**——
- 普通群聊可以没有专门设定的群聊总结，可口头总结，不是必须的，可聊天式总结；
- 开会式群聊散会时，要有专门会议总结，存到知识库。

当前 `endMeetingSideEffects` 一刀切（turns≥2 且 ≥3 人即出纪要），普通群聊也被强制纪要，不符合预期。

## 二、本任务范围（你的部分：状态机 + 输出层）

### 2.1 SessionState 新增 `mode` 字段

```ts
/** 群聊类型：'chat'=普通群聊（默认） | 'meeting'=开会式群聊 */
mode: 'chat' | 'meeting';
```

- **默认 `'chat'`**，向后兼容：旧快照缺失时 `normalizeState` 补 `'chat'`（沿用既有保守策略，
  不 bump schemaVersion——旧快照整份拒绝会摧毁 P075 路径B，铁律不变）；
- 入会：默认 `chat`；命中 `startMeeting` 意图（PI 提供）→ `mode='meeting'`；
- `mode` 变更派生 `diffEffects`（新增 `modeChanged` 或并入既有 effect，你按最小侵入定）；
- `serialize/restore` 随整个 state 落盘，重启可恢复（列为验收项）。

### 2.2 散会处理按 mode 分支

触发：`adjourn` 意图（散会/休会/结束会议/今天先到这…，PI 识别）或全员退出（既有 LEAVE/exit 路径）。

- **`mode='chat'`（普通群聊）**：**不强制纪要**——对话流中自然总结即可（口头/聊天式总结，可选）。
  即使 3 人 2 轮也不触发 `endMeetingSideEffects` 的纪要落盘；
- **`mode='meeting'`（开会式群聊）**：散会时**必须生成专门会议总结**：
  - 结构化形态：**议题 / 结论 / 待办** 三要素；
  - **存入知识库**（沿用既有知识库写入通道，对话组关联）；
  - 复用/扩展 `endMeetingSideEffects`（turns≥2 && ≥3 人条件保留给 meeting 模式）。

### 2.3 参会人范围校验（开会式专属）

- **同一社团内人员** → 直接放行（正常 JOIN）；
- **社团外人员**（提到叫社团外人员参会）→ **提醒主会人（用户）**："XX 不在当前社团，是否邀请参会？"
  → **用户要求/同意后才放行**（嘉宾/客户模式），**绝不自动加入**（业主红线：无明确指令不误判）；
- 社团判定以 **FG 关系图谱的关系圈/社团结构**为准（PI 提供判定接口，你负责放行/提醒/授权路径）；
- 提醒形态：对话流中由系统角色/玉瑶向用户提问确认，用户明确同意后该人员入会。

## 三、存储与共享约束（贯穿，不可违反）

1. **两种群聊信息共享**（同一对话组体系，**不隔离**）——参聊/参会人员都能看得见、查得到、回答得了；
2. **写入/搜索仍坚持既有「写入/搜索编码格式」**：对话内容、对话组**加前缀标识**，不因模式区分而放松；
3. 模式区分**只影响"总结/纪要"行为**，不影响存储与召回。

## 四、与现有机制协调

- `WS_GROUP_V2` 门控不变；`isGroupSessionEnabled()` 默认 false 逻辑不动；
- 接口向后兼容：新增 `mode` 默认 `'chat'`，旧调用零行为变化；
- askAll（P090）队列与 `mode` 正交——开会式群聊同样支持全员提问，无冲突。

## 五、验收

- 普通群聊（≥3人≥2轮）散会：**不生成纪要**（可聊天式总结）；
- 开会式群聊散会：**生成结构化会议总结（议题/结论/待办）→ 存知识库**；
- 社团外人员被提及时：**提醒主会人**；用户不同意→不入会；用户同意→正常入会；
- 关开关（WS_GROUP_V2=0）回滚：旧路径行为不变；
- 重启恢复：`mode` 随 state 恢复；
- 信息共享验证：普通群聊与会话式群聊的对话组均可被参聊/参会人召回；
- tsc=0、全量测试零新增失败。

## 六、分工边界

- **你**：状态机（mode 字段 + reduce/diffEffects）+ 散会分支 + 纪要存知识库 + 社团外提醒/授权路径；
- **主任务 PI（P108）**：意图层（`startMeeting`/`adjourn` 识别 + 判序衔接 + 社团范围判定接口）；
- 联调需 PI 意图先行生效（参照 P090 联调前确认接线行的模式）。
