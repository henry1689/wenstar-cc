# P074 - 文档存储治理任务分配

## 一、背景（PI 提出疑义 + 业主确认）

PI 提出：任务书等临时操作文件不应与系统架构文件放在一起。
业主确认：
1. 系统架构文件是**受控保护**的，不能与临时文件混放
2. 临时操作文件只能**另外集中存放**，任务完成后就要**清理**
3. 有长期价值的内容整理成**正式技能文档**，长期存储并被引用成为经验
4. **C 盘不存任何项目文件**，避免爆仓（当前 C 盘仅剩 30MB，紧急！）

## 二、治理原则（基于现有布局，不新建目录）

### 第一层：系统架构文档（受控保护）

利用已有目录，不新建：

| 文档类型 | 目标位置 | 说明 |
|---|---|---|
| ADR 决策记录 | `docs/adr/` | 已有 ADR-001~012，ADR-013 归位 |
| 架构设计 | `docs/architecture/` | M2-M8 设计、数据流、能力审计等 |
| 白皮书/蓝皮书 | `docs/blueprint/` | 已有白皮书3+蓝皮书3 |
| 技术规范 | `docs/architecture/` 或 `docs/blueprint/` | FG 结构规范、prompt 规范等 |
| 变更台账 | `docs/blueprint/` | 已有 V27-V51 变更台账 |
| 系统法律法规 | `data/knowledge-v4/governance/` | 已有，不动 |

**规则**：这些目录的文件受控保护，变更需走正式流程，不随任务删除。

### 第二层：临时操作文件（任务完成后清理）

利用 `docs/agent-collab/` 下已有的分类目录（建了但没用，全堆在 active/）：

```
docs/agent-collab/
├── 01-tasks/       ← 豆包写的任务书（P0xx-豆包-xxx.md）
├── 02-progress/    ← Claude/PI 写的进度报告（P0xx-Claude/PI-xxx.md）
├── 03-issues/      ← 问题记录（bug、阻塞点、风险）
├── 04-reviews/     ← 交叉 review 报告
├── 05-decisions/   ← 业主裁决记录
├── 09-archive/     ← 已完成任务归档（保留30天后自动清理）
└── active/         ← 废弃（避免再次混乱）
```

**规则**：
- 任务书写 `01-tasks/`，进度报告写 `02-progress/`
- 任务完成后，相关文件移入 `09-archive/`
- `09-archive/` 保留 30 天，超期自动清理
- `active/` 废弃，不再使用

### 第三层：经验技能文档（长期存储，被引用）

从任务报告中提炼有长期价值的内容，写成正式文档存入 `docs/architecture/`：

| 经验文档 | 来源 | 价值 |
|---|---|---|
| `tsc-验证铁律.md` | P069/P073 假验证教训 | 验收必须断言退出码，不能只 grep 输出 |
| `git-glob陷阱.md` | P070 推送踩坑 | git 的 * 能匹配 /，与 shell 不同 |
| `令牌编辑配方.md` | 多次踩坑总结 | 一个令牌一次编辑，删完 grep 验活 |
| `IPC协议原子提交.md` | P048/P049 TTS 断语音 | 主进程与 worker 协议变更必须原子提交 |
| `文档存储治理规范.md` | 本任务 | 本文档提炼后的正式规范 |

**规则**：经验文档被系统引用，成为知识库的一部分，不随任务清理。

### 第四层：C 盘铁律

> **所有项目文件、临时文件、缓存、数据库一律存 D 盘。C 盘只放系统文件和必须的应用程序。**

- TEMP/TMP 环境变量指向 `D:	mp`（业主自行安排设置）
- 项目根目录 `D:	ools\wenstar-cc`
- 数据库 `D:	ools\wenstar-cc\data`
- 临时备份 `D:	mp`
- **禁止**在 C 盘创建任何项目相关文件

## 三、任务分配

### 任务 A：整理 docs/ 根目录（Claude 或 PI）

**现状**：docs/ 根目录有 70+ 个 md 文件，系统文档和临时文档混放。

**操作**：
1. 逐个分类 docs/ 根目录的 md 文件
2. 系统文档 → 移入 `docs/architecture/` 或 `docs/blueprint/`
3. 临时文档（任务书、调查报告、postmortem）→ 移入 `docs/agent-collab/09-archive/`
4. 经验文档 → 提炼后存入 `docs/architecture/`
5. 用 `git mv` 移动，保留历史
6. 移动后验证文件内容不变

**注意**：不删除任何文件，只移动位置。

### 任务 B：整理 active/ 97 个文件（Claude 或 PI）

**现状**：active/ 有 97 个文件，任务书+进度报告+review+决策全堆一起。

**操作**：
1. 逐个分类 active/ 的 md 文件
2. 豆包写的任务书 → 移入 `01-tasks/`
3. Claude/PI 写的进度报告 → 移入 `02-progress/`
4. 问题记录 → 移入 `03-issues/`
5. 交叉 review → 移入 `04-reviews/`
6. 业主裁决 → 移入 `05-decisions/`
7. 已完成的任务相关文件 → 移入 `09-archive/`
8. ADR-013 → 移入 `docs/adr/`（归位）
9. 用 `git mv` 移动，保留历史

### 任务 C：加 .gitignore（Claude 或 PI）

**操作**：
1. 在 `.gitignore` 中加入 `docs/agent-collab/`（临时文件不提交远程）
2. 验证：`git status` 中 agent-collab/ 的文件不再显示为未跟踪
3. 已提交的协作区文档（远程历史中的 5+ 份）用新 commit 移除（不重写历史）

### 任务 D：清理 09-archive/ 超期文件（Claude 或 PI）

**操作**：
1. 检查 `09-archive/` 中 50 个文件的修改时间
2. 超过 30 天的文件 → 删除（任务已完成，临时文件无需长期保留）
3. 30 天内的保留
4. 记录删除清单

### 任务 E：写治理规范文档（Claude 或 PI）

**操作**：
1. 将本任务分配提炼为正式规范文档
2. 存入 `docs/architecture/文档存储治理规范.md`
3. 内容包含：三层文档体系、分类规则、清理周期、C 盘铁律、提交规则
4. 被系统引用，成为知识库的一部分

## 四、约束

1. 完成后必须立即同步报告到协作区（常设规则：完成必回传）
2. 不删除任何系统文档，只移动位置
3. 临时文件清理只删 09-archive/ 中超 30 天的
4. 用 `git mv` 移动，保留 git 历史
5. C 盘不创建任何文件，所有操作在 D 盘
6. 有问题或方向不确定，找业主裁决
7. 与 T013 切主任务并行，不冲突（文档整理不碰代码）

## 五、验收判据

1. docs/ 根目录无 md 文件（全部归入子目录）
2. active/ 为空（或废弃）
3. 01-tasks/ 到 05-decisions/ 有对应分类文件
4. ADR-013 在 docs/adr/ 下
5. .gitignore 包含 docs/agent-collab/
6. 09-archive/ 中超 30 天文件已清理
7. docs/architecture/文档存储治理规范.md 已创建
8. 所有操作在 D 盘，C 盘无新增文件

## 六、执行顺序

1. 任务 A（整理根目录）+ 任务 B（整理 active/）并行
2. 任务 C（加 .gitignore）
3. 任务 D（清理 archive）
4. 任务 E（写规范文档）
