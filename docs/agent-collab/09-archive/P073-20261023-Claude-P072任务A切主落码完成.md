| 文件 | 改动 |
|---|---|
| `chat.ts` | 汇聚点取值源 / 四类状态写入 → `gs.dispatch`（WAKE·LEAVE·JOIN·SPEAK）/ 判定与派生改走 `gs.getState()` / 三处 recordTurn 四参 / 重启恢复改由 R1 承担 / **投影调用移除 + 死代码清理** / 订阅前移到 GroupSession 创建点 |

| `process-stages.ts` | recordTurn 调用适配四参 |
| `switch-master.test.ts`（新） | 9 例切主守卫 |

### 关于「严格单写」的选型

业主要求「最彻底、最符合未来结构」，故**未采用**保留 `_em.enter/exit` 调用的省事路径
（那会让 `this._meeting` 成为「仍被写入但无人读取」的死数据，且把门卫/纪要的迁移债务推到 Phase 4 翻倍）。
改为给 EntityMeeting 建**纯副作用入口**，使状态写入唯一化到 `GroupSession.reduce` ——
ADR-013 硬约束② 得到**断言级**落实（见守卫测试第 1、2 例）。
