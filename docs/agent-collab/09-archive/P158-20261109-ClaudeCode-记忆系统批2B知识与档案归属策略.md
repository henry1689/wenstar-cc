# P158 记忆系统统一 · 批2B 知识与档案 + 归属策略单一化

> 任务：`MEM-UNIFY-V1` 批2B（`docs/记忆系统统一任务书-V1.md` §六）
> 业主授权：2026-11-09 会话「确认批2B」
> 结果：**归属判定收敛为 policyFor 单一源；知识检索统一守卫与来源策略；证据层收集器落地；【本地回复】直出删除；memarch fail-closed**。未改数据。

## 一、交付物

### 1. 归属策略单一源

- `UUIDPoliceFilter.policyFor` 新增 `ownerMode`：私有域户主态（无归属历史数据可见）也由本函数产出；
  `allowUnowned` 自此为**派生只读字段**（保留兼容，调用方不再自行决定）。
- 五个手写点全部改调 `policyFor`：
  - `m4/retrieval/adapter.ts` `buildPolicePolicy`（三态分支）
  - `m2/SQLiteAdapter` `_entityUuidClause`
  - `m4/UnifiedSearchEngine` 两处 `policePasses` 策略
  - `webui/chat.ts` 注入边界 `screenContext` 策略
  - `webui/chat/retrieval-stage.ts` 作品指称鉴权
- 守卫测试 `KNOWN_HANDWRITTEN` 清空（私有域欠账清零，新出现的手写点直接失败）。

### 2. 知识检索单一守卫 + 单一来源策略

- `KnowledgeEngine.search`：
  - 有效 UUID = 显式参数 **?? `getSessionEntityUuid()`**（会晤会话策略），SQL 与 post-filter 同源；
  - **空关键词直接返回 `[]`**（旧实现 `SELECT *` 全表返回）；
  - FTS 路径回读 `visible_entity_uuids` + `source_type`，行级 `passes` 生效；
  - 熔断降级 LIKE 补来源谓词；FTS 结果再做行级来源过滤（防旧内存索引残留）；
  - 缓存键改用有效 UUID。
- `KnowledgeEngine.weightedSearch`：空关键词返回 `[]`（旧实现会全表打分）。
- `SourceTypePolicy`：新增 `RETRIEVABLE_WHERE_SQL()` 单源 SQL 谓词；`document` 归入文件类型。
- `FtsSearch`：索引加载改用统一谓词（原 `NOT IN (GARBAGE)` 与加权路的 `IN (FILE+ANALYSIS)` 两套判据合一）。
- `KnowledgeAdapter`：传 `ctx.entityUuids[0]`，接口签名对齐 M2 `KnowledgeBase.search` 四参形态
  （旧五参声明会把 UUID 错位传进 `interactionType`）。
- `visible_entity_uuids` 决策：**启用**（写侧已完整；本次补齐读侧回读），未删除。

### 3. 证据层

- 新增 `src/m4/retrieval/evidence-layer.ts`：
  - `buildEvidencePolicy`（会晤 strict / 户主 ownerMode / 户主钥匙 enforce:false）；
  - `collectEvidenceLayer`（笔记 + 作品 + FG 档案并行收集，`runAdapter` 行级兜底，按 `domain:id` 去重）；
  - `evidenceFragment` 统一注入标签（【作品】/【记事】/【档案】）。
- `createExtendedRegistry` 补注册 `WorkAdapter`（扩展注册表 8→9 域；默认注册表不变，避免与 V13 work 路重复注入）。
- 深度回忆的 `sweepAllStores` 接入按任务书属**批4**；本批交付统一收集器与 owned 语义，批4 直接调用即可。

### 4. D7 与 memarch

- 删除 `KnowledgeContextBuilder` 的 `【本地回复】` 敏感词直出分支（知识统一交 LLM 表达）。
- `memarch-runtime.resolveNamespace`：
  - 新增纯函数 `resolveNamespaceFromMap`；
  - 非空 UUID 全部无法解析 / registry 未就绪 → **返回 `null`（fail-closed）**，不再回落 `ns_yuyao`；
  - `memarchRetrieve` 接受 `string | null`，null 时告警并返回空。
  - 空列表（无活跃实体）仍为本体语义 `ns_yuyao`。

## 三、与任务书的偏差 / 遗留

1. **`search` 与 `weightedSearch` 未合并为同一打分算法**：两档打分服务于不同调用方（FTS 精确标题去重 vs ngram 加权情境召回），本批把「守卫 / 归属 / 来源 / 空查询」合并为单一入口，打分保留两档；彻底合并会改变 18 处调用方排序，留待评估。
2. **证据层只交付收集器**：`sweepAllStores` 扩展属批4（任务书明列）。
3. `chat.ts` / `retrieval-stage.ts` 仅改策略构造与导入，未改召回结构。
4. 全量测试中 `sql-schema-consistency` 的唯一失败指向 `server-memarch-bridge-routes.ts`（存量，非本批）。

## 四、风险与回退

- 归属策略：`buildPolicePolicy` 三态返回值语义与旧实现逐字段等价（ownerMode 仅把 allowUnowned 变成派生值）；若异常可逐文件还原。
- 知识检索：空关键词从「全表」变为「空」，会晤会话 UUID 兜底可能让少数依赖「不过滤」的调用方结果变少（预期内，属安全收紧）。
- memarch：V14 默认关闭，无在线影响；如需回退，恢复 `resolveNamespace` 的 `DEFAULT_NAMESPACE` 回落即可。
- 证据层：新文件，未被主链调用；批4 接入前零行为影响。
