## 一、问题（P010 §四，Claude 交叉验证发现）

7/2088 组锚点是**全等票数**：两实体在组内 `COUNT(*)` 相等且 `MIN(seq_pos)` 也相等
（例：TXS-000000011=2轮/seq1104 与 TXS-000000019=2轮/seq1104）。
原两层判据（`COUNT DESC, MIN(seq_pos) ASC`）下归属**欠定**——谁先被 SQLite 分组扫描到谁赢。
实测当前零翻转纯属侥幸稳定，属判据缺陷（非正确性缺陷）。

## 二、修复（四层全序判据，三处同源）

判据升级为：`COUNT(*) DESC → MIN(seq_pos) ASC → MIN(timestamp) ASC → belong_entity_uuid ASC`
（多数决 → 同数取最早轮 → 全等取组内时间早 → 完全全等取字母序兜底，与扫描顺序彻底无关）

| # | 落点 | 内容 |
|---|---|---|
| 1 | `ANCHOR_REBUILD_GROUPS_SQL`（SQLiteAdapter.ts） | ORDER BY 补第三/四层 |
| 2 | 启动自检 SQL（同文件 `_rebuildMemoryAnchors`） | 同源同步（否则重建新判据/自检旧判据，7 组会被自检误报 ERROR） |
| 3 | `resolveAnchorOwnership`（dialog-group-stage.ts） | 同源同步（3b 确立的同源原则；两处漂移=闭组写一种归属、重启重建写另一种） |
| 4 | `anchor-rebuild-guard.test.ts` +2 例 | 全等票数按 MIN(timestamp) 定归属（精确复刻 P010 形态）；完全全等字母序兜底 + 逆序插入结果一致；另 +2 例防漂移断言（自检 SQL 与 resolveAnchorOwnership 必须带同一套 tie-break 字面） |
| 5 | `cross-entity-anchor-guard.test.ts` X5 升级 | 原断言完整两层字面串被演进打破（守卫失明，经验#21），改为能力断言 |
