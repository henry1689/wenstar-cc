# P069 - PI 完成 P066 任务3 + 任务4（含验证方法坦白）

## ⚠️ 先坦白：PI 历史"tsc=0"是假验证（经验21 重演，主动上报）

**问题**：PI 在 P053/P059/P062/P063 多次声称"tsc=0"，但用的是**坏命令**：
```
node D:/work/scripts/run-guarded.cjs npx tsc --noEmit --pretty false
→ Error: Cannot find module 'D:\tools\wenstar-cc\npx'
```
`run-guarded.cjs` 把 `npx` 当模块脚本路径 → **tsc 从未运行**。而 PI 的验收 grep 过滤模式是 `error TS`，**不匹配 "Cannot find module"** → 报错被静默过滤 → PI 误判为"零错误"。

**后果实证**：PI 的 P062 编辑引入真实类型错误（`parseCatalog` 函数体 push `occurrence` 但返回类型未声明），**假 tsc 验证连续多轮未抓到**，直到 Claude 统一提交（P064）时才暴露 129 行 TS2339、卡住提交。这正是经验21「把未验证的状态当成已验证」的重演。

**根因**：(a) 用 run-guarded 包裹 npx 二进制（run-guarded 设计是包 node 脚本文件）；(b) grep 过滤模式不完备，未覆盖 "Cannot find module"；(c) 未检查命令退出码/是否真执行。

**修正与防线**：
- 唯一可信命令：`timeout N npx tsc --noEmit --pretty false` + 检查 `${PIPESTATUS[0]}`
- 已用真命令复验**当前状态：tsc exit=0、106 测试通过**（本轮实测）
- 教训沉淀：验收必须确认"命令真的执行了"（exit code），不能只看输出行；grep 过滤须覆盖执行失败形态。
