# P072 - 切主落码（方案A）+ PI 全面复验 + 文档清理

## 一、业主裁决（3项）

1. **批准切主方案 A 落码**：状态源单点切换，阻塞点采用 A1（改 recordTurn 签名）
2. **远程历史中他人提交的 5+ 份协作区文档**：参照协作区管理规则进行清理（移入归档或从远程历史中移除）
3. **PI 全面复验 tsc**：之前所有"tsc=0"声明必须用真命令复验，发现问题立即修复

## 二、任务分配

### 任务 A：Claude - 切主落码（方案 A）

**执行人**：Claude Code
**优先级**：P0（最高）
**依据**：P071 切主适配层设计方案 A（业主已批准）

#### 实现要求

**核心**：换状态源，不搬全部职责。状态判定与写入全部改走 GroupSession；EntityMeeting 降级为门卫/纪要副作用执行器 + 轮次采集器。

**四组改动**（详见 P071 §二）：

1. **汇聚点（1 处）**：chat.ts:612 `_activeMeetingName` 改由 GroupSession 派生
2. **状态写入（6 处）**：enter/exit/switchTo/addParticipant → `gs.dispatch`
3. **状态判定/派生（7 处）**：isActive/isMultiParty/getEntityName/getEntityUUID → `gs.getState()`
4. **保留不动（3 处）**：recordTurn（纪要数据源）、inferSpeaker（发言人推断）

**阻塞点 A1：改 recordTurn 签名**
- 现状：`recordTurn(role, content, speakerName?)` 内部依赖 `this._meeting?.isMulti` 和 `this._meeting.entityName`
- 改法：将 isMulti 和 entityName 作为参数传入，或从 GroupSession state 派生后传入
- 确保切主后多人会议纪要不丢失
- 单人会晤本就是 no-op，不受影响

**门卫/纪要接线**：
- 用已有的 `onEffect`，追加 `meetingStarted` → 门卫 startMeeting
- `meetingEnded` → 纪要生成 + 门卫 clearSessionEntities
- 副作用跟随状态变更单一入口

**WS_GROUP_V2 常开**：
- .env 中设置 `WS_GROUP_V2=1`
- 新架构成为唯一真源
- 旧路径一行不删，关开关即回滚

**架构级改动流程**：
- 这是 arch_structural 级改动，必须走完整 S1→S7
- S4 独立评审 + S4.5 收敛 + S6-B 人工验收
- 一个令牌只做一次编辑，删完立刻 grep 验活
- 令牌 content_hash 绑定修改前内容，连续编辑必被 Sentinel 静默回滚

#### 验证要求

- tsc=0（用真命令：`timeout npx tsc --noEmit --pretty false` + 检查退出码，不许用 run-guarded 包 npx）
- 现有测试全绿（137+ 测试）
- 新增切主相关测试
- 单人会晤：进入/退出/恢复现场正常
- 多人会晤：加人/减人/换发言/纪要正常
- 旧数据：切主后旧会晤数据仍可召回
- 回滚：关 WS_GROUP_V2 后旧路径正常工作

#### 完成后

1. 立即同步报告到协作区（常设规则：完成必回传）
2. 通知 PI 开始任务 B（数据迁移验证）和任务 C（压测）
3. 提交 commit 并推送

### 任务 B：PI - 全面复验 tsc（历史所有"tsc=0"声明）

**执行人**：PI Agent
**优先级**：P0
**背景**：PI 在 P053/P059/P062/P063 多次声称"tsc=0"，但用的是坏命令（run-guarded.cjs 把 npx 当模块路径 → tsc 从未运行），grep 过滤不匹配 "Cannot find module" → 误判零错误。P062 真实类型错误连续多轮未抓到。

#### 复验范围

- P053（记忆链路彻查）
- P059（如有）
- P062（V15 编目行号修复）
- P063（处理 Claude 交叉review五问题）
- 以及任何 PI 声称过"tsc=0"的提交

#### 复验方法

- 唯一可信命令：`timeout N npx tsc --noEmit --pretty false`
- 必须检查 `${PIPESTATUS[0]}` 退出码
- 不许用 run-guarded.cjs 包裹 npx
- grep 过滤须覆盖 "Cannot find module"、"error"、"TS" 等所有失败形态
- 验收必须确认"命令真的执行了"（exit code），不能只看输出行

#### 发现问题处理

- 立即修复
- 修复后重新复验
- 记录哪些历史声明是假的、哪些是真的
- 修复 commit 单独提交，不与切主改动混在一起

#### 完成后

1. 立即同步报告到协作区
2. 列出复验结果清单（哪些提交真 tsc=0，哪些有问题已修复）
3. 沉淀教训到经验库
