## 一、根因（I003/I004 实锤）

`_rebuildMemoryAnchors()` 按 `(dialog_group_id, belong_entity_uuid)` 分组 —— 混合组产生多行，但循环内所有行共用同一主键 `id = dg + '_ANCHOR'` + `INSERT OR REPLACE` ⇒ 锚点最终归属 = UUID 字典序最大者（与多数决无关），**每次启动都错写一遍**。

第二缺陷：`perception_40d` 被误分类为「派生列」（`ANCHOR_REBUILD_DERIVED_COLUMNS`），重建时恒写 `encodeEmptyPerceptionV40()`（全零）且 V22 快照回填不恢复它（`_restoreCols = 表列 − 派生列`）。

## 二、修复（防复发四件套）

1. **[修复码] 分组多数决**：分组 SQL 收编为导出常量 `ANCHOR_REBUILD_GROUPS_SQL` —— 每组只返回多数决归属行，判据与 `resolveAnchorOwnership` 完全同源（`COUNT DESC, MIN(seq_pos) ASC LIMIT 1` + is_test）。**测试与生产共用同一 SQL 字符串**（防判据漂移）。
2. **[修复码] 40D 归位**：`perception_40d` 移出 `ANCHOR_REBUILD_DERIVED_COLUMNS` —— 重建时旧行非零 40D 由既有 `_restoreSnap` 快照回填恢复；仅新建组落全零默认。
3. **[回归测试] `anchor-rebuild-guard.test.ts` 10 用例**：混合组多数决（精确反转 I003 场景 DG_11824）/ 同数取最早轮 / 单一组不变性 / 空组宁拒 / 新建组 / is_test 隔离 / 幂等 / 生产同源引用断言 / 40D 列归位。
4. **[运行时自检]** 启动后校验全部锚点归属 == conversations 多数决，错配打 `console.error`；附带非零 40D 计数观测。
