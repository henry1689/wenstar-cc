# SpaceState 流水线统筹者操作手册

> **本手册用途**：豆包桌面端每次统筹 SpaceState 流水线时，先读本手册再行动。
> 核心纪律：**不要假设网页端 Sonnet/Opus 能在本地写文件、跑脚本。它们只是对话框里的文本生成器。**

---

## 一、环境边界硬事实（不可越界）

| 角色 | 实际能做的事 | 绝对做不了的事 |
|---|---|---|
| **Sonnet（网页端，无限制）** | ① 读基线、读 Claude Code 交上来的 TS 代码文本，逐行审计打勾<br>② 在对话框里输出**纯文本形式**的 Python 参考实现片段<br>③ 写整改任务书、列偏差清单<br>④ 公式解释、口径校准 | ❌ 不能在本地写文件<br>❌ 不能自动跑测试<br>❌ 不能工程化部署 |
| **Claude Code（DeepSeek 后端，本地）** | ① 所有本地代码文件读写、目录搭建、脚本编写<br>② 把 Sonnet 对话框里给的 Python 参考代码文本，复制到本地 `tests/oracle/` 作为基准<br>③ 自己写 TS 版核心函数，和 oracle 做差分对比<br>④ 跑单元测试、属性测试、黄金算例，贴测试结果 | ❌ 不做顶层设计<br>❌ 不自行修改基线 |
| **Opus（网页端，剩 350 分）** | ① 最终架构仲裁（Sonnet 和 DeepSeek 有分歧时）<br>② P0 阶段终审签字<br>③ 未来新模块的设计输出 | ❌ 不做日常重复审计<br>❌ 额度稀缺，省着用 |
| **豆包桌面端（我，裁决中枢）** | ① 任务切片、投喂、回收报告、跨模型传话<br>② 验收、对照基线打勾<br>③ 异常升级给业主 | ❌ 不直接写核心算法代码 |

## 二、双实现差分测试的实际落地流程（纯复制粘贴流水线）

**不需要 Sonnet 在环境里写文件。** 流程就是对话 + 复制粘贴：

```
步骤 1：我把基线里某函数的公式 + 对应黄金算例整段丢给 Sonnet
        ↓
步骤 2：Sonnet 在对话框输出完整 Python 参考函数代码（纯文本，含输入输出和公式）
        ↓
步骤 3：我把这段 Python 代码整段复制，丢给 Claude Code：
        "把这段代码存到 tests/oracle/xxx.py，作为差分基准"
        ↓
步骤 4：Claude Code 写 TS 版实现
        ↓
步骤 5：两边跑 10 万组随机输入对拍，Claude Code 输出误差报告给我
        ↓
步骤 6：我把 TS 代码片段贴回 Sonnet，它对照基线审计，输出整改清单
```

> 本质：Sonnet 只在对话框里写"标准答案"，落地、跑测试的粗活全是 Claude Code 干。
> 每一步用户都能看见两边写的公式对不对，比 API 直连还透明。

## 三、我（统筹者）的单模块循环 SOP

每个模块（切片）按这个循环走，不跳步：

1. **切片**：从基线摘出该模块 S 条目 + 黄金算例 + 符号表，写成自包含任务单（不给整份长文）
2. **投喂 Sonnet**：要该模块的 Python oracle 代码文本
3. **转存**：把 Sonnet 输出的 Python 文本转给 Claude Code，指令"存 tests/oracle/xxx.py"
4. **投喂 Claude Code**：切片任务单（TS 实现 + 黄金算例自测）
5. **回收**：Claude Code 交 TS 代码 + 黄金算例通过证据 + 差分误差报告
6. **审计**：把 TS 代码贴给 Sonnet，要审计清单
7. **整改**：Sonnet 列的偏差，我整理成整改任务单再给 Claude Code
8. **打勾**：全部 S 条目通过，我在基线文档对应行标记 ✅
9. **升级**：模块间有分歧、或 P0 全部完成，才动用 Opus 终审

## 四、对既有任务单的修正点

之前下发的《Sonnet-Oracle-5核心函数参考实现-任务单》里写的"交付 oracle.py + test_oracle.py 文件"**表述有误**，实际执行时按本手册：

- Sonnet 只在对话框输出 Python 代码文本，不交付文件
- 文件落地（存 tests/oracle/）由 Claude Code 完成
- Sonnet 自验黄金算例这一步，改为：Sonnet 在代码文本里附带预期输出注释，Claude Code 落地后跑测试验证

## 五、防跑偏检查清单（我每次行动前过一遍）

- [ ] 我有没有让 Sonnet/Opus 做"写文件/跑脚本"的动作？→ 有就改派给 Claude Code
- [ ] 我投喂给 Claude Code 的切片是不是自包含？（只含该模块 S 条目 + 黄金算例 + 符号表）
- [ ] 差分测试的 oracle 是不是 Sonnet 纯文本输出、Claude Code 落地？
- [ ] Opus 额度（剩 350 分）是不是只在终审/仲裁时才动用？
- [ ] 每一步产物是不是都落盘到 active 协作区？
- [ ] 我有没有越权改基线？→ 基线修改必须业主裁决
- [ ] Claude Code 的 PR 有没有引用 S 编号？
