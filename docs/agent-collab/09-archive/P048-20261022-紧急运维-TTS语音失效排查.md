# P048 - 紧急运维：TTS语音失效排查

## 问题现象

业主反馈：聊天端口3000没有语音了。

## 初步排查结果（豆包）

### 服务状态
- 端口3000：✅ 在监听
- wenstar-webui：✅ online，但已重启 71 次，uptime 6h
- harness-mcp：⚠️ 又自己活了（之前stopped，自愈问题复发）

### 日志关键错误
`
[TTS] 段生成失败(重试3次后): tts worker 未回报文件名
[TTS] 第 1 次失败，重试: tts worker 未回报文件名
[TTS] 第 2 次失败，重试: tts worker 未回报文件名
`

**根因方向**：TTS worker 进程没有正常回报生成的音频文件名，导致主进程认为生成失败。

## PI 排查任务

### 1. TTS worker 状态检查
- TTS worker 进程是否在运行？
- worker 进程是否崩溃/重启？
- worker 日志有没有报错？

### 2. TTS 配置检查
- TTS 配置文件是否正确？
- worker 路径、模型路径、输出目录是否存在且可写？
- 最近有没有改动 TTS 相关代码或配置？

### 3. 代码排查
- TTS worker 与主进程的通信机制是什么？（IPC/文件/HTTP？）
- "未回报文件名"是哪个函数抛的？
- worker 生成音频后是否正确写入了输出目录？
- 文件名回报的超时设置是多少？

### 4. 临时修复建议
- 如果是 worker 崩溃，重启 worker
- 如果是配置问题，修正配置
- 如果是代码bug，定位并修复

### 5. 附带问题
- wenstar-webui 重启71次的原因？（是否与TTS失败有关？）
- harness-mcp 自愈复发（pm2-recover.cjs 写死自愈逻辑），是否需要处理？

## 约束
- 这是运维排查，不是 T013 架构重构，优先级高
- 排查过程中不要影响 T013 的开发
- 找到根因后先报告，再决定修复方案
- 修复后验证语音能正常播放

## 要求
1. 完成后自动同步报告到协作区
2. 遇到问题随时写协作区
3. 有争议找业主裁决
