## 我尝试过但回滚的方案（诚实记录）
想做"**供给不足的池释放未用额度，二次填充被裁记忆**"（让稀疏 B 链路的剩余额度兜底给 memories）。
**实现后打破了 3 个既有测试**——recall-quota 的设计**故意**让各类严格按额度、剩余**浪费**（跨类隔离，防一类挤占另一类）。我的重新分配违反这一既定隔离语义。
**已回滚** `recall-quota.ts`（恢复严格配额设计）。

**教训**：配额的"剩余浪费"是**有意的隔离设计**（不是 bug）。要改成"跨类利用剩余"是**配额语义的取舍决策**，需业主/架构层拍板（是否允许稀疏类的剩余额度流向 memories），不该我单方面改打破既定测试。

## 建议（供业主裁决，不阻塞）
