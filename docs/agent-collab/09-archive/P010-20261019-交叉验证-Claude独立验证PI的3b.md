## 四、查出的判据欠定（7 条，非错配，建议补第三判据）

我的独立判据首轮报 **6~7 条与锚点不一致**，而 PI 的自检 SQL 报 **0**。差异逐条查口径后确认：

- 7 条全部是**全等票数**（两实体轮次数相等，且 `MIN(seq_pos)` 也相等）—— 例：某组 `TXS-000000011=2轮/seq1104` 与 `TXS-000000019=2轮/seq1104`
- **锚点当前归属落在并列候选集内**（`错人 = 0`），所以不是错配；两边谁先被 SQLite 扫到谁赢
- 实测**两次重启后归属零翻转**（全集 digest 一致），说明当前实现实际稳定

**性质**：判据在全等票数下**不唯一**（欠定），不是正确性缺陷。当前靠 SQLite 的分组扫描顺序侥幸稳定。
**建议**（不擅自改 PI 的 `SQLiteAdapter.ts`，留给裁决）：补第三层确定性判据，例如
`ORDER BY COUNT(*) DESC, MIN(seq_pos) ASC, MIN(timestamp) ASC, belong_entity_uuid ASC LIMIT 1`，
使重建结果与扫描顺序无关。影响面 7/2088 ≈ 0.3%。
