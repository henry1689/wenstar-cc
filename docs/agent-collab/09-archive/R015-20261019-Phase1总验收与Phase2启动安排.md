## 四、遗留项：7条全等票数判据欠定（Claude P010 §四查出）

**现象**：7/2088条锚点（0.3%）所在对话组，两个实体轮次数相等且MIN(seq_pos)也相等，多数决判据不唯一。当前靠SQLite分组扫描顺序侥幸稳定，两次重启后归属零翻转。

**性质**：不是错配（锚点归属落在并列候选集内），但判据欠定是隐患——未来SQLite版本变化或数据变化可能导致归属翻转。

**豆包判断**：按R012"彻底修好"标准，这个必须补。成本极低（加一个ORDER BY字段），但能消除不确定性。

**修复方案**：在ANCHOR_REBUILD_GROUPS_SQL的ORDER BY后加第三层确定性判据：
ORDER BY COUNT(*) DESC, MIN(seq_pos) ASC, MIN(timestamp) ASC, belong_entity_uuid ASC LIMIT 1

**任务安排**：PI认领（SQLiteAdapter.ts是PI的在途文件，3b刚改过），作为Phase 1收尾项，不阻塞Phase 2启动，但必须在Phase 2开始前补完。

**需要业主确认**：是否同意补这个第三层判据？（豆包建议补，成本低收益高）
