# P140 · 瑶灵主观体感流水线（业主裁决路径一）

## 一、链路设计

```
M3 情绪态/场景 → enqueueYaolingSensation（fire-and-forget, 单飞）
   → publish tianquan_snapshot 情境包（dna_root_id/location_fingerprint/medical_baseline_version/scene_tags/emotion）
   → 瑶灵 wf_sensation_pipeline（原典，40 器官通道，零改动）
   → workflow_result 回包 → 双路仲裁（v1 补位语义）→ 写 perception_40d 的 D01-D08
```

## 二、关键决策（记录在案）

1. **原典零改动**：瑶灵接收闭环已建成（bus_receiver → 流水线 → publish("t","workflow_result")），本实施只补天权侧一段线；
2. **零侵入既有模块**：新模块自建 GlobalBusClient 单例（懒连接），不动 MasterHarris/tianquan-rpc；
3. **v1 仲裁 = 补位语义**（`arbitrateSensation` 纯函数）：**仅填空维**，不覆盖 M3 语义维与瑶光已供值——「瑶灵主观 × 瑶光客观」完整双路仲裁留 v2（待客观值齐备）；
4. **纪律同瑶光队列**：fire-and-forget 不阻塞主链 / 单飞去重 / 不可达静默跳过 / 无区位指纹提前跳过（瑶灵守门必拒）；
5. **量纲合规**：只改"谁供值"，不动 40D 维度定义与扇区（《40D 量纲统一法令》）；
6. **解析防御**：体感包两种形态（dims[40] / d01_d08[8]→扩维），非法一律跳过——**真机首包到达后按实测锁定格式**。

## 三、验证计划

- 单测：仲裁三态（填充/不覆盖/全零不动）+ 解析三态（两形态/非法拒绝）；
- tsc=0 + persistence/chat 回归；
- **真机验证**（重启后）：对话一轮 → 观察 `[YaolingSensation]` 日志（补位维数）→ 查该记忆 perception_40d 的 D01-D08 非零；
- 风险：瑶灵 schema 对 payload 的字段名若与假设不符 → 回包校验失败被静默跳过（不伤主链），按真机首包日志校准。
