## 四、🔴 我踩的一个坑（值得记）

第一次用 `git add "docs/*.md"`（带引号让 git 自己匹配），结果暂存区混入 **101 份协作区文档**。

**根因**：**Git 的 pathspec 里 `*` 默认能匹配 `/`**（与 shell 的 fnmatch FNM_PATHNAME 行为不同）。
带引号的 `"docs/*.md"` 被 bash 原样传给 git，git 匹配时 `docs/agent-collab/active/P066-xxx.md`
也命中了 —— 因为 `*` 跨过了 `agent-collab/active/` 两级目录。

> 教训：**给 git 传 glob 时不要依赖 shell 引号来「转义」** —— 引号阻止了 shell 展开，
> 但 git 自己会展开，且规则不同。**要么让 shell 展开成真实文件名再传，要么用 `:(exclude)` 显式排除。**

处置：发现后立即 `git reset` 撤销（只动 index，**工作树文件完好**，已抽查确认），
改用 **shell for 循环展开真实文件名 + case 显式排除 `docs/agent-collab/*`** 重做，
最终暂存恰好 12 个、协作区 0 误入（ADR-013 单独补 add）。
