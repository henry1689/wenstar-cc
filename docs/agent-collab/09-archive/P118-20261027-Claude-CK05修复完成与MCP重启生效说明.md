## 一、修复内容（harness 仓 commit `cd84742`）

### 为什么必须加第 2 处（申请未提）

锚点原本只认裸参数 `_meetingEntityName`，而 wenstar 已改为：

```ts
const _identity = _resolveIdentity({ isMeeting: !!_meetingEntityName,
                                     speakerName: _meetingEntityName, ... });
ctx.m5.orchestrate(..., _identity.role, _identity.isMeeting, streamOpts, _identity);
```

**实体名仍在传**（`_identity.speakerName`），只是换了载体。原正则恒不匹配 ⇒ 锚点 violation ⇒ hard fail，
会**绕过第 1 处修复**继续卡死。判断依据：`_resolveIdentity` 的入参里明确有 `speakerName: _meetingEntityName`。

### 为什么必须加第 3 处（申请未提）

`ComplianceScorer` 对 CK 的 `warn` **仍扣 15 分**（`CK_WARN_DEDUCTION`），不是只扣 `fail` 的 40 分。
而 probe 格式下 `via` 是**描述性文本**、不必紧邻 probe——实测 wenstar HEAD 的
`L10-主人镜像` 的 via 与 probe 相距 **248 行**，据此报 drift warn ⇒ CK-05 = `warn` ⇒
DS-06 = 85 < `PASS_THRESHOLD` 98 ⇒ **解析修好了照样过不了**。属误报，故跳过。

**未放松的部分**：传播链硬判据 `catalogEntryHasEvidence`（via 全文存在）一字未改。

## 三、🔴 关键运维教训：改了 harness 不重启 MCP = 改了等于没改

这是「bug 仍未修」的**真实原因**——不是代码没改，是**进程里还是旧代码**：

```
10-26 10:58  修改 src/main_harness_checker.ts（commit cd84742）
10-27 01:51  才重启 harness-mcp        ← 此前进程已跑 24.7 小时
```

`mcp/start.cjs` 用 **tsx 直接跑 `mcp/server.ts`（源码）**，每次启动才加载。
而 `main_harness_checker.ts` 经 `ConvergenceGate.ts` → `FlowEngine` 在 MCP 的**依赖链**里。

**给所有会话的判据**：

> 改任何被 `mcp/server.ts` **直接或间接 import** 的文件，都必须 `pm2 restart harness-mcp`，
> 并等端口 `127.0.0.1:8765` 出现 `LISTENING` 再验证（本次实测约 2 分钟后才绑定）。

`dist/` 是 09-16 的陈旧产物，**不参与** MCP 运行路径，但会误导排查（易误判为"旧代码在跑"）。

## 五、给 harness2 的一条设计建议（注入块不该内联进 flow YAML）

排查工作树时发现 `data/flows/wenstaros_core_repair_flow.yaml` 有 +70 行未提交改动，
内容是 `apply-feedback.cjs` 写入的 `HARNESS2_FEEDBACK` 块。

**问题**：块里是**会变的运行时数据**（数据生成时间、运行次数、完成率、告警快照），
却被**内联**进了需要稳定的流程定义文件。后果：

- 每次 harness2 刷新都产生 diff → 工作区长期脏；
- 多人/多会话协作时该文件必冲突；
- 容易被别人 `git add -A` 误卷进提交；
- 而 `data/flows/` 又在 `AUTO_GRANT_NEVER` 内 —— 每次刷新都等于写了一次授权禁改区。

**建议改法**：`apply-feedback.cjs` 不要内联内容，改为**引用**：

```yaml
global_arch_constraint: |
  ...固定铁律 1-N...
  # 🔴 监管反馈：运行时见 data/harness2/feedback_memo.md（由每阶段 memo 注入读取）
```

反馈数据留在它自己的 `data/harness2/`（本就是独立目录），YAML 永远稳定、可入库。
这样「注入」这件事就不需要碰流程定义了。

> 本次我**没有提交**这 70 行改动（运行时产物不该入库），也没有改动 harness2 —— 交豆包判断。
