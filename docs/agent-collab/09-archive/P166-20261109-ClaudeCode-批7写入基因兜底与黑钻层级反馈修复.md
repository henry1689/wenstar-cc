## 一、修复内容

### 1. 写入 genes 结构化兜底

- `src/m2/memory-identity.ts`：移除 `missing_entity_genes` 硬拒写。
- `src/m2/SQLiteAdapter.ts`：
  - 新增可插拔 `setBelongNameResolver`（m2 不反向依赖 m4）；
  - `writeMemory` 在字段校验前，对非 roleplay / 非 note / 非 knowledge_vault 的空 `entityGenes`，按 **belong_entity_uuid** 解析实体名并合成
    `{name,uuid,type:'person',allele,phenotype:'neutral',knowledge_type:'family'}`；
  - 解析不到 ⇒ 告警后放行（宁可留告警，不可丢记忆）。
- `src/webui/server.ts`：装配时注册 `familyGraph.getEntityByUUID(uuid)?.name`。

### 2. 黑钻层级与反馈

- `src/m4/recall/recall-bus.ts`：`金库黑钻` → **diamond**（此前被 `/金库/` 归 gold）；`【档案】/【记事】` → other。
- `src/m4/retrieval/meeting-recall.ts`：
  - `SweptFragment` / `OrganizedFragment` 增 `backref`；
  - sweep 去重由 Set 改为 Map + **来源优先级升级**（金库黑钻 > 知识/作品 > 砂金/档案/记事 > 对话原文），同文不再被来源砂金挤掉；
  - memories / black_diamond / knowledge_base 查询透传 `id` 作为 backref。
- `src/webui/chat/retrieval-stage.ts`：
  - 会晤分支收集 backref 并立即 `applyRecallFeedback`（该分支在统一反馈点之前 return）；
  - 普通分支把 backref 汇入出口统一反馈。

### 3. 测试

- `memory-identity` / `memory-write-required-fields`：空 genes 放行 + 有 resolver 时合成。
- `sweep-organize`：backref 透传、同文升级为金库黑钻。
- `recall-bus`：金库黑钻→diamond、档案/记事→other。
- `recall-bus-wiring`：两分支 backref 收集守卫。
