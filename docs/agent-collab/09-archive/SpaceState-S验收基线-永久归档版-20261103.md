# SpaceState 时空机标准验收基线（永久归档版）

> 共 140+ 条：P0 阶段约 60 条，覆盖全部数学内核、不变量红线和工程架构；P1 至 P3 及系统平衡约 80 条；外加 13 组黄金算例。
>
> **三条前置说明**：
> 1. v3.1 本身有错：编写黄金算例时逐个核算公式，发现 v3.1 有 3 处数学表述错误、1 处参考代码 bug，另有十几处口径没写死。"σ 增大，证据单调不增"这条红线按原样执行在数学上是错的——σ 增大时，失配维度的证据会向 0 回升。全部列在第二章，冻结基线前必须确认。
> 2. 本清单写法偏向防翻译偏差：DeepSeek 最容易出错的是把公式"翻译"成代码那一步，第三章单独给出符号、代码、单位三者对照表和常见陷阱清单。
> 3. 系统平衡单独成章：单条公式正确不等于整个系统协调，第八章把参数耦合关系、调参顺序和平衡指标写成可验收条目。

## 〇、验收从哪些层面看

一套实现要等同于设计，需要依次通过五个层面。任何一层没过，后面的层都没有意义。

| 层面 | 回答的问题 | 手段 | 针对的顾虑 |
|---|---|---|---|
| L1 规约一致 | 代码里写的公式是不是设计的公式 | 符号对照表、静态审查、配置 schema 校验 | 多模型对设计的理解不一致 |
| L2 数值正确 | 算出来的数对不对 | 黄金算例；双实现差分测试：Sonnet 独立编写参考实现，与 DeepSeek 实现用随机输入逐条对比 | DeepSeek 的公式翻译偏差 |
| L3 性质不变 | 任意输入下，红线是否守住 | 属性测试（fast-check，固定种子，≥10⁴ 组随机输入） | 局部正确、边界失守 |
| L4 系统协调 | 各模块参数组合后行为是否合理 | 耦合校验器、加速时间仿真（30 年压缩到分钟级）、因子消融 | 单测全过但整体失衡 |
| L5 长期稳定 | 运行几个月几年后会不会慢慢偏离 | 黄金轨迹每晚重放、分布漂移指标 PSI、配置指纹、线上不变量抽检 | 动力学行为缓慢偏移 |

**执行纪律（适用于全部条目）**：

1. 每个 PR 必须在描述里引用它实现或影响的 S 编号；没有编号的改动不予合并。
2. 交给 DeepSeek 开发时按模块切片投喂，每次只给该模块相关的 S 条目、对应黄金算例和第三章符号表，不要给整份设计长文。
3. 参考实现（oracle）由 Sonnet 只根据本基线编写，不看 DeepSeek 的代码，两边独立实现、交叉对比。
4. 本基线和设计文档冲突时，以本基线为准；基线本身的修改必须经业主裁决。

## 二、勘误与补定（冻结基线前必须确认）

标 ⚖️ 的是本基线新补的规定，需要业主确认；其余是纠正错误，直接生效。

| 编号 | 原表述 | 问题 | 本基线规定 |
|---|---|---|---|
| E-01 | 精度编码 16·log2(π)+偏移，范围 1/400～400 | 码值范围约 277，超出 uint8 | k = clamp(round(128 + 14.75·log2 π), 1, 255)，π=0 时 k=0（见 S-005） |
| E-02 | "σ 增大，证据分单调不增"（简报红线） | 只对匹配情形成立。失配时 ℓ<0，σ 增大会使 ℓ 回升到 0 | 拆成三条：匹配情形单调不增；σ→∞ 时 ℓ→0；\|ℓ\| 随模糊程度收敛（见 S-061） |
| E-03 | 属性测试"把维度置为未知，E 不增加" | 该维 ℓ<0 时，置为未知后 E 反而上升 | 改为：置为未知后，E 恰好减少 m_L·w_s·w_i·ℓ_i（见 S-060） |
| E-04 | 参考代码 px = sx2>0 ? 1/sx2 : 0 | sx2=0 本意是"无限精确"，代码却把它当成"未知" | 接口一律传精度 π，不传方差；π=0 才表示未知，σ 有下限（见 S-011） |
| E-05 ⚖️ | 用途掩码表只有 6 层 | 缺少第Ⅴ层关系场 | 层组定为 7 个：body / core / appraisal / motive / relation / scene / dyad；relation 默认掩码见 S-018 |

### 3.1 符号、代码名与单位

| 符号 | 代码名 | 单位 / 值域 | 说明 |

| v | v | 单极 [0,1]，双极 [-1,1] | 维度值 |
| π | pi | 1/方差，[0, 400] | 0 = 未知，接口只传 π |

| ℓ_i | ell | [-3, 3] | 先截断，再乘权重 |
| E_L, E | layerE, totalE | 对数似然 | 按固定顺序求和 |

### 3.2 必查的转化陷阱（Sonnet 审计逐项打勾）

1. 把 σ、σ² 和 π 混用。公式里的 σq² + v 是方差相加，不能写成 σ 相加。
2. OU 预测协方差用的是 exp(−2Δt/τ)，不是 exp(−Δt/τ)。
3. z 的分母是方差之和再开方：sqrt(s² + σ_S² + s_min²)。
4. 收缩用精度加权：(πx·x + π0·μ)/(πx + π0)，不能用 σ 加权。
5. Birge 公式里的 G 是模态组的数量，不是读数条数。
6. ℓ 先截断到 [−3, 3]，再乘权重，顺序不能反。
7. 时间单位要显式转换：毫秒转天除以 86400000，毫秒转分钟除以 60000。
8. sigmoid 必须用数值稳定写法，E 很大或很小时不能出现 NaN。
9. 全部计算用 float64，核心代码禁止出现 Float32Array；int8 只用在存储层。
10. 舍入规则见 E-11。
11. 求和顺序固定：按层、按主体、按维度编号升序；并列时按 imprint_id 字典序排。
12. log 的参数必须 ≥ 1e-12，除法的分母必须先校验，逐项列在 S-056。
