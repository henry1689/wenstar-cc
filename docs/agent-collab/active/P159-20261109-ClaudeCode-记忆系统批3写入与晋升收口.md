# P159 记忆系统统一 · 批3 写入与晋升收口 + 编码强制

> 任务：`MEM-UNIFY-V1` 批3（`docs/记忆系统统一任务书-V1.md` §六）
> 业主授权：2026-11-09 会话「确认批3」
> 结果：**同一轮只写一次；去重键统一；晋升单向门以 active 为判据；语义块强制字段与健康计数落地；记事强制归属；vault_log 退出召回**。未改数据。

## 一、交付物

### 1. 写入一次（D2）

- `m9/WorkingMemory`：`push` 增 `persistEvents` 选项（默认 true 保既有单测），`server.ts` 装配 `persistEvents:false`
  → 对话轮不再产生 `evt_*` 重复副本（同一轮由 persistence-stage 写 `mem_*`）。
- 删除「砂金→金库」1:1 复制：
  - `MemoryAssessor`：移除 `sandToGold` 调度；执行体默认关闭（`MEM_SAND_TO_GOLD_LEGACY=true` 可应急回开）。
  - `SleepTimeConsolidator`：`_promoteSandToGold` 默认关闭（同一环境开关）。
- 合并重复黑钻晋升：`SleepTimeConsolidator._promoteGoldToDiamond` 默认关闭（`MEM_GOLD_TO_DIAMOND_LEGACY`），
  唯一晋升路径 = `VaultManager`（资格判定 + active 去重 + 合并 + 单向门）。

### 2. 去重键统一

- 新增 `src/m2/memory-identity.ts`：`normalizeMemoryText`（NFKC + 零宽清理 + 空白折叠）、
  `deriveMemoryRole`（user/assistant/note/dialog/roleplay/knowledge_vault）、`buildDedupeKey`、
  `validateMemoryWriteFields`。
- `SQLiteAdapter._isDuplicateNewWrite` 改为 **(belong_uuid, role, normalized_text)**：
  - user 与 assistant 仍互不拦截（保留 2026-10-30 裁决）；
  - 同角色跨 taxonomy zone（language/emotion/social…）同文即重复；
  - `write()` 与 `writeMemory()` 共用。

### 3. 晋升单向门 + 黑钻上限

- `findDuplicateDiamond` 只匹配 `COALESCE(status,'active')='active'`。
- `addBlackDiamond`：INSERT 显式 `status='active'`；`promoted_to_diamond=1` 移到 INSERT 之后，
  且必须 `EXISTS(active 黑钻)` 才置位。
- 合并路径：目标黑钻必须 active（复核），置位同样带 EXISTS。
- 上限：`if` 改 `while` 逐枚归档（步数上限 64）；**先归档黑钻，再按「是否仍有 active」清源记忆状态**。
- 删除黑钻：先 DELETE，再仅在无其它 active 黑钻时清位。

### 4. 强制字段 + 健康报告

- `writeMemory` 写前 `validateMemoryWriteFields`：
  - `belong_entity_uuid` 必填 + 格式 `TXS-\d{6,}`；生产由 server 注册 FG 存在性校验器（`getEntityByUUID`）；
  - `dna_root_id` 缺失 → 从 `dialogGroupId → threadId` 派生，仍无 → 拒写；
  - `entity_genes` 空 → 拒写（roleplay 豁免）；
  - source 锚点（`sourceConversationIds` 或 `dialogGroupId`）缺失 → 拒写；
  - `perception_40d` 缺失 → 拒写；
  - note（记事）与 knowledge_vault（证据文档）按任务书豁免；knowledge_vault 保留 unowned；
  - `global_uid` 缺省派生改为从 `dna_root_id ?? id`。
- `FusionStorageAdapter.write`：无归属直接拒写（`missing_belong`）。
- 健康计数：`getMemoryWriteHealth()`（累计拒写 / 原因分布），`_resetMemoryWriteHealthForTest()`。
- `YuyaoMemoryService`：三个写入口归属为空即拒写（`setReminder` 返回 `NoteMemory | null`），旧记事不再被误作废。

### 5. D3：vault_log 退出记忆召回

- `VaultAdapter` 两条查询均限定 `operation='auto_induct'`（事实锚点）；`promote/landmark` 仅审计。
- 写入侧 `logVaultOperation` 与 `persistence-stage` 的 auto_induct 保持不变。

## 三、与任务书的偏差 / 遗留

1. **存量数据未动**：665 条「已晋升但无 active 黑钻」、95 条反向不一致、894 条 active 超限、988 组重复 —— 属**批6 数据治理**；本批只保证新写入不再产生。
2. 「晋升只用于多轮派生摘要（带 derived_from）」：本批只删除 1:1 复制；派生摘要晋升结构留待后续批次。
3. `_promoteSandToGold` / `_promoteGoldToDiamond` 函数体保留（默认关闭），按「只删调度不删公共能力」的稳妥口径，批6 清理。
4. 去重文本归一为 NFKC + 空白折叠（不做相似度）；SQL 侧按 `TRIM(raw_input)` 比对，历史多空格变体可能漏判 —— 不影响新数据。

## 四、风险与回退

- 强制字段拒写：若某调用方漏传字段，写入会失败并计入健康报告（fail-closed，符合任务书）；`note` / `knowledge_vault` 已豁免。
- FG 归属校验器未注册时只做格式校验（测试/离线环境不受影响）。
- 应急回开旧复制路径：`MEM_SAND_TO_GOLD_LEGACY=true` / `MEM_GOLD_TO_DIAMOND_LEGACY=true`（仅排障）。
- 逐文件 git checkout 可完全还原；无 schema/数据迁移。
