## 一、交付物

### 1. 深度收集扩容（`src/m4/retrieval/meeting-recall.ts`）

- `sweepAllStores` 收集仓：砂金（排除 note）→ **黑钻 active** → 知识（自有 + 无归属共享，D5）→ **对话原文**；
  证据层（FG 档案 / 作品 / 记事）由 `collectDeepEvidenceFragments` 收集后并入同一整编包。
- **D3 对齐**：不再读 `vault_log`（审计台账）。
- **取消硬顶**：`maxFrags=12` → `maxChars=6000` 字符预算 + 安全条数 48；每条 `110 字` → `perFragmentChars=400`。
- `organizeForQuestion`：命中密度排序后按字符预算装包；预算满时跳过该条继续找高分短片，不静默截断。
- 知识可检索谓词由调用方传 `SourceTypePolicy.RETRIEVABLE_WHERE_SQL()`（唯一来源策略，D6 隔离区不入包）；
  `visible_entity_uuids` 行级可见性在收集时复核。

### 2. 主动回忆（新增 `src/m4/recall/proactive-trigger.ts` + `src/webui/chat/proactive-stage.ts`）

- 五类信号：**节日 / 纪念日 / 情绪 / 日常 / 话题关联**；纯规则、零 LLM、零副作用，只产结构化信号。
- 节日：懒加载 `CalendarEngine.getFestivals`（唯一节日真源，按自然日缓存；不另建节日表）。
- 纪念日：只读 `memories`，条件 = 同月同日 + 往年 + 钙化≥3 或地标；`vault_log` 不参与（D3）。
- 指令文案：`MEMORY_LAW_DUTY / TRIO / FUTURE` 单源组装；无信号不注入空块。
- 配置：`proactive` 段（五类开关 / `min_weight` / 纪念日阈值）。

### 3. 分支接线（`src/webui/chat/retrieval-stage.ts`）

- **会晤**：通路判定改 `applyProactiveToPath(classifyMemSymPath(...), triggers)`（纪念日/话题关联升 A）；
  深度素材包并入证据层；日志 `[Proactive] meeting` / `[DeepSweep] meeting`。
- **普通（玉瑶）**：话题切换或主动触发时执行同一收集链，注入深度素材包 + `CRYSTAL_DIRECTIVE`（此前完全没有）；
  总线模式 `deep`（话题切换）/ `proactive`（仅主动触发）/ `standard`；主动指令在总线**之后**注入，不占记忆名额。
- 新增 `src/webui/chat/deep-recall-stage.ts`：配置→收集参数、证据层并入、统一抬头（避免两分支文案漂移）。

### 4. 总线与通路

- `recall-bus.ts`：`【深度回忆素材包/结晶表达/回忆表达三档/默契元素/主动回忆】` 归 `other`，不占三层名额。
- `memsym-path-router.ts`：新增 `applyProactiveToPath`（只升不降；节日/情绪/日常维持原判，避免闲聊乱加"印象里"）。

### 5. 配置

- `src/config/retrieval-fusion-config.ts` + `config/retrieval-fusion.config.yaml`：
  `deep_sweep`（各仓候选额度 / 单条字符 / 总字符 / 安全上限 / 共享知识 / 对话原文 / 证据层）、
  `proactive`（五类开关 / 阈值 / 纪念日钙化门槛）；均逐层深合并，yaml 缺段不丢另一段。

## 三、与任务书的偏差 / 遗留

1. **"按要素集打包"** 实现为「按关键词命中密度排序 + 字符预算装包」；未引入向量分（40D 重排在召回总线/闸门层，避免双份打分）。
2. **主动触发** 的"纪念日"以 `memories` 同月同日为判据（事件日期未单独建模），属近似；若后续有独立纪念日实体，替换数据源即可。
3. **憧憬/三重奏出现率 ≥ 80%** 属行为验收，需批5 真机压测统计；本批只保证每轮记忆回合都有法源指令在场。
4. `per_kw` 候选额度仍是每词上限（整编前），注入总量由 `max_chars` 决定 —— 符合"收集最大化、限额降级为排序权重"。
