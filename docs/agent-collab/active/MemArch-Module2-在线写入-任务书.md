## 一、模块概述与边界

### 1.1 模块定位

在线写入模块负责**每一条新消息进来后，在用户感知延迟内（≤30ms）完成的所有轻量编码工作**。它是记忆系统的"入口闸门"，决定什么值得记住、什么先记着、什么直接扔。

### 1.2 模块边界

**本模块负责**：
- L1 原文同步落盘（永远第一步）
- 事件分割器（判断是否切分 episode）
- 工作记忆缓冲（重写版，持久化、互斥、崩溃恢复）
- 三岔门控（WRITE / RAW_ONLY / DISCARD）
- 在线显著性快速计算（规则版，非 LLM）
- 前瞻记忆在线抽取（"答应/提醒/下周"等）

**本模块不负责**：
- 精确显著性打分（→ M3 睡眠步骤 3）
- 巩固度计算与更新（→ M3 睡眠步骤 4-5）
- 记忆检索（→ M4）
- 记忆呈现与守卫（→ M5）

## 二、核心功能清单

### 2.1 写入时序（8 步）

```
① 消息到达
② L1 原文同步落盘（conversations，带 ts_utc / namespace / episode_id）
③ L0 编码：DNA / 感知 24D→40D / 实体 / 在线显著性
④ 写入 wm_buffer（持久化，崩溃可恢复）
⑤ 事件分割器：判断是否切分 episode
⑥ 三岔门控判定
⑦ 前瞻记忆抽取
⑧ 重要度累计（可选微反思触发）
```

### 2.2 事件分割器

**边界分数公式**：
```
E = 0.4 · (1 - cos(e⃗ₜ, ē_win))
  + 0.25 · min(1, gap / 30min)
  + 0.2 · |Δa|
  + 0.15 · cue
```

**切分条件**（任一满足即切分）：
- E ≥ 0.55
- 时间间隔超过 120 分钟
- episode 超过 40 轮

**输入特征**：
- `e⃗ₜ`：当前消息语义向量
- `ē_win`：最近 3 轮语义向量均值
- `gap`：距上一条消息的时间间隔
- `Δa`：情绪唤醒度变化
- `cue`：是否有显式转场词（"对了""换个话题""说起来"）

### 2.3 工作记忆缓冲（重写版）

**修复旧版问题**：
- 旧版：强制毕业（不管重要不重要都写金库）→ 新版：三岔门控
- 旧版：并发重入 → 新版：互斥锁 flushing 标志
- 旧版：崩溃丢失 → 新版：wm_buffer 持久化表，启动时 recover()

**核心接口**：
```typescript
class WorkingMemory {
  // 进程启动时恢复未处理条目
  async recover(): Promise<void>;
  
  // 推入一条新编码条目，返回门控结果
  async push(entry: WorkingEntry): Promise<Gate>;
  
  // 定时清理已完成条目（互斥）
  async sweep(): Promise<void>;
}
```

### 2.4 三岔门控

| 门控结果 | 触发条件 | 后续动作 |
|---|---|---|
| WRITE | salience ≥ 0.45 且有意义实体 | 写 L3 痕迹（c₀ = 0.6·S），异步生成语义向量 |
| RAW_ONLY | salience < 0.45 或无有意义实体 | 不建痕迹，挂在 episode 上，等睡眠期复评 |
| DISCARD | namespace='test' 或纯元话语/寒暄 | 不建痕迹（原文仍在 L1） |

**在线显著性快速计算**（规则版，非 LLM）：
```
S = 0.30 · imp_rule + 0.25 · self_rule + 0.20 · arousal + 0.15 · nov_rule + 0.10 · ent
```
- `imp_rule`：是否包含计划/决定/首次/身体或情绪事件（关键词匹配）
- `self_rule`：是否出现第一人称经历、关系词
- `arousal`：沿用 PerceptionState 的 VAD 输出
- `nov_rule`：与近 30 天痕迹的最大余弦相似度反向（快速近似）
- `ent`：是否有有意义实体（沿用 hasMeaningfulEntity）

### 2.5 前瞻记忆在线抽取

识别以下模式并写入 prospective_items：
- 承诺类："我答应你""我会记得""下次一定"
- 提醒类："别忘了""记得提醒我""到时候说一声"
- 时间类："下周""下个月""纪念日""生日"
- 计划类："我们要去""约好""计划着"

## 三、技术实现要点

### 3.1 写入顺序红线（P1 原则）

**原文先落盘，痕迹后建立**：
- 第②步必须同步完成，不能异步
- 即使后面所有步骤都失败，原文也已经在 L1 了
- 崩溃恢复时，优先恢复未处理的 wm_buffer 条目

### 3.2 性能约束

| 指标 | 目标 | 降级方案 |
|---|---|---|
| 在线写入总延迟 | ≤ 30ms | 语义向量生成异步化 |
| 事件分割器计算 | ≤ 10ms | 无向量时跳过语义项，只用 gap + cue |
| 门控判定 | ≤ 5ms | 纯规则计算 |

### 3.3 幂等设计

- 每条消息有唯一 message_id
- 写入 L3 痕迹时以 message_id 为幂等键
- 重复推送同一条消息不会产生重复痕迹

### 3.4 并发安全

- WorkingMemory 类内部用 flushing 标志互斥
- 所有写操作走 M1 的 WriteQueue
- 睡眠流水线的批量写入不阻塞在线写入

## 四、验收标准

### 4.1 功能验收

| 验收项 | 通过标准 |
|---|---|
| 原文落盘 | 每条消息都在 conversations 表中，ts_utc 正确 |
| 事件分割 | 测试 10 组对话，切分点与人工判断一致率 ≥ 80% |
| 工作记忆恢复 | 强制中断后重启，wm_buffer 中 pending 条目全部重新处理 |
| 三岔门控分布 | 正常对话中 WRITE 占 15-35%，DISCARD 占 30-50% |
| 测试数据隔离 | namespace='test' 的消息全部走 DISCARD |
| 前瞻记忆抽取 | 测试 20 个承诺/提醒句子，召回率 ≥ 80%，误报率 ≤ 20% |

### 4.2 性能验收

| 验收项 | 通过标准 |
|---|---|
| 在线写入 p95 | ≤ 30ms（不含异步向量） |
| 事件分割 p95 | ≤ 10ms |
| 崩溃恢复 | 100 条 pending 条目恢复时间 ≤ 5s |

### 4.3 正确性验收

| 验收项 | 通过标准 |
|---|---|
| 原文不丢 | 模拟 100 次写入，全部在 conversations 中可查 |
| 门控后状态一致 | WRITE 的痕迹在 memories 中，RAW_ONLY 的消息 lifecycle_state='raw_only' |
| 幂等性 | 同一条消息重复推送 3 次，只产生 1 条痕迹 |

## 五、⚠️ 加固防篡改要求（验收合格后强制执行）

### 5.1 加固时机

**本模块全部验收通过后**，由模块负责人执行加固，加固完成前不得交付给 M3/M4 调用。

### 5.2 加固内容

#### 5.2.1 入口冻结

- 对外只暴露 `MemoryWriter.write(message)` 单一入口
- 内部的门控逻辑、分割器、缓冲器全部**私有**，不允许外部直接调用
- 入口参数校验：必须包含 message_id / role / content / timestamp，否则拒绝

#### 5.2.2 内部代码保护

- 模块核心文件（WorkingMemory.ts / EventSegmenter.ts / Gate.ts / SalienceCalculator.ts）标记为只读
- 提交时强制要求：commit message 中必须包含 `[M2-OnlineWrite-改动说明]`
- 门控阈值（write_threshold / salience_weights）只能通过配置文件改，不能硬编码

#### 5.2.3 外接部分预留

- 保留以下必要外接点：
  - `onMessageWritten` 钩子：每条消息写完后的回调（供审计/统计扩展）
  - `onGateDecision` 钩子：门控判定后的回调（供监控扩展）
  - 自定义门控规则注册接口：允许其他模块添加自定义门控条件
- 除上述预留外接点外，**模块内部逻辑不允许外部直接修改**

#### 5.2.4 Harness 监管接入

- 模块状态上报到 Harness：门控分布、写入速率、平均延迟
- 每次门控决策记录到 reinforcement_events 或专用日志表
- Harness 定期校验：写入延迟是否在阈值内、门控分布是否异常
- 发现篡改或异常 → 自动告警 + 冻结模块写入

### 5.3 修改权限

| 操作 | 权限要求 |
|---|---|
| 正常写入业务消息 | 所有模块可用（通过统一入口） |
| 门控阈值调整 | 模块负责人 + Harness 备案 |
| 事件分割参数调整 | 模块负责人 + Harness 备案 |
| 门控规则新增/修改 | 必须业主授权 + ADR 评审 |
| 内部代码修改 | 必须业主授权，否则视为篡改 |
