# I009 · harness-mcp 第二服务器链

## 现象（2026-10-20 任务H 重启时发现）

`pm2 list` 中应用 **`harness-mcp`（id 1）实际跑的是 WenStar 的 `server.ts`**，与 `wenstar-webui` 构成**两条服务器链**：

```
pm2 harness-mcp (id 1)
 └ 36196 ProcessContainerFork (–root D:/tools/wenstar-cc)
    └ 55920 tsx cli.mjs server.ts
       └ 36496 tsx preflight        ← 未监听 3000（被 ServerLock / 端口占用挡在外层）

pm2 wenstar-webui (id 6)             ← 真正的监听者
 └ 36164 start.cjs
    └ 39956 tsx cli.mjs src/webui/server.ts
       └ 48108 preflight            ← 0.0.0.0:3000 LISTENING，持有 server.lock
```

- 该链**不是**本次改动/重启产生的 —— 重启前就在，且当时同样不是监听者。
- 属记忆里记录过的「harness-mcp 保活拉 webui」形态（历史数据震荡根因之一）。

## 风险

1. **sql.js 内存库覆盖磁盘**：若该进程已把库载入内存并在某次整库导出时写回，会覆盖停服窗口内的人工改库/清理（2.4 要清 8000–9000 条，覆盖即前功尽弃）。
2. **数据震荡**：两个实例读同一库、各自内存视图不同，写入时序不可控。
3. **监控误判**：`pm2 list` 上 harness-mcp 显示 `online`，让人以为 MCP 正常，实际跑的是别的程序。

## 判定「单实例」的可执行判据

```bash
# ① 监听者必须唯一
netstat -ano | grep "0.0.0.0:3000.*LISTENING"        # 期望恰好 1 行
# ② server.lock 的 pid 必须等于监听者
cat data/webui/server.lock
# ③ 进程链必须唯一（排除 pm2 harness-mcp 那条）
powershell -NoProfile -Command "Get-CimInstance Win32_Process -Filter \"Name='node.exe'\" | Where-Object { \$_.CommandLine -match 'wenstar' } | Select ProcessId,ParentProcessId,CommandLine"
```

三条同时满足才算「单实例」；停服窗口开始前请让我跑一遍并留证。
