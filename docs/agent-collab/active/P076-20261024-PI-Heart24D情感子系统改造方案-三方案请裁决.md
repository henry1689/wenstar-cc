# P076 · Heart 情感子系统「24D」改造方案

> 背景：P072 批3b 摸底发现 Heart 心脑引擎存在**活着的** 24 维情感向量子系统（与感知量纲是不同东西）。
> 业主裁决发现一选 **A（改造）**，按约定先出方案后动。

## 一、现状实测（它是什么、在哪、干什么用）

**定义**：`src/engine/bus/types.ts:115` `EmotionVector24D` —— 24 个**情绪类别分量**（joy/sadness/anger/fear/surprise/disgust/calm/anxiety/affection/trust/intimacy/respect/arousal/fatigue/excitement/boredom/dominance/compliance/warmth/coldness/nostalgia/curiosity/shyness/jealousy），值域 [0,100]。

**性质判定**：它是**情绪状态清单**（每维=一种情绪的强度），不是空间维度系统——但名字带「24D」，按业主法令字面（"不管多少 D 都是非法"）属清除对象。

**活跃消费面（删错会断功能）**：
| 模块 | 用途 |
|---|---|
| `engine/cortex/PromptComposer.ts` + `prompts/emotion-state.ts` / `intimate-scenes.ts` | **生成时的情绪状态提示词**（AI 表达情绪的依据）|
| `engine/cortex/GenerationOrchestrator.ts` | 初始情绪状态构造（joy:30 等）|
| `engine/tianquan/heart/`（emotion-decay/emotion-label/emotional-emergence/reconsolidation/stimulus-table/types + EmotionCycleTracker/EmotionRegulator/HeartStateStore/desire-stack/relation-synapse） | 心跳引擎：情绪衰减/标签/涌现/刺激表——**每轮心跳在跑** |
| `engine/storage/EmbeddingEngine.ts` | 情绪向量嵌入 |
| `engine/bus/types.ts` | 总线载荷（GlobalBus emotionVector 字段）|
| 测试 ×4 | emotion-decay/label/reconsolidation/stimulus-table |

**关键事实**：三域契约里 heart 的 `emotional_24d` 字段已在批1 随 `user_state_schema.json` 改为 `perception_40d`（且该契约全仓无加载方）；**但 Heart 引擎内部的 `EmotionVector24D` 是活代码**——这就是"契约已改、内核未动"的缝隙。

**关联件**：`engine/tianquan/heart/dim_mapping_24d_32d.ts`（24↔32 映射表，被 SensationAdapter 消费）、`Heart EmotionVector24D` 相关测试。

## 二、三方案

### 方案乙（**推荐**）：去量纲化改名 + 结构保持——"改造"的合规高效解
- `EmotionVector24D` → **`EmotionState24`**（或 `HeartEmotionState`）：从"24 维向量（量纲）"改名归位为"**24 项情绪状态分量**（清单）"——语义上它本来就是情绪清单，不是测量维度
- `dim_mapping_24d_32d.ts` → 重命名 + 内部注释 40D 化（SensationAdapter 同步 import 改名）
- 所有注释/文档中的「24D 情感向量」→「情绪状态分量」；测试名同步
- **零行为变更**，功能完整保留（情绪引擎/提示词/心跳全不受影响）
- 符合法令目标：**量纲命名体系里不再存在任何 "XD"**（除40D）；死灰无从复燃
- 工作量：~16 文件改名+注释，Harness 1-2 批，测试全绿即可验收

### 方案丙（彻底统一，工程较大）：情绪状态由 40D 派生
- 废除独立情绪清单，Heart 的情绪分量改为从 `perception_40d` 语义维派生（D12 愉悦→joy、D11 恐惧→fear、D13 共情→affection…）
- 问题：24 情绪与 40D 维度**并非一一对应**（boredom/nostalgia/shyness/jealousy 等在 40D 无对应维），派生必失真 → 情绪衰减/涌现引擎全部重设计
- 工作量：引擎级改造+行为回归，量级≈P074

### 方案丙-简（介于两者）：删除情绪清单，情绪表达直接引用 40D
- Cortex 提示词改读 perception_40d（"当前愉悦 D12=0.7、依恋 D15=0.6"），废除 EmotionState 通路
- 心跳引擎（衰减/涌现/刺激表）失去输入 → **功能退化**，需业主接受 AI 情绪表达简化

## 三、我的建议

**方案乙**：它精准命中法令本质（消灭非法量纲，而非消灭情绪功能）——「24D」错在**把自己当量纲**，改名归位即合规。方案丙留作远期与 P074（感知 40D 化）联动评估。

**待业主裁决**：乙 / 丙 / 丙-简。裁决后我按 Harness 流程执行（预估 1-2 个批次令牌）。
