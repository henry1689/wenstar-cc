## 一、问题现象（业主实测发现）

### 实测对话关键节点

```
鸿艺：怎么一会就忘了，你不回去拿...当然是那个情趣... ...
徐诗雨：【徐诗雨】（脸腾地热了...）……诗雨没忘。...

鸿艺：拿什么，说来听听，不然又拿错了
罗珍思：【罗珍思】（脸烫得厉害...）……那套情趣内衣。  ← 阿珍知道了诗雨的私密事！
```

### 六大症状

| # | 症状 | 现象 |
|---|---|---|
| 1 | 块内多角色台词 | 一个输出块里塞了两个人的对话（【罗珍思】徐诗雨：... 罗珍思：...） |
| 2 | 跨角色记忆泄漏 | 阿珍知道了诗雨和用户的私密对话（"情趣内衣"） |
| 3 | 多人点名只匹配一个 | "找徐诗雨和阿珍一起聊" → 只徐诗雨回复，阿珍没来 |
| 4 | LLM 自切发言人不同步 | 用户说"拿什么说来听听" → 上一轮是徐诗雨，但这一轮变成罗珍思回复了 |
| 5 | "结束"没退出 | 说"结束" → 罗珍思说"嗯，在呢。你说。" |
| 6 | 角色说话内容窜 | 罗珍思回复了徐诗雨的私密台词 |

## 二、三根深因（豆包代码实读挖出）

### 根因 1：outputGuard 不检测块内多角色台词

**文件**：`src/m5/group/outputGuard.ts:145-180`

**代码实读**：
```typescript
// validateReplyIdentity 只校验两件事：
// ① 头里声明的 speaker 是否在参与者列表里
// ② 正文里有没有"我是X"这种显式自称冲突

const selfIdent = detectSelfIdent(body);  // 只找"我是X"
const conflicting = selfIdent.filter(n => byName(n) && byName(n)!.name !== declared.name);
```

**问题**：
- 守卫**不扫描正文里是否混入了其他参与者的台词**
- LLM 在一个块里写了两个人的对话，守卫看到头是"罗珍思"、正文里没有"我是徐诗雨"，就直接放行了

**修复方向**：
```typescript
// 在 validateReplyIdentity 里增加块内多角色检测
function detectInlineMultiSpeaker(body: string, participants: Person[]): string | null {
  for (const p of participants) {
    if (p.name === declaredSpeaker) continue;
    // 检测正文里是否出现"徐诗雨："或"（诗雨...）"这种其他角色台词
    if (body.match(new RegExp(`${p.name}[：:]`) || body.match(new RegExp(`[（(]${p.name.slice(0,2)}`))) {
      return p.name;  // 发现混入
    }
  }
  return null;
}
```

### 根因 2：LLM 输出 speaker 头与系统 speakerUuid 不同步（核心根因）

**文件**：`src/webui/chat.ts:760` + `src/webui/chat/persistence-stage.ts:213-217`

**代码实读**：
```typescript
// chat.ts:760
const _meetingUuid = ctx._entityMeeting?.getEntityUUID?.();
// getEntityUUID() 返回的是系统的 speakerUuid

// persistence-stage.ts:213
const _meetingUUID = input.ctx._entityMeeting?.getEntityUUID?.() ?? null;
let belongUUID: string | null = _meetingUUID ?? ...;
let asstUUID: string | null = _meetingUUID ?? ...;
```

**问题链条**：
```
用户说"拿什么，说来听听"
    ↓
speakerResolver 粘性策略：上一轮是徐诗雨 → 保持徐诗雨
    ↓
系统 speakerUuid = 徐诗雨UUID
    ↓
LLM 生成回复 → 自己决定让罗珍思说话 → 输出【罗珍思】...那套情趣内衣...
    ↓
outputGuard 解析 speaker 头 → 罗珍思
    ↓
但系统 speakerUuid 没有同步切换（还是徐诗雨UUID）
    ↓
persistence-stage 写入对话
    ↓
belongUUID = getEntityUUID() = 徐诗雨UUID
    ↓
罗珍思的对话，被错误地标记成了徐诗雨的UUID！
```

**这导致了什么？**
- 当徐诗雨发言时 → `getContextWindow(徐诗雨UUID)` → 包含所有对话（包括罗珍思的）✅
- 当罗珍思发言时 → `getContextWindow(罗珍思UUID)` → **什么都找不到** ❌
- 罗珍思拿不到自己的历史对话 → 走 fallback 路径 → 把全局对话历史直接给了 LLM
- **这就是为什么阿珍能看到诗雨的私密对话**！

**修复方向**：
```typescript
// 在 outputGuard 或 persistence-stage 里，检测到 speaker 头变化时同步切换
const detectedSpeakerName = extractSpeakerHeader(reply).speaker;
const currentSpeakerName = getCurrentSpeakerName();

if (detectedSpeakerName && detectedSpeakerName !== currentSpeakerName) {
  const detectedUuid = getUuidByName(detectedSpeakerName);
  if (detectedUuid) {
    // 同步切换 speakerUuid
    gs.dispatch({ type: 'SPEAK', target: detectedUuid, now: Date.now() });
    // 然后写入对话时，belongEntityUuid 就是正确的了
  }
}
```

### 根因 3：speakerResolver 多人点名只匹配一个

**文件**：`src/m5/group/speakerResolver.ts:100-120`

**代码实读**：
```typescript
export function ruleFindNamed(message: string, state: SessionState): { uuid: string; name: string } | null {
  // "某人，…" / "某人：…"
  const voc = msg.match(/^\s*([一-龥]{2,8})\s*[：:，,、]/);
  if (voc) {
    const hit = byName(state, matchParticipantName(voc[1], state) ?? '');
    if (hit) return hit;  // ← 只返回一个！
  }
  return null;
}
```

**问题**：
- `ruleFindNamed` 只返回**一个**名字
- 如果消息里同时提到两个人（"找徐诗雨和阿珍一起聊聊"），它只匹配句首第一个名字
- LLM 看到用户点了两个人的名，就自己在回复里替两个人都写了台词

**修复方向**：
```typescript
// ruleFindNamed 增加多人检测
export function ruleFindNamed(message: string, state: SessionState): {
  single?: { uuid: string; name: string };
  multi?: Array<{ uuid: string; name: string }>;
} {
  // 检测消息里提到的所有参会者名字
  const mentioned = state.participants.filter(p => message.includes(p.name));
  if (mentioned.length >= 2) {
    return { multi: mentioned };  // 多人待分配信号
  }
  // ... 原有单目标逻辑
}
```
