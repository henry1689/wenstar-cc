# P173 · 文曲星记忆系统（MenWen OS）总体规划

> **性质**：**方案立项书（待业主确认后实施）**。依据业主 2026-11-09 指令：①现状读写架构对照落盘 ②制定可落地完善计划 ③高度整合/集中管理/核心机制固化不易篡改 ④命名「文曲星记忆系统 / MenWen OS」自研记忆系统 ⑤补齐缺口 ⑥修复上下文连贯问题 ⑦凸显前瞻性、行业领先。
> **纪律**：本文为规划，**未动任何代码与数据**；实施需业主拍板 + Harness 全流程。

## 一、命名与品牌

| 项 | 值 |
|---|---|
| 中文名 | **文曲星记忆系统**（文曲星：主掌文运与典籍的星宿——契合"记忆/文书/文明传承"） |
| 英文名 | **MenWen OS**（**Mem**ory × **Wen**——记忆操作系统；业主定名） |
| 定位 | **自研人格社会记忆系统**——不是外挂 RAG 组件，是角色的"海马体 + 新皮层" |
| 模块前缀 | `MW-`（MW-Gateway / MW-Vector / MW-Context / MW-Archive / MW-Gate） |
| 标语 | 「让每一次被记住，都能被想起」（守恒即品牌承诺） |

**自研底座盘点（已有，构成 MenWen OS 的技术主权）**：
- `@zvec/zvec` C++ HNSW 向量库（自研，HNSW+COSINE+WAL）
- 40D 感知向量（`cosineSimilarity40D` 单一实现，P072 立法）
- 五级闸门 G1-G5（仿生遗忘 floor、时空一致性、话题壁垒）
- 钙化分层 L0-L3 + 黑钻结晶（仿生巩固）
- 双螺旋 DNA（`dna_root_id`/`dna_full_code`）+ entity_genes 实体基因
- BlockArchive 内容哈希封存（content_hash/summary_hash，防篡改雏形）
- 记忆总线 RecallBus（层保底+配额+统一反馈）

## 二、现状架构实证（读写一张图）

### 2.1 写入侧：三层结构（已实证）

```
对话轮 (user/assistant 每轮)
   │  LLM 决策打分（钙分/40D/类型/前瞻时态）
   ▼
① 轮级记忆条目  memories   avg 149字，42%<50字   ← 最小存储单元
   │  话题切换划分
   ▼
② 对话组 dialog_groups  3623组≈4.9轮/组          ← 聚合语义块
   │  摘要/快照/归档
   ▼
③ 组摘要(conversations.is_summary=1) + 40D组快照 + 黑钻结晶 + BlockArchive哈希封存
```

**判定**：语义块思想**部分具备**（话题组≈语义块），但**最小单元是轮级、不带上下文描述**——与 Anthropic contextual retrieval 的差距在"块的上下文自描述"。

### 2.2 检索侧：四路混合（已实证）

| 路 | 机制 | 缺陷 |
|---|---|---|
| ① 结构化槽位 | SQL 排序（近期8/历史6/最早6） | 槽位 0.4% + `recall_count DESC` 马太（P167 ⑤⑥） |
| ② 40D 感知向量 | cosine top-k（G1≥0.3） | **属性向量非内容向量**——"外公去世"无表达 |
| ③ 关键词/FTS | sweep + FTS5 + n-gram | 漏词即失明 |
| ④ 摘要形式 | 组摘要 B50% + 高钙组 A30% + 深度素材包 | 整包 other 层级失真（P168-B） |

**判定**：hybrid 骨架正确（业界共识），**缺 dense 内容向量一路**；`EmbeddingProvider` 实为 TF-IDF hash 256 维且只服务知识侧。

### 2.3 自诊断：上下文连贯问题（业主痛点，已定位线索）

- **检索查询零上文参与**：`previousTurn`/`上一句`/`前文` 在 retrieval-stage/meeting-recall **零命中**——查询=当前 message 单句，**上一轮 assistant 说了什么不参与检索**；
- 历史窗口在 `chat.ts` 多分支组装（空间视图/DB补充/玉瑶态 fail-closed），**窗口与截断策略未审计**；
- 记忆预算 C 与历史字符挂钩（`memory_max_ratio_of_history`），历史若被截断则记忆预算同步缩水——**两个通道互相牵连，未验证**。

⇒ 连贯性差的三个候选根因（M0 专项诊断确认）：**R1 检索不带上文 / R2 历史窗口过小或截断 / R3 预算联动副作用**。

## 三、五缺口清单（G1-G5）

| # | 缺口 | 现状 | 影响 |
|---|---|---|---|
| **G1** | **dense 内容向量缺失** | TF-IDF hash 256 维顶替，只服务知识侧 | 内容语义查询靠关键词碰运气——双靶子 T4 失败的深层根因之一 |
| **G2** | **上下文自描述写入缺失** | 轮级条目裸文本入库，组上下文不进块 | 检索侧无法利用"当时场景"做内容语义匹配；与 40D 优势未打通 |
| **G3** | **上下文连贯性**（业主痛点） | R1/R2/R3 三候选根因未诊断 | 下句与上句关联弱，体验直接可见 |
| **G4** | **核心机制固化不足** | 机制散落：蓝皮书/ADR/法规注释/守卫测试各处有雏形，**无统一"宪法+强制绑定"** | 机制可被绕过/漂移（历史：Sentinel 回滚、正则被复制、单测假绿） |
| **G5** | **整合度不足** | 读写网关收口进行中（MemoryWriteGateway 批4b/7），观测/守卫/迁移分散 | 集中管理维护成本高，改动易漏 |

## 四、目标架构：MenWen OS 分层

```
┌────────────────────────── 表达层（对话/会晤/主动回忆） ──────────────────────────┐
│  MW-Express：prompt 组装 · 主动回忆指令 · 三档表达 · 憧憬                         │
├────────────────────────── 读取层（四路→五路混合召回） ──────────────────────────┤
│  MW-Read：①结构槽位 ②40D感知向量 ③dense内容向量【新·G1】 ④关键词FTS ⑤摘要分级    │
│           → RecallBus 总线（层保底/配额）→ 五级闸门 G1-G5 → 注入预算              │
├────────────────────────── 巩固层（仿生记忆规律） ──────────────────────────────┤
│  MW-Consolidate：钙化 L0-L3 · 黑钻结晶 · 仿生遗忘 floor · 组摘要 · BlockArchive   │
├────────────────────────── 写入层（单一网关·宪法化） ───────────────────────────┤
│  MW-Gateway：MemoryWriteGateway 唯一写入口【G4/G5】                              │
│    ├ 决策打分（钙分/40D/前瞻）  ├ Contextual 拼装【新·G2】：组话题+时间+人物+前轮  │
│    └ 双螺旋（DNA+entity_genes+UUID）                                             │
├────────────────────────── 存储层（自研底座） ──────────────────────────────────┤
│  MW-Store：memories/dialog_groups/conversations + zvec HNSW【dense索引·G1】      │
│            + FTS5 + schema_version 迁移 + content_hash 封存【防篡改】             │
├────────────────────────── 治理层（固化·防篡改） ──────────────────────────────┤
│  MW-Govern：ADR 宪法 · 守卫测试矩阵 · Harness S1-S7 强制 · 单写入口审计          │
│             · 机制白皮书单源 · 可观测仪表（retrieval_log/decay_log 统一）         │
└──────────────────────────────────────────────────────────────────────────┘
```

**"高度固化不易篡改"七机制（G4 落地）**：

1. **单写入口**：一切写入经 `MW-Gateway`（MemoryWriteGateway）——守卫测试断言"绕过路径=0"；
2. **机制宪法**：核心机制（四路召回/五级闸门/守恒/40D 单实现）逐条 ADR 立法 + 代码内法规注释（沿袭蓝皮书/DSA 传统）；
3. **守卫矩阵**：每个核心机制 ≥1 个 guard test（沿袭 vector-contract-guard / write-path-guard / sliding-junk-selfcheck 模式），**能力断言**（不写计数/位置前提——经验21）；
4. **Harness 强制**：核心文件改动必须走 S1-S7（现行宪法不降级），S4.5 收敛闸门把关复杂度；
5. **哈希封存**：BlockArchive 的 content_hash/summary_hash 模式推广至 memories 关键批次（写入即封存，篡改可检）；
6. **版本迁移**：schema_version 单源迁移，禁离线改库（BlockArchive 事故教训已立法）；
7. **观测闭环**：四层指标（存储守恒/候选资格/注入可达/实召——P170 纲领1）日报表化，异常自动告警（方案 D 守恒监控并入）。
