# T009 · FG 统一架构收口

## 🎯 业主裁决（核心决策）

> **废弃多路径分裂，统一为：定时 LLM 提取 + 统一格式规范 + 录入前去重 + 读取端统一 + 定期清除残留**
>
> 1. 不用 RAG/其它模式提取实体特征，统一用定时 LLM 提取
> 2. 提取录入必须按统一格式和规范
> 3. 录入前必须分析去重
> 4. 读取端统一格式和规范
> 5. 以前的旧路径（HWG/PAE/FGRelationExtractor/HumanWorldGraph）都可以不要
> 6. 因去重残留的信息要定期清除

## 📋 审计结论（T008 交叉验证）

- 7 项 P0 结构性风险（读写语义分裂/关系方向丢失/读取触发删边/void不过滤/密级死字段/HWG空壳/字典分裂）
- 三套关系词表分裂（FG 8类/HWG 18类/DEFS ~40类）
- 顶层 flat 与 dossier 双写无同步（33.6% vs 2.2%）
- HWG 四表全 0 行，enhanceFromConversation 零调用者
- FGRelationExtractor 产出恒为 0（LLM 提取链路失效）
- security_level/tags/circle_level 全为死字段

## 🏗️ 新架构设计

### 一、统一数据规范

#### nodes 表（必填字段）
| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| id | TEXT | ✅ | TXS-UUID |
| name | TEXT | ✅ | 主名 |
| type | TEXT | ✅ | person/org/place/object |
| uuid | TEXT | ✅ | 唯一，户籍铁律 |
| status | TEXT | ✅ | active/candidate/dormant/void |
| category | CHAR(1) | ✅ | S/U/A/B/X/G |
| aliases | TEXT | — | JSON 数组 |
| properties | TEXT | ✅ | JSON，统一 dossier 结构 |
| created_at/updated_at | TEXT | ✅ | |

**废弃字段**（Phase 4 删除）：security_level, tags, circle_level, entity_source, legacy_ids, family_gene, social_group_genes

#### edges 表（必填字段）
| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| id | TEXT | ✅ | |
| source_id | TEXT | ✅ | FK→nodes.id |
| target_id | TEXT | ✅ | FK→nodes.id |
| relation | TEXT | ✅ | 必须∈RELATION_TYPE_DEFS |
| properties | TEXT | ✅ | JSON: confidence, source, evidence, created_from |
| created_at/updated_at | TEXT | ✅ | |

#### 统一 dossier 结构（废弃顶层 flat）
`
properties.dossier = {
  basicInfo:      { gender, birthYear, birthPlace, education, maritalStatus },
  selfProfile:    { traits[], appearance, bodyFeatures, style, voice },
  socialIdentity: { currentOccupation, currentWorkplace, socialRoles[] },
  lifeMilestones: [{ date, event, type }],
  contact:        { workplace, address, phone },
  personalityPrefs: { traits[], interests[] },
  misc:           {},
  _changeHistory: [{ time, field, old, new, source }]
}
`
**废弃**：顶层 flat 字段（appearance/body_features/traits/occupation/description/style/personality/interests/relation_to_user）

### 二、统一录入路径：定时 LLM 提取器

**替代**：PAE 自动触发 + FGRelationExtractor + HumanWorldGraph.enhanceFromConversation

**工作流程**：
1. 定时扫描（默认每 6 小时）最近 N 个对话组
2. LLM 提取实体和关系（统一 prompt 模板 + JSON schema 校验）
3. 录入前去重：
   - 实体去重：UUID 精确 → 别名模糊 → 新建 candidate
   - 关系去重：source+target+relation 三元组去重
   - 字段去重：已有字段不覆盖，新增字段合并
4. 写入 FG 主库（nodes + edges + dossier）

**统一提取输出格式**：
`json
{
  "entities": [{
    "name": "张三", "type": "person", "aliases": ["小张"],
    "dossier": { "basicInfo": {"gender":"male"}, "selfProfile": {"traits":["认真"]} }
  }],
  "relations": [{
    "source": "张三", "target": "李四", "relation": "colleague_of",
    "confidence": 0.9, "evidence": "对话原文片段"
  }]
}
`

**PAE 保留为手动录入接口**（不再自动触发），用于业主手动确认/修正。

### 三、统一读取路径

1. **单一档案读取入口** PersonProfileView：合并 dossier 所有子卷，会晤/普通模式共用，废弃顶层 flat
2. **单一关系读取入口** getUserRelation：返回带方向的关系标签 + 置信度 + 热力，edges 为唯一权威源
3. **读取零副作用**：移除 getPersonProfile 中的 _checkStatusDowngrade，状态降级改由维护任务触发
4. **void 过滤**：getEntityByUUID 增加 status != 'void' + merged_into 重定向

### 四、废弃清理（Phase 4 停服窗口）

1. **HWG 新系统**：删除 hwg_persons/relations/events/profile_snapshots/bridges 五表 + HumanWorldGraph.ts 相关代码
2. **旧录入路径**：删除 FGRelationExtractor.ts、HumanWorldGraph.enhanceFromConversation
3. **死字段**：删除 security_level/tags/circle_level/entity_source/legacy_ids/family_gene/social_group_genes
4. **垃圾边清理**：
   - 未定义关系类型的边（elder_sister_of/younger_sister_of/lives_in/has_appearance/lover_of 等 7 种）
   - void 节点参与的边
   - 孤儿边（source/target 不存在）
5. **顶层 flat 迁移**：将 appearance/traits/occupation 等迁移到 dossier 对应子卷后删除

### 五、定期维护机制

1. **去重残留清除**（每周）：
   - void 状态超 30 天的节点（物理删除）
   - 重复边（同 source+target+relation 多条，保留置信度最高）
   - 孤儿边
2. **候选节点生命周期**：
   - candidate 超 30 天未晋升 → dormant
   - dormant 超 90 天 → void
   - void 超 30 天 → 物理删除
3. **垃圾数据清除**：
   - 无任何边的孤立节点（超 30 天）
   - 空 dossier 节点（超 30 天）
