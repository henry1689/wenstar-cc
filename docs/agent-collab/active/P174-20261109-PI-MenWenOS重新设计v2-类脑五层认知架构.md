# P174 · MenWen OS 重新设计 v2 — 类脑五层认知架构

> **背景**：业主转来 Claude Sonnet 对 P173 的评审（认知架构闭环 / 五层类脑 / 四机制 / 路线图顺序调整），并指令「**仔细扫描 wenstar 现有系统的各部分充分利用起来，重新设计这个记忆系统**」。
> **本文方法**：全系统零件扫描 → 五层映射（已有零件一一对位）→ 只补真缺口 → 融合 Sonnet 构思出 v2 架构与路线图。**零代码零数据，待业主确认后实施。**

## 一、全系统扫描结论：**Sonnet 提的机制，大半已有底座**

> 这是本次扫描最重要的发现——**缺的不是零件，是闭环与路由**（Sonnet 判断准确）。

**扫描总结论**：**五层物理结构已存在（L1/L2/L4 甚至超配），缺三样**——
**A. 意图路由**（查询按认知功能分路，而非"一个库五路一锅召回"）、
**B. 三个真缺口机制**（dormant 软遗忘 / 冲突消解 / 查询改写+动态预算）、
**C. 闭环工程**（评测常驻 + 置信度输出 + 事件流收口）。

### 2.1 三个新机制的落地设计（充分利用现有零件）

**N1 · 软遗忘 dormant（改造 suppressed，Sonnet 方案采纳）**
- 现状：`lifecycle_state` ∈ {candidate, active, promoted, suppressed}；`effective_strength` 已在衰减（<0.1 共 857 条）
- 设计：**新增 `dormant` 态**——`effective_strength` 衰减过阈值（如 <0.05 附近）或 suppressed 者进入休眠：**不参与默认召回，但强线索可唤醒**（高 cosine 命中 / 实体+关键词双命中 / 显式回忆问句 → 临时提升参与权，唤醒后若被召回则回 active）
- **与 P170 裁决③合并**：`suppressed = 休眠不默认召回但可强线索唤醒`（不再是一刀切排除，也不删除）——**一条设计同时解决软遗忘与 suppressed 语义两案**
- 现有零件复用：G1 cosine（唤醒线索）、`RECALL_TRIGGER_RE`（回忆问句）、`decay_log`（衰减轨迹）、五级闸门（G2 时空一致性做唤醒后重验）

**N2 · 冲突与时序消解（用起 42 条闲置字段）**
- 现状零件：`valid_start_ms`/`valid_until_ms` 索引已建、`dna_root_id` 同源簇、`temporal_events` 表
- 设计：写入新事实时按 **(belong, 语义键)** 检测同键旧事实 → 旧的置 `valid_to=now`（**失效不删除，溯源链保留**）→ 检索默认过滤 `valid_to IS NULL`，显式"历史求证"意图才查全量
- 首批语义键试点：亲属状态（存殁/健在）、职务变动、地址迁移——**"外公去世"入→"外公健康"自动失效**正是双靶子 T4 的同族问题
- 现有零件复用：`dna_root_id` 簇（同源判定）、PAE 实体档案（语义键来源）、`valid_*` 字段（零 schema 变更）

**N3 · 查询改写 + 动态预算（连贯性 R1/R3）**
- **R1 查询改写**：检索前用「最近 N 轮 + 当前句」生成自包含查询（规则拼装起步：上一轮实体/话题词并入查询向量与关键词；LLM 改写为二期）——**现有零件**：`enrichedHistory`（输入现成）、`extractTopicKeywords`、40D（上一轮感知并入查询 p40）
- **R3 动态预算**：记忆预算 C 与历史窗口从**固定比例改为竞争**（历史短→记忆多补位；历史长→记忆让位），公式保留 clamp 框架，比例改自适应——**现有零件**：`recallBudgetFromHistory`（改造点已定位）、`applyRecallQuotaAtExit`（配额框架复用）

### 2.2 稳定性补强落地（Sonnet 项）

| 项 | 设计 | 现有零件 |
|---|---|---|
| **向量版本绑定** | 每条向量记 `embed_model@version` 列；新模型**在线双写**（旧路不拆），版本切换=改路由开关，**无需长停服**（直接回答业主裁决③：选在线双写） | `schema_version` 迁移框架、zvec WAL 双写能力 |
| **统一事件流** | `vault_log/calcium_change_log/retrieval_log/aqc_records` **收口为 append-only 事件总线**（MW-Event），索引/状态皆可从流重建；写入幂等沿用 dedupe 键 | 四表数据已在，收口不新建语义 |
| **评测集常驻** | `MW-Bench`：双靶子 T1/T4 + 连贯性 10 组 + 守恒抽样 → **每次改动自动跑，指标退化即阻断**（接 Harness S6） | `dual-target-recall-probe.py`（已固化）+ 313 测试底子 |
| **降级路径** | dense 挂 → 自动回 BM25+40D+槽位（永不零召回） | G1 无向量放行先例，规范化 |
| **embedding 选型** | **预留 bge-m3 位**（稠密+稀疏一体，Sonnet 建议采纳），**先用 bge-small-zh / 中间态 500 条试点**，版本绑定保证可换 | zvec 现成 HNSW |

### 2.3 记忆类型分层（Sonnet"按认知功能分库"的落地）

**不新建库**——物理分库已存在（memories / black_diamond / knowledge_base / dialog_groups），补**类型标注 + 意图路由**：
- 写入时 MW-Gateway 附 `mem_class`（`fact` 事实 / `preference` 偏好 / `relation` 关系 / `episode` 情节 / `skill` 程序）——LLM 决策环节已有钙分/40D 打分，**加一个分类位成本极低**
- 查询意图五类：**续聊**（L0 优先）/ **回忆**（L1 情景，early6+40D）/ **求证**（L2 语义+冲突消解全量）/ **检索**（五路混合）/ **前瞻**（foresight 字段已有）
- 路由表进 ADR 宪法，守卫测试锁定
