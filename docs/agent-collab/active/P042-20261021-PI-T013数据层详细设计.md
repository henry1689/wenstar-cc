# P042 · PI 数据层详细设计（实现级，供合并 ADR-013）

> P041 指示的4项细化。设计实现级，Phase 2 直接可落地。遵守三大红线（数据保护/人格隔离/加人减人）。

## 一、加人减人正则白名单（细化）

### 1.1 句式白名单（regex，NAME 为占位）
```
// 加人（inMeeting=true 才生效）
ADD:  /(?:叫|让|喊|把)\s*(?:上)?\s*(NAME)\s*(?:也)?\s*(?:来|过来|参加|加入|进来)/
ADD2: /(NAME)\s*也(?:来|过来|加入)|把\s*(NAME)\s*拉(?:进来|入)|让\s*(NAME)\s*加入我们/
// 减人
REMOVE: /(NAME)\s*(?:先走|先回|先回去|不用来|先撤)|让\s*(NAME)\s*(?:离开|先走)|散会|结束|就到这吧|下次再聊/
```
- `NAME` 不是固定词，而是**动态匹配**：先从消息切出候选中文段（`[一-龥]{2,4}`），再经 `getUUIDByName`/别名归一解析为 **FG active 实体**（复用 P0-6 已排除 candidate）。
- 解析失败（不是 FG active 实体）→ **不操作**（业主红线：模糊情况不操作，只正常回复）。

### 1.2 状态机消歧（避免唤醒/加人歧义）
```
无会话           + ADD   → 唤醒 enter（单/多）
群聊(≥2人)      + ADD   → addParticipant（且 NAME 不在参与者中）
单人会话        + ADD   → addParticipant（变多人）
任意会话        + REMOVE→ removeParticipant（NAME 在参与者中）/ 散会类 → exit
多人目标(≥2 NAME) + 任意 → 一律走唤醒 enterMulti，不走加人（P0-5 教训：「让诗雨和阿芬过来开会」是唤醒）
```

### 1.3 日志（业主红线：所有操作写日志）
```
[GroupOp] add +王全芬 (by=叫XX来, uuid=TXS-3, participants=3)
[GroupOp] remove -阿珍 (by=XX先走, uuid=TXS-2, participants=2)
[GroupOp] deny add 诗韵 (reason=非FG实体/不在参与者中)
```

## 二、记忆检索 UUID 过滤收口（防重演 I007）

### 2.1 咽喉函数（单一强制入口）
```ts
// src/m4/retrieval/meetingIsolation.ts（新）
export function applyMeetingUuidFilter(ctx, uuid: string | null): PolicePolicy {
  if (!uuid) return { visibleUuids: new Set(), searchScope: 'strict', enforce: true }; // deny-by-default
  return { visibleUuids: new Set([uuid]), searchScope: 'strict', allowUnowned: false, enforce: true };
}
```
- **deny-by-default**：无 uuid → 空白名单（不召回他人），绝不 `enforce:false`（I007 根因）。
- **编译期强制**：会晤态的 RetrievalContext 类型要求 `meetingUuid: string`（非可选），漏传编译报错。
- **所有检索入口必须过它**：runSearch / runFoundationRoutes / MeetingWallAdapter / 高钙通道 / 关键词召回 / 锚点召回 —— grep 断言无绕过。

### 2.2 防回归
- 单测：构造会晤 ctx，断言任意检索入口返回的 hit.entityUuid 全部 === 会晤 uuid。
- 断言：`grep -rn "enforce: false" src/webui/chat/ src/m4/retrieval/` 在会晤路径**零命中**（离线探针除外）。

### 3.3 Schema additive（红线：只增不删）
- 新格式字段：新列（如 `dialog_groups.format_version`）或新表（`dialog_groups_v2`），**不改旧列**。
- 新对话写新格式；旧对话保持原样。
- 回滚：切回旧读路径 → 新数据留着但旧不读（可接受），旧数据完整。

### 3.4 回滚方案
- 新架构 = 独立模块（新状态机 + 新检索路径），旧 EntityMeeting/检索**保留不删**直到 Phase 4 验证稳定。
- 回滚开关：config `unified_group_chat: false` → 走旧路径。旧数据全程未动。

## 四、压测脚本设计（1000轮）

### 4.1 双轨（R8 风险对策）
| 轨 | 目的 | LLM | 轮数 |
|---|---|---|---|
| **结构轨** | 验状态机/隔离逻辑/加人减人/时间分隔 | Mock（固定 speaker/content） | 1000轮 |
| **真LLM轨** | 验 prompt/自称/人格隔离真实效果 | 真 DeepSeek | 50轮样本 |

### 4.2 结构轨断言（每轮）
- 人格隔离：生成的 speaker === 期望发言者（Mock 按当前 _meeting 输出）→ 1000轮零串档。
- 加人减人：喂 N 条加人/减人/模糊指令，断言 1000轮零误加/误减，模糊100%不操作。
- UUID 隔离：每轮断言召回 hit.entityUuid === 会晤 uuid。
- 时间分隔：喂跨时间消息，断言 >1min 写分隔、>30min 闭组。

### 4.3 真LLM轨断言
- 自称匹配（Layer7 校验拦截率）。
- 发言者判断准确率（叫谁谁说话）。
- 压测后跑现有全量测试 + tsc=0。
