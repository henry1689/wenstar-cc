# P148 实体准入批2b：确定性取证

## 一句话

实体准入从「模型输出取证头」改为「从用户消息里确定性取原文证据」：
**一个判据、一个闸门、四个写入点共用**，合法新实体本轮即可进入 `entity_genes` 并参与 M4/FG/记忆检索。

## 为什么改（实测结论）

| 事实 | 证据 |
|---|---|
| LLM 取证头协议合规率 **0/4** | 四种注入全试过：PromptAssembler 任务块 / 独立 system 消息（`responseContract`）/ 用户轮前缀 / 回忆类消息。指令确实进了 prompt（`inKB=true`、`[ResponseContract] applied`），模型就是不输出头 |
| 合法新实体进不来的真因 | `entity_genes` 的人名来源只有 FMM 词典 + FG 已知名单；显式介绍的人从未进入 `entity_genes` ⇒ 本轮 M4/FG/检索看不见他 |
| 同一判据散落三处 | `hasExplicitPersonIntro`（仅对已有名字生效）/ `integrateSocialRelation`（无判据）/ `storeRelations`（无判据） |

## 结构

- 判据：`findIntroEvidence(text, name)` —— 名字 ±10 字窗口内出现介绍线索（介绍动词/社会角色/亲属称谓）→ 返回窗口原文作证据（恒为消息的连续子串）。
- 发现：`extractIntroducedPersons(text)` —— `叫X` / `X是我的Y` / `这是我同事X` / `X老师`，证据 = 正则整体匹配。
- 闸门：`verifyAdmission` —— **未变**（证据必须是用户消息连续子串且包含名字）。
- 写入点：L3 产出（带 `evidence`/`admission:'deterministic'`）/ `integrateFromEntity` / `integrateSocialRelation`（仅新建节点）/ `storeRelations`（仅新建 entities 行）。
- LLM 头：降级为**可选增强**（`admitModelFromReply`，被动解析，不再作为准入前提）。

## 行为变化（已声明）

「只是提到某人」（如「和张中山开会」）不再建档；已入库人物不受影响（只闸新建）。
