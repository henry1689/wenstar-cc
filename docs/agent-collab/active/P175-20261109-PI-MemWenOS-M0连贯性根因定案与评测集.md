# P175 · M0 定案报告（连贯性根因 + 评测集 + 基线）

> **性质**：ADR-024 路线图 M0 交付（只读诊断 + 评测集数据文件，**零代码改动**）。
> **依据**：业主批 v2 + 10 修正（ADR-024）；M0 目标 = R1/R2/R3 根因定案 + MW-Bench 常驻评测 + 指标基线。

## 一、连贯性三根因定案（R1/R2/R3）

### 🔴 R1 · 查询零上文参与 —— **全时段主因，定案**

**证据**（代码级）：
- `chat.ts:1020` `runRetrieval({ message, ... })` —— `message` = **当前用户单句**；
- `fetchBionicMemories(message, ...)` 同样单句；
- 全仓 `previousTurn` / `上一句` / `前文` 在 retrieval-stage / meeting-recall **零命中**。

**结论**：每一轮检索只用当前句查询，**上一轮 assistant 说了什么、上一轮话题是什么完全不参与** → 检索结果与对话上文无关 → 回复与上句关联弱。**这是"下一句与上一句关联性不强"的全时段根因**（不分长短会话）。

**M2 修复方向**（ADR-024 修正5 约束）：查询改写 = 最近 N 轮 + 当前句并入查询（关键词与 40D 双通道），**带话题漂移判定**——当前句与上一轮相似度低于阈值则不并入，防拖回旧话题。

### 🟡 R2 · 历史窗口 —— **已大幅修复，残余两点**

**证据**：
- ✅ V35-B（2026-10-05）已把 **5 套口径收口为单一真源** `_window = MEMORY_CONFIG.compaction.contextWindowTurns`（默认 80）；历史"80→10 断崖"已修（超窗改"满窗口+超出部分进摘要"）；
- 🟡 残余 1：**PFC（前额叶）上下文只拿 `enrichedHistory.slice(-10)` × 每条 `substring(0,200)`**（chat.ts:2470/2506）——PFC 决策辅助的上文视野仅 10 条×200 字；
- 🟡 残余 2：超窗压缩 `enrichedHistory = _compressed.anchor`（chat.ts:1011）后历史显著变短（触发条件：>80 条长会话）。

**结论**：主 prompt 链路历史相对完整；**R2 不是日常连贯性主因**，但长会话与 PFC 视野有损。

### 🔴 R3 · 预算与历史正反馈劣化 —— **定案（长会话触发）**

**证据**：
- `memory_max_ratio_of_history: 1.0`（retrieval-fusion-config.ts:227 默认值）；
- **`C = clamp(histChars × 1.0, 200, 8000)`** —— 记忆预算 = 历史字符数（封顶 8000）；
- 压缩发生时 `enrichedHistory` 变短 → `histChars` 变小 → **C 同步缩水**。

**结论**：长会话触发压缩后，**"她忘了上文"与"记忆注入变少"同时发生且互相强化**（正反馈劣化）。日常 <80 条会话不触发，但一旦触发双重劣化。

**M2 修复方向**：预算解耦——压缩时记忆预算不下调（C 的下限提高或改按"原始历史"计），切断正反馈。

### 三根因权重

| 根因 | 影响面 | 权重 |
|---|---|---|
| **R1 查询零上文** | **全时段** | **主因（M2 第一优先）** |
| R3 预算正反馈 | 长会话（>80 条） | 次因（M2 一并修） |
| R2 残余（PFC 视野/压缩） | 长会话 + PFC 决策 | 辅因（审计结论，按需调） |
