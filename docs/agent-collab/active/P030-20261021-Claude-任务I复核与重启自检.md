## 三、🔴 根因定位：`harness-mcp` 为什么「停了又活」

不是 watchdog 的猜测 —— 是代码写死的自愈逻辑：

```
D:/AI文件/harness/scripts/pm2-recover.cjs:128-131
  addAction('harness-mcp','ok','已停止/缺失，从 start.cjs 重新启动');
  cmd(`npx pm2 start <startScript> --name harness-mcp …`)
```
`harness-watchdog` 定期执行 `pm2-recover`，**看到 harness-mcp 处于 stopped 就主动 start**。
⇒ **单停 harness-mcp 永远不生效**（本轮实测：02:18 停 → 02:25 复活 → 02:27 再停 → 54 秒后又活）。

**本轮处置**：同时 `pm2 stop harness-watchdog` + `pm2 stop harness-mcp`，观察 60 秒稳定：
`harness-mcp=stopped / watchdog=stopped / 3000 唯一监听 45296 / server.ts 进程只剩主链` ✅

⚠️ **副作用与待决**：watchdog 停着期间 Harness 自愈暂停（`harness-sentinel` 目前是 `waiting restart`）。
若恢复 watchdog，harness-mcp 会在一分钟内再次回来。**长期解法需业主定**：
① 保持 watchdog 停用（harness 自愈暂停）；② 或改 `pm2-recover` 支持「维护模式白名单」（改 harness 自身 =
管理员解锁 + 流水线令牌，属另一项治理工作）。
