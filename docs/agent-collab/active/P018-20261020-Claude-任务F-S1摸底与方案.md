## 二、方案F（四条 + 兜底 + 自检）

### F-0 前置·标签分层
orchestrator 循环注入改为按 hit.route 分标签：
- dialog_group → 【X的对话组·MM-DD】
- 高钙路已被该循环 continue 跳过（保持）
- 单条记忆仍为 【X的记忆·MM-DD】

### F1/F2 配额裁剪 — 新增纯函数 applyRecallQuota(fragments, opts)
- 分类正则表：A=高钙组、B=对话组/摘要、RECENT=记忆/记忆·相关、OTHER=铁律/金库/作品/时间检索（OTHER不占配额，只受全局cap）
- 基数 C = clamp(历史×memory_max_ratio_of_history, 200, hard_max_chars)（与chat.ts同一公式，抽成共享helper或现场算）
- 会晤：A 40% / B 40% / RECENT 20%；非会晤：B 60% / A 40%（近期记忆并入B侧60%）
- 类内按现有注入顺序截到各自额度；某类用不完→余量按配置转给其他类（默认不转）

### F5 泛词降权
泛词 = keywords.length===0 或 命中候选<阈值 ⇒ A类比例降到 recall_quota_generic_query（建议0.15），让出的额度给 RECENT + B

### F3 去重与冲突
- 维持前20字前缀去重
- 同组两路命中：runRetrieval内共享 injectedGroupIds: Set，高钙通道遇到已由块路注入的组直接跳过
- 全局：OTHER + 配额类合计 ≤ C
