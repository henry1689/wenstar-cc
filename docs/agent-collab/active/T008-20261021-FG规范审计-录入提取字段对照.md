# T008 · FG 规范审计

## 🎯 审计目标
全面审计 FG（家庭图谱）的录入和提取逻辑，输出**字段对照表**（写了什么/读了什么/是否对应），找出不一致和缺失，为后续规范制定提供依据。

## 📋 审计范围

### 一、数据结构审计
1. **nodes 表**：所有字段、类型、必填/可选、默认值、约束
2. **edges 表**：所有字段、类型、必填/可选、关系类型字典
3. **properties.dossier 七子卷**：selfProfile / socialIdentity / lifeMilestones / boundDocuments / _changeHistory / misc / _deprecated 的完整字段
4. **HumanWorldGraph 四表**：hwg_persons / hwg_relations / hwg_events / hwg_profile_snapshots 与 FG 主库的字段映射

### 二、录入路径审计（3 条路径）
1. **PAE（ProfileAcquisitionEngine）**：写入哪些字段？校验规则？
2. **FGRelationExtractor**：LLM 提取关系写入 edges 的哪些字段？confidence/reason 格式？
3. **HumanWorldGraph.enhanceFromConversation**：写入 hwg_* 表的哪些字段？_guessRelationType 的规则？

### 三、读取路径审计
1. **EntityContextBuilder**：从 dossier + edges 读取哪些字段？构建 LLM 上下文的逻辑？
2. **getUUIDByName / getEntityByUUID**：查询逻辑、别名匹配、void 状态处理
3. **getPersonProfile / getPersonBio**：读取哪些字段？
4. **RelationHeatTracker**：读取和更新哪些字段？

### 四、读写对应审计
- 输出**字段对照表**：字段名 | 录入路径是否写入 | 读取路径是否使用 | 是否对应 | 备注
- 找出"写了但不读"（死字段）和"读了但不写"（缺失字段）

### 五、专项审计
1. **社团/组织关系**：是否有社团节点？是否有"人属于社团"的边？缺失程度？
2. **DNA/基因码**：gene 字段的生成规则、校验规则、使用场景
3. **安全密级**：security_level 的取值、使用场景、是否在读取时过滤
4. **关系类型字典**：RELATION_TYPE_DEFS 完整性，是否有未定义的关系类型被写入
5. **双库一致性**：FG 主库与 HWG 影子库的字段映射是否完整，双写是否一致

## 👥 分工（交叉验证）

- 审计读取逻辑中的问题（如方向修正、去重、密级过滤）

### PI（写入侧审计）

- 审计写入逻辑中的问题（如必填校验、关系类型验证、DNA生成）

### 交叉验证（两人共同完成）
