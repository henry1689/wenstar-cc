### 1.3 量纲红线（摘自法令，施工时随身携带）

1. **只有 40D**。`PERCEPTION_40D_DIM = 40`，任何 24D / 32D / 36D / 14D / 20D 出现即违法。

4. **扇区加权合法，子维度切片违法**。判据见白皮书 §4.3.3。
5. **不得以「权重为 0」为由截断维度** —— 存储与接口层恒为 40 维。

### 2.3 错误契约（**fail-open / fail-closed 分界，唯一权威表述**）

| 环节 | 失败时行为 | 理由 |
|---|---|---|
| **围栏 SQL 执行失败** | **fail-closed**：返回 `[]` + `console.warn` | 拿不到候选池就无从判断安全，宁拒不放 |
| **UUID 闸门** | **fail-closed**：空白名单 ⇒ `AND 1=0` | 既有实现已如此（`UUIDPoliceFilter.ts:183`） |
| **五级闸门加载失败** | **fail-closed**：返回 `[]` + 告警 | 🔴 **业主裁决 2026-10-27（方案 A）**，见 §5.3 |
| **40D 余弦计算失败 / 无查询向量** | **跳过语义路**，其余三权重重新归一化 | 法令第四条：无原生 40D 时直接跳过，不得降级 |
| **单个候选的 `perception_40d` 解析失败** | 该候选 `cosine = undefined`，不参与语义项；**不清零** | 缺数据不等于负相关 |
| **LLM 精排失败/超时** | **fail-open**：直接用规则精排结果 | 不得因精排失败而丢召回（白皮书 §4.3.4） |
| **组合海胆聚合失败** | 该组降级为「无组合刺」，靠壳肉文本命中 | 组合刺是辅助信号 |

> 🔴 **两条铁律**：
> ① **闸门与围栏是安全边界，只能 fail-closed**；
> ② **精排与增强是质量优化，只能 fail-open**。
> 把 ② 的容错写法套到 ① 上，就是本条要根治的历史缺陷。

## 第三章 · 围栏层实现

### 3.1 设计原则

1. **高召回、低精度**：目标是「不漏」，不是「准」。
2. **全部走结构化条件**：不建倒排、不建索引表，靠 `LIKE` 分片 + 既有列。
3. **现算优先**：命中分片数由候选文本现算（白皮书 §4.3.2 实测 500 条 < 10 ms）。
4. **UUID 闸门必须第一个拼进 SQL**，不得先查后过滤（后者会把他人的行读进内存）。

### 3.2 SQL 模板

> 所有模板统一由 `buildSqlClause(policy)` 产出 `{ clause, params }` 并**拼在 WHERE 尾部**。
> `policy` 来自 `policyFor(domain, visibleUuids, opts)`（`UUIDPoliceFilter.ts:99`）。

**A. 原子层（memories）**

```sql
SELECT id, raw_input AS text, calcium_score, created_at, belong_entity_uuid, perception_40d
FROM memories
WHERE 1=1
  {policy.clause}                       -- 例：AND belong_entity_uuid IN (?,?,...)
  AND locus_path LIKE ?                 -- 话题前缀；无话题时省略
  {keywordShards}                       -- AND (raw_input LIKE ? OR raw_input LIKE ? ...)
ORDER BY calcium_score DESC, created_at DESC
LIMIT ?
```

**B. 对话组（dialog_groups）—— 主路**

```sql
SELECT id, block_summary AS text, primary_emotion, created_at, turn_count
FROM dialog_groups
WHERE 1=1
  {policy.clause}
  AND block_summary IS NOT NULL AND block_summary <> ''
  {keywordShards}
ORDER BY created_at DESC
LIMIT ?
```

> 🔴 **不得**在此 SQL 里 `SELECT emotion_curve` 做向量比较——对话组无 40D 列，
> 且 `emotion_curve` 是标量序列不是感知向量（见 §7.1 论证）。

**C. 单条对话（conversations）**

```sql
SELECT id, content AS text, created_at, belong_entity_uuid
FROM conversations
WHERE 1=1
  {policy.clause}
  AND created_at >= ? AND created_at <= ?   -- 时间窗；退化期回捞时必须传
  {keywordShards}
ORDER BY created_at DESC
LIMIT ?
```

**D. 作品（works）**

```sql
SELECT id, substr(full_text, 1, 800) AS text, created_at
FROM works
WHERE 1=1 {policy.clause} {keywordShards}
LIMIT ?
```

> 作品级**不造刺**（`works.semantic_vector` 188 行全空，不补），只做文本命中 + 壳肉溯源。
> 800 字切块语义保留自 `SearchIndexBuilder.indexWorkChunks`，但**不建倒排**。

### 3.3 分片构造（`keywordShards`）

```ts
// 每个关键词产出 2 字滑窗分片，最多 8 片，避免 SQL 膨胀
function buildShards(keywords: string[]): { sql: string; params: string[] } {
  const shards = new Set<string>();
  for (const k of keywords) {
    for (let i = 0; i + 2 <= k.length && shards.size < 8; i++) shards.add(k.slice(i, i + 2));
  }
  if (shards.size === 0) return { sql: '', params: [] };
  return {
    sql: ' AND (' + [...shards].map(() => 'raw_input LIKE ?').join(' OR ') + ')',
    params: [...shards].map(s => `%${s}%`),
  };
}
```

> ⚠ **列名随域变化**：`memories` 用 `raw_input`，`conversations` 用 `content`，
> `dialog_groups` 用 `block_summary`，`works` 用 `full_text`。
> 模板必须由域→列名映射表生成，**禁止**在字符串里写死后再 `replace`。

### 3.4 性能预算

| 阶段 | 预算 | 实测基线 |
|---|---|---|
| 围栏（单域，500 候选） | ≤ 100 ms | 38–60 ms ✅ |
| 全部四个域并行 | ≤ 150 ms | 待 S2 实测 |
| 精排（500 → top-K） | ≤ 50 ms | 9 ms（40D 200 条）✅ |

> 超预算的处置顺序：① 降 `LIMIT`；② 减分片数；③ 收时间窗。**不得**为此新增索引表。

## 第四章 · 精排层实现

### 4.1 打分公式（唯一实现）

```
score(m) = w_hit      × norm(hitShards_m)
         + w_calcium  × norm(calcium_m)
         + w_recency  × norm(recency_m)
         + w_semantic × cosine40D(query, m)      // 仅当两侧向量均存在
```

### 4.2 归一化（各分量独立归一，**必须在当次候选集内做**）

| 分量 | 归一化方式 | 边界 |
|---|---|---|
| `hitShards` | `x / max(hitShards)` （max = 0 时该分量整体置 0） | [0,1] |
| `calcium` | `calcium_score / 10`（钙分上限 10） | [0,1] |
| `recency` | `1 - min(1, ageMs / HALF_LIFE_MS)`，半衰期 30 天 | [0,1] |
| `cosine` | 直接取 `cosineSimilarity40D` 返回值 | [-1,1] |

> 🔴 **`recency` 半衰期 30 天是常量**，改它等于改召回性格，须走白皮书修订。
> 🔴 **`max(hitShards) = 0` 时不得除以零**：该分量整体置 0，其余三权重重新归一化。

### 4.3 40D 余弦调用（**唯一合法写法**）

```ts
import { decodePerceptionV40, cosineSimilarity40D } from '../../m2/PerceptionVector40DCodec.js';

const qv = options.p40;                    // M3 原生，不得二次投影
if (qv) {
  for (const h of hits) {
    if (!h.perception_40d) continue;       // 无向量 → cosine 保持 undefined
    const mv = decodePerceptionV40(h.perception_40d);
    if (!mv) { h.cosine = undefined; continue; }   // 解析失败不清零
    h.cosine = cosineSimilarity40D(qv, mv);
  }
}
```

> 🔴 `cosineSimilarity40D` **接收两个 `PerceptionV40` 对象，不是数组**（`PerceptionVector40DCodec.ts:272`）。
> 🔴 **禁止** `map24DTo40D` / `buildFallbackV40` 作为查询投影（法令第四条明令违法）。
> 🔴 **禁止**新增 `cosineSimilarity40DSemantic` / `resonanceVector40D` 等一切切片实现。

### 4.4 无向量时的权重重归一

```ts
const active = {
  hit: w.hit, calcium: w.calcium, recency: w.recency,
  semantic: anyCosine ? w.semantic : 0,
};
const sum = active.hit + active.calcium + active.recency + active.semantic;
// 逐项 / sum 后使用
```

> 这样「无 40D」时是**跳过语义路**，而不是把余弦当 0 分拉低全池 —— 两者数学结果不同，后者属变相降级。

### 4.5 LLM 精排兜底（默认关闭）

| 项 | 规定 |
|---|---|
| 触发 | `w_semantic` 关闭 **且** top-K 边界分数方差 < 阈值 |
| 输入 | top 20 候选正文，每条约 200 字 |
| 输出 | 重排后 top-K |
| 成本 | 约 5–10k token/次；**必须可开关** |
| 失败 | **fail-open**：用规则精排结果 |
| 开关 | `RETRIEVAL_V11_LLM_RERANK`（默认 `false`） |

> 🔴 LLM 输出**只能改变顺序**，不得增删候选（增删会绕过闸门的成员过滤语义）。

## 第五章 · 五级闸门挂载（**含 fail-closed 改造**）

### 5.1 两个挂载点（缺一即合规缺陷）

| # | 位置 | 覆盖链路 |
|---|---|---|
| ① | `MemoryRetriever.ts:463-494`（`retrieveMemories` 出口） | 主对话注入链路 |

> 🔴 白皮书 §4.1.1 与 §5.1：闸门是「唯一读取通道，无旁路」。
> **v11 重构必须原样保留这两处调用**，不得因为「新链路自带过滤」而省略。

### 5.2 容器层不映射 `cosine_score`（**易踩的坑，原样保留**）

`FiveStageGate.filter` 的 G1 有一段「池内只要有任一候选带分，就把无分候选全部清零剔除」的逻辑
（`FiveStageGate.ts:129-135`）：

```ts
const hasScores = pool.some(m => (m.cosine_score ?? m.similarity_score ?? 0) > 0);
if (hasScores) pool = pool.filter(m => (m.cosine_score ?? m.similarity_score ?? 0) >= 0.3);
```

六路混合池里绝大多数候选**没有**余弦分。一旦给某一路映射了 `cosine_score`，
**其余所有路会被整体清零**。

> 🔴 **规定**：容器层（挂载点 ①②）**只映射 id / 文本 / 钙分 / 时间 / locus**，
> **不得**映射 `cosine_score` 或 `similarity_score`。语义初筛由 spine 路内部（floor=0.3）完成。
> 这是**设计**，不是权宜；改它等于让闸门吃掉五路召回。

```ts
}
```

**改造约束**：

| 约束 | 说明 |
|---|---|
| 返回类型不变 | ① 仍 `Promise<DNA[]>`；② 仍 `Promise<MultiRankResult>` |
| 缓存不得先写 | ① 的会话缓存写入（`:496-500`）在闸门之后，改造后 `return` 早于写缓存，顺序正确 |
| 告警级别 | 必须 `console.error`（原 `warn`）。fail-closed 是**异常**，不是可忽略的降级 |
| 可观测 | 每次 fail-closed 触发须累加 `gate_failclosed_total` 计数（见 §8.1） |
| 上线节奏 | 与 S2 新链路**同批次**，但**独立可回滚**（`RETRIEVAL_V11_GATE_FAILCLOSED`） |

> 因此 S6 必须专测「故意破坏 dynamic import，确认返回空而非全量放行」。

## 第六章 · 组合海胆聚合

### 6.1 公式与实现（**纯计算，不落盘**）

```
spine(G) = Σ_{i∈G} w_i · spine(member_i) / Σ_{i∈G} w_i ,   w_i = calcium_score_i
```

```ts
export function aggregateSpines(members: Array<{ spine: number[]; weight: number }>): number[] | null {
  const valid = members.filter(m => Array.isArray(m.spine) && m.spine.length === 40 && m.weight > 0);
  const wSum = valid.reduce((s, m) => s + m.weight, 0);
  if (wSum <= 0) return null;                       // 无有效成员 ⇒ 无组合刺，不伪造零向量
  const out = new Array(40).fill(0);
  for (const m of valid) for (let d = 0; d < 40; d++) out[d] += m.weight * m.spine[d] / wSum;
  return clampSpines(out);
}
```

### 6.2 值域钳制（逐维，不可省）

| 维度 | 值域 |
|---|---|
| D01–D35 | `[0, 1]` |
| D36 / D37 | `[-1, 1]` |
| D38–D40 | `[0, 1]` |

> 钳制必须在**聚合输出**处做一次，而不是逐个成员做（逐成员钳制会改变加权平均的数学性质）。

### 6.3 不落盘（ADR-013 豁免边界）

| 禁令 | 理由 |
|---|---|
| 🔴 禁止为 `conversations` / `dialog_groups` / `works` 新增任何 40D/向量列 | 违反 ADR-013 ②「状态只有一处写」 |
| 🔴 禁止把组合刺写进 `search_index` 或任何缓存表 | 成员变动/钙化衰减会让缓存永久过期 |
| 🔴 禁止在组合刺上做 40 维以下截断 | 违反法令第二条 |

> **ADR-013 豁免声明**：组合刺**不进入存储层**，不构成「派生字段」这一 ADR-013 所约束的对象。
> 本裁决不修改 ADR-013，仅明确其适用范围止于**持久化字段**。

### 6.4 成本

单个对话组平均 `turn_count = 2.1`，成员极少 ⇒ 单次聚合 < 0.1 ms。
**不需要缓存**；若实测某组异常大（> 100 成员），降级为「不聚合，只用壳肉」。

## 第七章 · 对话组召回主路

### 7.1 为什么必须走 `block_summary`（不是次优选择）

生产库实测（2026-10-26，只读）：

| 层 | 40D 覆盖 | 结论 |
|---|---|---|
| `memories` | 100% | 唯一真值载体 |
| `conversations` | ❌ 无此列 | 只能文本命中 |
| `dialog_groups` | ❌ 无此列 | **只能 `block_summary`** |
| `works` | ❌ `semantic_vector` 188 行全空 | 只能全文切块 |
| `black_diamond` | 96.4% | 可语义精排 |
| `knowledge_base` | 96.5% | 可语义精排 |

> 对话组没有向量，`cosineSimilarity40D` 无从作用。**文本摘要召回是唯一可行主路**。
> 🔴 `emotion_curve` 是标量时间序列，**不是** 40D 感知向量，**不得**拿去算余弦（会造出第 41 种量纲语义）。

### 7.2 检索流程

```
查询
  ├─ ① 摘要通道：dialog_groups 围栏（block_summary LIKE 分片，UUID 闸门）
  ├─ ①' 原文通道：conversations 按 dialog_group_id 聚合（不经过 block_summary 的 extraWhere）
  ├─ ② 候选合并：摘要命中 ∪ 原文命中（ADR-010 §12.2.2），回表补 turn_count / 钙分 / 时间戳
  ├─ ③ 精排（ADR-010 §12.2.3 四分量，见 §7.5）
  ├─ ④ 组内展开：按 group_id 取成员 memories 的原生 40D
  └─ ⑤ 五级闸门（挂载点 ②）
```

> 🔴 2026-11-02 更正：原 §7.2 写的精排是 `hit(壳肉) + calcium + recency + semantic`
> —— 那是**改造前**用通用四权重的实现。对话组自 v11.4 起按 ADR-010 §12.2.3 的
> 专属四分量执行，见 §7.5。排序**引擎**仍是 `scoreAndRank` 一处，分量以方案声明。

### 7.3 未命中 `block_summary` 的组

现状：`dialog_groups` 共 2,779 组，`block_summary` 非空 2,335 条（84%）。
剩余 444 组走**兜底**：

1. 取组内首条 conversation 的 `content` 前 200 字作伪壳肉；
2. 标记 `hitSource: 'fallback_first_turn'`，精排时 `w_hit` 乘 0.5；
3. **不得**因此给组新增字段存伪摘要（ADR-013 ①）。

### 7.4 对话组召回退化处置

| 情形 | 处置 |
|---|---|
| 组内所有成员 `perception_40d` 全缺 | 组合刺 = `null`，语义项按 §4.4 重归一化 |
| `turn_count` 异常（> 100） | 不聚合，只用壳肉；记 `WARN` |
| `block_summary` 为空且首条也为空 | 跳过该组，计入 `dialog_group_skipped_total` |
| **双通道候选 SQL 抛错**（ADR-010 §13.4） | 降级 `dialog_groups` 单表按 `last_ts DESC` 取块，**不得整路返回空**（返回空 = 该组永远召不回且对调用方完全静默）；告警 `console.warn` 可追责 |
| 本池某分量全体算不出（如全组无摘要命中） | 该分量权重置 0 并把其余权重重归一（§4.4），**不是**按 0 分拉低全池 |

### 7.5 对话组精排四分量（ADR-010 §12.2.3，业主确认 2026-10-18）

```
score = convDensity×0.40 + summaryDensity×0.30 + bothChannels×0.15 + calcium×0.15

convDensity    = min(1, 原文命中轮数 / turn_count)
summaryDensity = min(1, 摘要命中分片数 / 10)
bothChannels   = 原文与摘要同时命中 ? 1 : 0
calcium        = min(1, block_calcium_score / 5)     ← 基准 5 见 ADR-010 §13.1
```

- **纯原文最高 0.55、纯摘要最高 0.45** —— 摘要命中略低于原文，但足以进入候选集。
- **无 `recency` 分量**：法典只列四项，不得擅自补时间近因（补了就是第二套判据）。
  时间次序由最终排序按 `last_ts` 做同分 tiebreak 承担。
- **两路量纲不同**：摘要给「命中分片数」、原文给「命中行数」，**禁止相加**；
  分别记入 `EnclosureHit.channels.summary` / `.content`，判据一律走 `channels`。
  `payload.hitShards` 保留相加值**仅供观测**，不参与精排。
- **实现形态**：分量以 `ADR_010_BLOCK_SCHEME` 声明在 `StructuredRecall.ts`，
  权重常量在 `Flags.ts` 单一产出点；引擎仍只有 `scoreAndRank` 一处（不变量 #7）。

### 7.6 🔴 通道主次与拆除方向（业主 2026-11-02 裁定）

| 通道 | 定位 | 质量要求 |
|---|---|---|
| **原文通道**（`conversations` 聚合） | **主通道，长期保留** | **必须高质量** —— 召回质量的投入全在这里 |
| 摘要通道（`block_summary` 围栏） | **妥协产物，临时使用** | **不要求高质量** |

**为什么摘要是妥协**：历史 `block_summary` 是 LLM 已生成的**新增内容**，无法从原文还原 ——
不保留就等于把这批数据的可召回性一次性丢掉，故临时保留；它**不是长期备用通道**，
业主已明示后续会拆除。

**拆除时的结构保证（已由守卫锁住）**：摘要通道只在三处被引用 ——
① `DialogGroupAdapter` 的 ①a 段；② `channels.summary` 字段与 `summaryDensity` / `bothChannels`
两个分量；③ 组装时的【摘要】前缀与 `payload.summary`（含 `DOMAIN_SPECS` 的
`textCol='block_summary'` / `extraWhere`）。三者之外无代码依赖 ⇒ **拆除是删代码，不是改判据**。
两个摘要分量走**可用性判定**，摘要恒为 0 时权重自动置 0 并重归一，
方案退化为 `convDensity + calcium`，**引擎一行不用改**
（守卫：`adr010-block-ranking.test.ts`「摘要通道整体为 0 ⇒ 自动退化」）。

**排序分量的后续**：业主裁定「现在能检索查询到就行」—— 拆除摘要后分量如何重定
**另立任务书**，本次不改 ADR §12.2.3 条文。

### 8.2 每日缺口台账（S1.1 方案② 强制配套）

**文件**：`data/retrieval-v11/gap-ledger.jsonl`（一行一天，追加写，不覆盖）
**开关**：`RETRIEVAL_V11_GAP_LEDGER`（S1 起置 `true`，S3 专项回捞验收后置 `false`）
**写入时机**：每日 00:05 由定时任务写入**前一日**记录；进程重启不补写（断档即视为验收失败）

**字段定义**

| 字段 | 类型 | 含义 |
|---|---|---|
| `date` | `YYYY-MM-DD` | 统计日（本地时区） |
| `s1_started_at` | ISO8601 | S1 落地时刻，全程不变 |
| `n_gap` | int | 当日新增且**未进旧索引**的 conversation 条数 |
| `cum_gap` | int | 自 `s1_started_at` 起的累计缺口 |
| `conversations_total` | int | 当日 23:59 的 `conversations` 表总行数 |
| `expected_total` | int | `s1_start_conversations_total + cum_gap` |
| `first_gap_id` / `last_gap_id` | string | 当日缺口区间的首尾 id（用于回捞） |
| `verifier` | string | 校验命令或脚本名（可复现） |
| `note` | string | 空串或断档说明 |

**样例**

```json
{"date":"2026-10-28","s1_started_at":"2026-10-27T21:00:00+08:00","n_gap":412,"cum_gap":412,"conversations_total":14707,"expected_total":14707,"first_gap_id":"14296","last_gap_id":"14707","verifier":"node scripts/v11-gap-audit.cjs --date 2026-10-28","note":""}
```

**对账判据（写入前必须自检，失败则不写并告警）**

1. `n_gap >= 0` 且 `cum_gap == previous.cum_gap + n_gap`（首日 `previous.cum_gap = 0`）；
2. `conversations_total == expected_total`（误差必须为 **0**，不接受近似）；
3. 台账日历**无断档**：相邻两条 `date` 相差 1 天。

> 🔴 三条任一不满足 ⇒ 当日记录写 `note` 说明并以 `ERROR` 落日志，**不得静默跳过**。
> S3 后的「专项回捞」以 `ΣN_gap` 与 `[first_gap_id, last_gap_id]` 区间为输入清单。

### 8.3 度量口径（S2 双跑报表必含）

| 口径 | 定义 |
|---|---|
| 召回覆盖率 | 「旧链路每条结果 ∈ 新链路候选集」的查询占比 |

> 🔴 统计前必须剔除 `< 2s` 的 run（测试污染生产审计的已知坑）。

## 附录 C · 更新摘要（2026-11-02）

**标题**：对话块精排改按 ADR-010 §12.2.3 四分量执行（`RankingScheme` 分量可插拔）

**变更条目**

1. **§7.2 检索流程与精排分量更正** —— 对话组精排不再是 `hit + calcium + recency + semantic`，
   改为 ADR 法典四分量 `convDensity×0.40 + summaryDensity×0.30 + bothChannels×0.15 + calcium×0.15`
   （钙分归一基准 `/5`，见 ADR-010 §13.1）。新增 **§7.5** 作为该公式的蓝皮书侧定义源；
   排序**引擎**仍只有 `StructuredRecall.scoreAndRank` 一处，分量以 `ADR_010_BLOCK_SCHEME` 声明，
   权重常量在 `Flags.ts` 单一产出点（不变量 #7）。
2. **双通道计数分离** —— `EnclosureHit.channels{summary, content, turnCount}` 分别承载
   摘要命中分片数、原文命中轮数、组总轮数。两路量纲不同（分片数 vs 行数），**禁止相加**；
   `content = max(命中 user 行, 命中 assistant 行)`，与 `dialog_groups.turn_count` 同为「轮」
   （2026-11-02 起该列口径为已落库问答对数）。`payload.hitShards` 保留相加值仅供观测。
3. **§7.4 新增两条退化处置** —— ① 双通道候选 SQL 抛错时降级 `dialog_groups` 单表按
   `last_ts DESC` 取块，**不得整路返回空**（ADR-010 §13.4）；② 本池某分量全体算不出时
   权重置 0 并重归一（§4.4），不是按 0 分拉低全池。

4. **`is_summary` 双职责分离（摘要归并批1/批3）** —— `conversations` 里的摘要行
   `is_summary=1`：**只参与召回、不参与计数**。原文通道聚合 SQL 用 CASE 分列：
   `hit_rows`/`u_hit`/`a_hit` 一律 `COALESCE(is_summary,0)=0`，否则摘要行会让每组
   凭空多出 1 个「命中轮」，`convDensity = max(u_hit,a_hit)/turn_count` 失真。
   召回与计数在**同一条 SQL** 内分开 ⇒ **仍是一条通道**，不拆第二路、不 UNION。
   同时给「内容会交给模型 / 被当原文再加工」的读取点补 `is_summary=0`
   （🔴 必堵 `BlockSummaryService`：读原文生成摘要，不堵会把摘要当原文再摘要）。
   **收口先于数据落地**；迁移前两批零行为变化（现有 213 行摘要行的 `dialog_group_id` 全为 NULL）。

5. **召回与卷宗读取点收口（摘要归并批3b）** —— `ConversationAdapter` 关键词检索、
   `meeting-recall` 三条召回路（关键词 `LENGTH>150` / 时间窗 `LENGTH>40` / 结构化）、
   `KnowledgeAccessFacade.queryConversationFallback`、`BlockArchiveService` 与
   `BArchiveReader` 卷宗读写，一律补 `COALESCE(is_summary,0)=0`。
   判据三分类：**内容会交给模型 ⇒ 堵**；纯统计 COUNT ⇒ 记账不改；
   `LENGTH>=500/800` 类本就捞不到摘要 ⇒ 不改（避免无意义 diff）。
   **九层管线架构图无变更** —— 改动全收在层内。
