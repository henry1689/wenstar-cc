## 0. 一句话

**把「会晤模式」换成一个自然的对话空间：人在就听得见，走了就不知道，叫谁谁来。**

不再有模式切换，只有三件事：**谁在场**、**这话冲谁**、**下一句谁说**。

---

## 1. 业主原话与需求锚点（2026-10-29）

> 「完全有真人对话那种感觉，叫谁谁来，叫谁走谁走，没有那么多模式机械切换，信息改绝对隔离就绝对隔离，该共享的就共享，一个人在几个人里聊了一会又走了，走了的就不应该知道后聊的内容，等等，一切都为自然而设计」

> 「核心问题就是重构这个分配器系统」

这段话拆出来是**两类**需求，不是一类：

| 类别 | 需求 | 关键词 |
|:---|:---|:---|
| **可见性** | 走了的不知道后聊的；该隔离就隔离，该共享就共享 | 「听得见 / 不知道」 |
| **分配器** | 叫谁谁来、叫谁走谁走、不靠模式切换 | 「谁接话」 |

⚠️ **本项目最重要的一条教训**：第一版只实现了「可见性」。隔离确实修好了（玉瑶说"手上没有落成字"、诗雨说"诗雨这边没听着"），但业主的主诉——分配器——**一点没动**：换人仍被拒绝，勉强放行后标签与内容分裂。

**判据**：只有「叫谁谁来」当场生效，才算完成。隔离改善带来的"干净"会让实现者误判任务已完成。

## 2. 领域模型：对话空间的三条关系

任意一条消息都同时挂着三条互相独立的关系：

| # | 关系 | 含义 | 类型谓词 |
|:--:|:---|:---|:---|
| ① | **可感知** | 这条消息**谁听得见** | `canPerceive(seat, event)` |
| ② | **指向** | 这句话**是冲着谁说的** | `address` |
| ③ | **发言权** | **下一句由谁来说** | `focus`（🔴 **不属内核**，唯一真源是 `GroupSession.speakerUuid`） |

三者不能合并：

- 阿珍在场（①成立）不等于这话是对阿珍说的（②）；
- 这话是对阿珍说的（②）不等于下一句一定阿珍接（③，业主可以自己接着说）；
- 阿珍听得见（①）但轮不到她说（③）—— 这叫**旁听**，是常态不是异常。

**反面实证**（真机）：阿珍在场，业主后来说「阿珍，我刚刚说叫你别忘了带什么」，阿珍答"那会儿阿珍在旁边收拾东西，没听真切"。①成立但她无法判断那句是否**点名对她**——缺的正是②。

### 2.1 任期公理（唯一判定式）

```
canPerceive(seat, event) :=
  ∃ period ∈ seat.periods :
      event.ts >= period.enteredAt
   && (period.leftAt === undefined || event.ts < period.leftAt)
   && audienceIncludes(event.audience, seat.uuid)
```

- **任期（tenure）** = 席位从进入空间到离开空间的时间区间。可有多段（多次进出），每段独立、升序、互不重叠。
- 一条消息只有在席位**在场的那一刻**被发出，才算「听得见」。

**由公理直接推出的行为**（无需额外规则）：

| 行为 | 直接来源 |
|:---|:---|
| 走了的看不到后来的 | 任期上界 `leftAt` |
| 新人看不到旧历史 | 任期下界 `enteredAt` |
| 两人在场都听得见 | `audience.kind === 'room'` |
| 耳语只有目标可见 | `audience.kind === 'seat'` |
| 中间离开再回来，空白段永久不可见 | 多段任期之间的空白 |
| 空间空 = 业主独处、无人应答 | 无在场席位 ⇒ 无人可应答（见 §2.5） |

> **🔴 边界注释（2026-10-30 业主确认）**：**场景标签**（公园 / 会议室 / 线上会议 等）是空间的**附属元数据**，**不参与 `canPerceive` 路由判定**，仅用于角色感知环境氛围、影响对话文案与措辞。
> 可见性**只由「席位任期 ∧ audience」决定**。空间（路由器）与场景（情境描述）是两件事，不得混用。

### 2.2 第一条铁律：说话人标签必须真实

> **转述别人的话，标签必须还写别人的名字，不能写成自己的。**

旧实现把所有 assistant 轮硬标成「当前会晤实体名」，于是 B 不在场时 A 和业主的对话被标成 B 说的——这是「串台」在语法层的根因，也是模型被误导的直接原因（它会照着标签把不属于自己的话认成自己说的）。

空间路由器把标签来源改成**事件的 `actorUuid`**：

- 每条 `say` 事件记录真实说话人；
- 视图里呈现时用**真实说话人名**，而不是「当前发言人」；
- 归属未知的轮次**不猜**（fail-closed），只留诊断。

**这条判据比任何过滤逻辑都重要：标签错了，再准的过滤都是假的。**

### 2.3 第二条铁律：宁可多看，不可全盲

时间锚点类缺陷（会晤起点、任期起点）一律遵循：

- 数据合法 → 精确；
- 数据损坏 / 缺失 → **退化为「看得见更多」**，绝不退化为「全部看不见」。

理由：全盲是**静默失忆**（角色突然不认识刚才聊过什么），且极难定位——症状往往只表现为「角色有点怪」。多看是可见的冗余，边界仍由窗口（`startIndex`）收紧，不会越权。

⚠️ **反面实证**：会晤起点只看**首行**时间戳。首行恰好缺时间戳 ⇒ 锚点 null ⇒ 首次入场被锚到「现在」⇒ 会晤内全部历史落在任期之前 ⇒ `历史=0条`。症状极具迷惑性：事件数 173、席位 5（在场 1）、诊断只有几条 `ts_missing`，唯独历史为空。

### 2.4 第三条铁律：隔离不是让事件消失

事件永远留在流里，隔离**只作用于正文可见性**：

- `privateContent` —— 仅 audience 内可见；
- `publicMeta` —— 全员可见的摘要（如 `{type:'whisper', from, to}`），**仍受任期约束**。

于是离场者知道「那会儿有人在说话」，但不知道说了什么。这更接近真人：**你走了，你知道他们在聊，你只是不知道聊了什么。**

### 2.5 独处：没人应就证明只有自己（2026-10-31 接线）

由公理直接推出的一条**产品行为**：空间里有过席位、但此刻**零人在场**时，

- **不生成任何回复**（没有角色可以应答）；
- 业主的发言**照常落库**，记在本体 UUID（`TXS-000000001`，即玉瑶档案 —— 玉瑶是本体人格）。

这叫**自言自语**：说得出去，收不到回应。它不是"系统坏了"，恰恰是"确实只有你一个人"的证据。

⚠️ 判据刻意保守：只看**已经有过任期**的空间。从未建立过任何席位时维持既有玉瑶态 ——
把"第一次聊天"误判成独处，会让系统看起来像死掉。

### 2.6 耳语：一对一的私有通道（2026-10-31 接线）

**耳语不是一种状态，它只表示"人多时两个人的私下说话"。**

| 维度 | 规则 |
|:---|:---|
| **记录** | 与**一对一私聊完全相同** —— `belong_entity_uuid` 记听众本人，不是当前发言人 |
| **落库** | 库里没有任何"耳语"标记：无标记列、无动作描述、无占位文本 |
| **不共享** | 运行时只有听众能读到正文；其余在场者看到「（鸿艺压低声音，跟人耳语了几句——你没听清）」 |

占位文本是**渲染期生成的，不写入存储**。从数据库看，一条耳语和一条普通私聊记录长得一模一样。

> ⚠️ **已知限制**：运行时隔离依赖内存里的标记，重启后重新摄取会退化为全场可闻。
> 这是刻意取舍（业主裁决 2026-10-31：不为此新增状态）。

#### 2.6.1 目标离场时的耳语：可见，但不降级（2026-10-31 补齐）

业主对**已离场**的人耳语时，`audience={seat, uuid}` 而目标不在任期内 ⇒
`canPerceive` 对任何席位都不成立，正文无处可去。

处理原则有两条，取其一：

| 方案 | 后果 | 采纳 |
|:---|:---|:---|
| 降级为 `audience=room` | 业主以为的悄悄话变成全场可闻 | ❌ 隐私泄漏 |
| 保持 `audience=seat`，但**留下告警** | 消息确实没送达，但不再无声无息 | ✅ |

故 `route()` 在该情形下向 `warnings` 追加 `whisper_target_offscreen:<uuid>`。
**分流结果不做静默修正**——内核只保证「异常可被观测」，是否提示用户由上层决定。

## 3. 系统定位：路由器是「分配器」，不是「过滤器」

### 3.1 旧模型的问题

模式（普通 / 会晤 / 群聊）是**显式状态**，需手动切换，每个模式内部各有一套「谁说话」的判定。结果：

- **六个说话人来源并存**并互相漂移：intent 换人 · `_activeMeetingName` · Stage2 `_meetingEntityName` · `GroupSession.speakerUuid` · outputGuard 标签 · 适配器视图；
- 内核里养着一套「发言权」模型（`pendingTokens`）**全仓无消费者**，而真实的"谁答"由另外两套决定；
- 换人被门卫拦截；勉强放行后外层标签写「玉瑶」、内容里全是「诗雨」——标签与内容分裂。

### 3.2 新模型：一条关系只有一个真源

| 关系 | 唯一真源 | 载体 |
|:---|:---|:---|
| ① 可感知 | `SpaceState.seats[].periods`（任期） | `buildViews` |
| ② 指向 | 事件的 `address` 字段 | `SpaceEvent.address` |
| ③ 发言权 | `GroupSession.speakerUuid`（**不在内核**；内核原有的 focus/令牌模型已删除） | 运行时状态机 |

**原则：一条关系只能有一个真源。多真源必然漂移。**

### 3.3 系统里没有例外

> 业主 2026-10-29 明确：**无默认发言人；玉瑶与其他席位完全同权，可被叫来、可被叫走；空间为空 = 业主独处，可以自言自语，没有人应答。**

这条写法很关键——任何"某角色永远在场 / 永远优先"的实现都是对本模型的破坏，会重新引入不可见的第二种真源。

### 3.4 平台无关性

内核（`types.ts`、`SpaceRouter.ts`）**零依赖、零 IO、零 LLM、不读时钟**（时间由调用方传入）。平台事实（对话历史、参与者列表、当前发言人）由**适配层**翻译。

理由：内核可被单测完全覆盖；换平台（chat / 语音 / 未来其它）不需要改内核。

## 4. 不变量（违反即抛错，不静默降级）

| # | 不变量 | 检查点 |
|:--:|:---|:---|
| I1 | 每段任期 `leftAt > enteredAt` | `exportSnapshot()` |
| I2 | 同一席位各任期按时间升序且互不重叠 | `exportSnapshot()` |
| I3 | 只有**户籍登记过**的 UUID 能进入席位表（防僵尸席位） | 适配层 `_register()` / `recordAgentSay()` |
| I4 | 归属未知的 assistant 轮**不猜归属**，只留诊断 | 适配层 `syncFromHistory()` |
| I5 | 事件时间戳回落时只告警**不纠错**（乱序真实存在，纠错会篡改历史） | `route()` |
| ~~I6~~ | ~~只有在场席位能获得发言令牌~~ | 🔴 2026-10-30 **随令牌模型一起删除** |
| ~~I7~~ | ~~focus 离场回落 null~~ | 🔴 2026-10-30 **随 focus 模型一起删除**；「不自动转给他人」现由 GroupSession 保证 |

**为什么在导出时校验而不是每次 apply 后**：`buildViews` 是 O(席位×事件) 全量扫描，每轮调用多次，长会晤退化 O(n²)。校验只在需要留证的时刻跑。

**纯函数不变性**：外部禁止直接改 `SpaceState`；所有变更只能通过 `route(state, flow) => nextState` 推进；存储适配器只负责 serialize / deserialize，不做任何业务修改。由此**回放 = 按时序喂 flow 逐步复现**，天然可复现、可审计。

### 4.1 视图派生层的求值策略（2026-10-31）

视图派生是**纯读**，不参与任何状态写入。三层策略按「谁真正需要」逐级收敛：

| 层级 | 函数 | 求值时机 | 消费者 |
|:---|:---|:---|:---|
| 写路径 | `route()` 的 `out.views` | **惰性 getter**，首次访问才算 | 生产链路 0 处；测试 7 处 |
| 单席位 | `buildViewFor(state, uuid)` | 调用即算，只扫一遍事件 | `turnsFor()` |
| 全量 | `buildViews(state, events)` | 调用即算，逐席位 | 诊断与契约测试 |

三条实测量（2006 事件 / 3 席位）决定了这个分层：

| 环节 | 耗时 | 说明 |
|:---|---:|:---|
| `route` 单次（视图惰性化后） | 0.008 ms | 惰性化前 0.321 ms，因为每次都在算无人读取的全量视图 |
| `buildViewFor` 单席位 | 0.044 ms | 全量版 0.214 ms —— 只读一个席位时不该付全量的钱 |
| `turnsFor` 全量 | 1.86 ms | 优化前 5.93 ms |

`turnsFor` 的两处实现细节同样属于**分流正确性**，不只是性能：

1. **排序键用事件的数值 `ts`**，不用 `Date.parse(timestamp)` —— 后者占原开销 65%。
2. **先做 O(n) 有序检测再决定是否排序**。事件按 ts 递增追加，绝大多数情况已有序；
   但**乱序 flow 会被追加到尾部**（实测 `enter@1000 → say@2000 → system@1500`），
   因此**不允许无条件假设有序**。检测到逆序才真正排序，两种输入都正确。
3. `timestamp` 改为**惰性字段**：构造 2000 条轮次时不再逐条 `new Date().toISOString()`，
   只有真正渲染时才生成，且同一对象只生成一次。

> 🔴 **口径不变**：以上全部是求值时机与比较键的调整，`canPerceive` 判定、
> `readable/metaOnly/addressed` 的归属结果**逐字段等价**，已有 58 条用例零改动全绿。

## 5. 演进方向（v1 之后）

已落地的是**让三条关系各自有真源并接上主链路**。尚未完成：

## 6. 本版新增的三条判据（给后来者）

1. **业主的话要拆成两类读**——「可见性」和「分配器」。只做前者会用"干净"骗过自己。
2. **标签真实性优先于过滤准确性**——否则模型会照着错标签自证。
3. **时间锚点坏了要往「多看」方向退化**——全盲是静默失忆，最难查。
