# P0-4 全零向量根因调查报告

> 日期：2026-10-07 ｜ 依据：《P0 记忆体系止血任务书 V3》§4
> 方法：S1 只读诊断（生产库副本 + 代码静态追踪），**全程未改动任何生产数据**
> 结论一句话：**全零向量不是脏数据，是四处按设计写入的产物；真正坏掉的是「不参与情感余弦」这条契约——它在两条断裂链上从未生效。**

## 一、事实基线（实测，纠正 V3）

| 项 | V3 记载 | 本次实测 |
|---|---|---|
| 全零向量总数 | 1,538（16.0%） | **1,540（16.05%）** |
| ANCHOR 锚点行 | 1,318 | **1,320** |
| 「普通行 220」 | 未细分 | **全部是 `note_` 记事行**（220 条） |
| 判据 | `LENGTH(perception_40d) = 98` | **`l2_norm = 0`**（见下） |

**判据以 `l2_norm = 0` 为准**：实测 1,540 条全部命中、其中 `perception_40d` 为 NULL 的 0 条、空串 0 条，**零误伤**；且该列已存在、已有索引 `idx_memories_l2_norm`，无需任何 schema 变更。`LENGTH(...) = 98` 是等价但更脆弱的写法（拿长度当哨兵）。

**钙化分布**：`<1` → 1502 ／ `1~2` → 33 ／ `2~5` → 3 ／ `5~10` → 2。
⇒ **与 P0-1 的「14 条钙化=10」两组不相交**，V3「全零向量 ≠ 会晤入口指令」的判断成立，可以沿用。

## 二、来源：四个写入点，都是「设计如此」

| 模块 | 位置 | 规模 |
|---|---|---|
| 锚点重建 | `SQLiteAdapter._rebuildMemoryAnchors()` INSERT | 1,320 条 |
| 记事 | `YuyaoMemoryService` 三处 `writeMemory` | 220 条 |
| 金库 | `VaultManager:378` | 本批存量未覆盖，**会继续产生** |
| 睡眠巩固 | `SleepTimeConsolidator:689` | 同上 |

锚点那条尤其顽固：`perception_40d` 被列入 `ANCHOR_REBUILD_DERIVED_COLUMNS`（**不接受快照回填**），而该函数每次服务启动先 `DELETE` 全部 `%_ANCHOR` 再重建 ⇒ **每重启一次，全部锚点向量必被重写成全零**。

### 是否设计如此？**是。** 三处注释都明说这些行不该参与情感余弦：

> `SQLiteAdapter._rebuildMemoryAnchors`：对话组摘要**不参与**情感余弦
> `SQLiteAdapter._scoreMemory40D`：缺失行 → **emotional=0**，仅按钙化分+recency 降级排序
> `SQLiteAdapter.rowToRecord`：全零对象经 cosineSimilarity40D **恒得 0**（norm=0 → 返回0）

## 三、🔴 三条注释的前提，全部为假

### 断裂链 ①：归一化把 0 变成了 0.5

```ts
// PerceptionVector40DCodec.ts
const BIPOLAR_40D = new Set([36, 37]);          // D36 dominance, D37 moral_judgment
function normalize40D(v: number, dim: number): number {
  return BIPOLAR_40D.has(dim) ? (v + 1) / 2 : Math.max(0, Math.min(1, v));
  //                              ↑ 双极性维度上 0 → 0.5，不是 0
}
```

全零向量归一化后 = **D36=0.5、D37=0.5，其余全 0**，**范数 = 0.707107 ≠ 0**
⇒ `cosineSimilarity40D` 里那道 `if (normA === 0 || normB === 0) return 0` **永不触发**。

**实测余弦值**（查询向量 = 用户当前感知）：

| 查询形态 | cos |
|---|---|
| 高支配(D36) + 高道德(D37) | **1.000000** |
| 高愉悦 + 高唤醒 | **1.000000** |
| 随机三维持中 | 0.876 |
| 全中性 0.5 | 0.522 |

### 断裂链 ②：两个 S4 P1-1 改动互相抵消

```ts
// rowToRecord  —— 兜底让 r40 永不为 null
perceptionV40: decodePerceptionV40(obj.perception_40d) ?? createEmptyPerceptionV40(),

// _scoreMemory40D / applyReinforcement  —— 守卫却在等 null
const emotional = r40 ? cosineSimilarity40D(q40, r40) : 0;
//               ↑ 恒为真 ⇒ 契约「缺失行 → emotional=0」从未发生
```

**最讽刺的一点**：`rowToRecord` 那行上方的注释写着「不制造 14×0.5 假签名」，而它 `??` 出来的那个对象**正是**假签名本身。

## 四、影响（可量化）

```ts
composite = str × (0.55·emotional + 0.30·(calcium/10) + 0.15·recency)   // 阈值 > 0.05
```

锚点行 `is_landmark = 1`，正是 `findByEmotionalSimilarity40D` **第一个分支**（`WHERE is_landmark = 1 ORDER BY calcium_score DESC LIMIT 20`）优先捞出的那批。

| 情形 | 按设计（emotional=0） | 实际（emotional 最高 1.0） |
|---|---|---|
| 老旧锚点 composite | ≈ 0.007 → **低于阈值被滤掉** | ≈ **0.26 → 入选且被大幅加权** |

同一缺陷也存在于 `applyReinforcement(...)`：全零行可越过 `similarity < 0.3` 门槛，拿到**强化加成**（并写回 `effective_strength`）。

## 五、已实施的修法（读取侧）

新增私有判据，**恢复代码自己声明了三遍的契约**：

```ts
private _hasPerception(r40: PerceptionV40 | null | undefined): r40 is PerceptionV40 {
  return !!r40 && computeL2Norm40D(r40) > 0;
}
```

`_scoreMemory40D` 与 `applyReinforcement` 两处同源调用改用它。

**为什么对「原始」40D 求范数就够**：`computeL2Norm40D` 作用在未归一化向量上，因此「全零（无向量）」与「真实的中性向量」可分辨——归一化后的向量做不到这一点。

**为什么不是硬排除**：契约本身就是「emotional=0 但保留在钙化/近因上排序」。实测恢复契约后，老旧锚点 composite ≈ 0.007 **自然落到 0.05 阈值之下**，正好达成 V3 §4.3 的验收判据；而**近期**锚点（recency 有值）composite ≈ 0.074 仍可召回——比硬排除更贴合原设计意图。

## 六、🔴 登记为后续专项的两条（本批**未**修）

| 项 | 位置 | 为何不在本批 |
|---|---|---|
| `?? createEmptyPerceptionV40()` 兜底 | `rowToRecord` | 它是**另一种**「让守卫失效」的机理，但 `write()` 的读-改-写路径依赖「恒有 perceptionV40」，改 null 会波及写入链路 |
| `normalize40D` 双极性 `0 → 0.5` | `PerceptionVector40DCodec` | 改它会改变**全部现存向量**的语义（所有向量都被重新解读），风险面远超本批 |

两者才是「为什么会有全零向量、为什么契约守不住」的真问题；本批只在读取侧堵住症状，**不改任何存量数据、不改向量语义**。

## 七、教训（同族第 N 例）

这是本仓「**注释写的才是对的、实现与之相悖**」的又一例，同族已有 V35 三批、P0-2a 等。本批的特殊之处在于：**注释不仅前提为假，而且它专门声明自己在防的那个东西（14×0.5 假签名），恰恰是它自己制造出来的。**

可推广的判据：**当一个"防线"依赖某个数学不变量（这里是 `norm === 0`）时，必须为该不变量本身写一条测试**。三条注释都描述了这个不变量，却没有一条测试验证它 —— 于是它静静地假了一年。本批新增的 3 条**红用例**正是补这个，若日后 `normalize40D` 或 `rowToRecord` 被修正，它们会失败并提醒：读取侧判据可以退役了。
