## 一、为什么有这么多编码（背景）

编码体系随系统演进叠加产生，分四类动机：

| 动机 | 编码 | 说明 |
|---|---|---|
| **记忆存储** | 40D / global_uid / DNA根码 | 记忆如何编、如何唯一标识、如何聚合 |
| **身份管理** | 实体 UUID / global_uid | 角色与记忆的归属关系 |
| **导航/路径** | locus_path / leaf_zone / branch_id | M1 四层（L0-L3）编码即路径 |
| **标记/标签** | 情绪色号 / narrative_tag / time_period | 附加认知标签（本体-标签分离原则） |
| **历史演进** | 24D / 32D / perception_v2 / VAD | 各阶段维度方案，部分已根除/废弃 |

## 三、编码生命周期规约

每个编码必须遵循「**本体-标签分离**」与「**生成者-消费方契约**」：

```
生成者（写入） → 存储字段 → 消费方（读取干活）
   必须明确         唯一        必须有实际消费方，否则废弃
```

- **本体编码**（决定记忆身份/路径）：40D、UUID、global_uid、DNA 根码、locus_path、branch_id —— 不可删减
- **标签编码**（附加认知）：情绪色号、narrative_tag、time_period —— 可增删不影响身份
- **死字段判定**：连续无消费方 → 标注废弃 → 下个迁移窗口删列
